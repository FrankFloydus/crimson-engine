# Material Resize

Add **Resize** (search also accepts **Resample**) after an image branch, then connect its Result to another node or a material input. Width and Height independently accept 1–4096 pixels, default 1024. Filter selects Nearest, Linear or Area. Area averages fractional source-pixel coverage when reducing an axis and uses linear interpolation when enlarging it. Resize changes the actual cached image resolution; it does not change UV tiling or recover detail absent from the source.

Resize and the other adaptable image filters show a mixed grayscale/color input connector while disconnected. Once connected, the input uses the incoming Scalar, RGB or RGBA color; the Result and outgoing wires show the resolved output type. The mixed input describes what can be connected; it does not perform a conversion. Grayscale, channel extraction and other fixed-result operations retain their actual output types.

For example, `Color texture → Desaturation → Levels → Resize → Height` is valid and connects directly, without an automatically inserted conversion node. Color textures decode sRGB once before linear graph calculations. A packed/raw height texture should instead use Linear Data. The Resize result is already linear and needs no second color-space switch. A fixed scalar receiving input uses the existing first-channel rule; fully desaturated RGB has identical channels. Explicit channel or Grayscale nodes remain available when the artist wants a particular extraction or conversion.

Resize evaluates the complete supported upstream branch on its working pixel lattice before filtering to the requested dimensions. That lattice uses the largest source width and height independently; nested Resize nodes provide their declared dimensions. Procedural Texture nodes provide their authored dimensions; analytic Noise and Grunge retain their 1024-pixel reference lattice. Thus Levels before Resize adjusts source texels before they are resampled. The CPU bake samples base bitmap texels with point/linear filtering and static UV0 transforms/wraps; it does not reproduce a view-dependent GPU mip selection. The final resize filter uses edge-clamped pixel coverage. A subsequent Resize can resample a previous Resize without quantizing it to eight bits.

The initial scope is static 2D UV0: ordinary color/data bitmaps, constants, supported arithmetic/image/channel nodes, Noise, Grunge and static UV0 mappings. Time, moving Panner, Particle Color, UV1, local/world triplanar mapping and decoded Normal inputs are rejected. A zero-speed Panner with static inputs is allowed. Encoded RGB from Height to Normal remains ordinary RGB; no automatic normal renormalization is performed. Invalid/missing assigned sources report a diagnostic and retain the last coherent material. An unassigned Texture 2D retains the ordinary white graph default.

The canonical renderer owns the CPU image evaluator and shader boundary. Engine ResourceManager workers evaluate cancellable immutable snapshots; TextureStreamer owns coarse-first GPU upload, row budgets, residency, leases and retirement. No worker calls bgfx or changes a document. A content key includes upstream settings, source identities/fingerprints, dimensions, filter and generator revision. Layout changes and warm frames do not rebake. Source changes produce a new immutable generation; pending replacements retain the last usable packet. Generated images create no authored files or Asset Browser entries.

CPU evaluation uses 32-bit float channels. GPU images and complete linear mip chains use RGBA16F, preserving independent straight alpha, transparent RGB, signed channels and finite HDR values within the half-float range. Ordinary source bitmaps remain RGBA8. The CPU evaluator limits simultaneous temporary float-image storage to 512 MiB and reports over-budget requests. A 2048² RGBA16F image with full mips uses about 42.67 MiB of GPU texels, versus about 10.67 MiB for RGBA8; 4096² uses about 170.67 MiB. Residency can be lower when the normal streaming budget selects a coarser image.

At render time each active Resize is one image sample/binding from the existing twelve-slot budget; its upstream subtree is evaluated during regeneration, rather than repeated in the fragment/domain shader. Other direct consumers of the same original branch still evaluate that branch normally. Width, Height, Filter and upstream numeric edits update generated content without recompiling compatible shader topology. Height Texture LOD still selects a mip of the new dimensions: a high LOD can deliberately remove detail even from a larger Resize result.

Graph schema 10 introduced Resize; schema 11 adds cached image operations without renumbering older nodes/pins. Readers accept schemas 1–11; native material v6 and uniform ABI 32 remain unchanged, while generated shader source identity is v33. Consumers handling `MaterialGraphTextureBinding` must recognize `resize`, resolve its immutable graph and source images, recognize all `materialNodeCachedImage` kinds, query `materialCachedImageExtent` from source metadata, call `bakeMaterialCachedImage`, and publish the result as a linear float texture. The `.resize` binding member and the older Resize API names remain compatible aliases; the recipe may now identify Blur, Grow/Shrink, Warp, Image Transform, Procedural Texture or an Occlusion node. Nested image nodes are private bake dependencies, not extra runtime samplers. Use the immutable content graph in the binding so outer Image Transform mapping edits do not regenerate the image. It is not an empty ordinary bitmap binding. Engine AssetLibrary implements this adapter; other hosts need equivalent resource ownership before exposing the node.

The image-size boundary follows Adobe's documented [Output Size](https://experienceleague.adobe.com/en/docs/substance-3d-designer/using/substance-graphs/output-size) and [intermediate-result resizing](https://experienceleague.adobe.com/en/docs/substance-3d-designer/using/technical-issues/incorrect-image-output) behavior. Crimson implements its own evaluator and filters; it does not claim Adobe pixel parity or use Adobe implementation code. Focused checks cover independent filter references, color/data/alpha precision, cancellation, typing/history, shader lowering, warm cache reuse and real DX12 RGBA16F Height sampling. [Integration measurements](MATERIAL_RESIZE_PERFORMANCE.md) distinguish generation latency from steady-frame GPU work.
