# Renderer and Character lighting implementation guide

Updated 2026-10-25. This is a source-oriented companion for agents changing Crimson's current renderer or Character lighting. [ENGINE_ARCHITECTURE.md](ENGINE_ARCHITECTURE.md) remains authoritative for ownership, implementation status and the next agreed milestone. The implementation described here exists in the checkout; deferred proposals at the end require their own requested slice.

Crimson's current game direction is first-person action with an editable eye camera, WASD movement, mouse look, jumping, strafe tilt and smooth stair traversal. DUSK and Quake inform locomotion and camera feel only. Scene and Game use the same perspective-aware directional shadow policy; the former elevated-camera projection and player-occluder fading are removed. Evaluate future appearance changes from the authored first-person view while preserving current rendering and asset contracts.

Read the relevant sections before editing, then verify the source rather than treating a historical screenshot or test count as the current contract. [D2R lighting findings](D2R_CHARACTER_LIGHTING_FINDINGS.md) records the reference evidence and discarded iterations. It does not establish Diablo II: Resurrected's unpublished equations or require copying its complete pipeline.

Current identities are native material v6, graph schema20, scene schema25 and material ABI39. Fragment, node-preview and native-domain source revisions are independent entries in canonical `MaterialGraphSourceRevisions.h`, currently all42. A change to a lighting helper invalidates its actual compiler dependencies; a Decal-only change must leave unrelated surface artifacts reusable. Follow the [material startup and browser requirements](MATERIAL_SHADER_STARTUP.md#startup-and-browser-regression-requirements) when changing shaders or material preparation. Warm shader hits alone do not verify generated images, streamed textures or rendered thumbnails.

The Windows renderer defaults to Direct3D 12. **Edit → Preferences → Rendering → Renderer (restart required)** selects Direct3D 12 or Direct3D 11 for the next launch; the tooltip reports the active backend. `--renderer dx11|dx12` overrides that preference for one process without persisting it. The engine-owned `GraphicsBackend` value is selected before bgfx initialization and does not belong to scene or Environment data. The renderer validates the requested backend and checks native blendable RGBA32F support using the matching D3D11/D3D12 device. Both backends retain the same linear HDR lighting, final sRGB encoding, effects and SM5/DXBC shader/cache/preflight contracts. Switching APIs alone adds no rendering effects and does not require material recompilation. Vulkan is not enabled for the Engine rich Forward+/PBR path. The shared renderer separately implements borrowed Vulkan for Quader's modeling/editor path. Historical D3D11 measurements below retain their original scope; they are not DX12 measurements or cross-backend speed claims.

## Actor lighting and removed features

Surface-wrapped and box-projected decals modify eligible world mesh color, shading-normal surface gradient, roughness and metallic before normal PBR lighting. They use the same lights, environment, fog, GI donor and SSR surface paths as the receiver. They add no separate lit transparent overlay and consume no additional receiver graph texture slots. Scene, Game, the Decal and Material Editor previews, and asset thumbnails have independent targets. Current receiver eligibility, provenance, memory bounds and authored workflow are specified in [the architecture](ENGINE_ARCHITECTURE.md#surface-wrapped-pbr-decals) and [README](../README.md#decals). The conforming path excludes skin/morph and animated receivers; the Box path uses their current visible prepass. Transient particle billboards, Height/displaced, Unlit, translucent/additive and partially faded receivers remain unsupported. Rigid actor attachments are eligible; Receive Decals defaults on per visual entity. Decal materials use the dedicated graph shader model with independent color, normal, roughness and metallic coverage.

Actors, players and enemies receive ordinary scene point/directional lights and environment illumination. `SceneActor` defines the nearest visual ownership boundary and World/Character classification; it supplies no private lighting. Character Light Rigs, their Key/Fill and Local World sources, dedicated rig silhouettes, Darkness Reveal and Environment Ambient Darkness have been removed. Existing scenes load while discarding those obsolete settings in memory; saving writes only the current settings. Player-occluder fading and its nearest-wall compositor are also removed. Ordinary scene lights, character shadow casting from those lights, authored transparency, generic instance opacity, SSGI and SSAO remain independent. Legacy model fade participation and application fade keys are ignored on read and omitted on Save.

## Ragdoll skin presentation

Passive Jolt ragdolls are implemented for reusable imported-skeleton setups. [The architecture](ENGINE_ARCHITECTURE.md#reusable-jolt-ragdolls) defines asset/source validation, authoring, physics and Play ownership; [the authoring workflow](../README.md#author-and-test-ragdolls) covers body/joint editing and mouse-driven simulation testing. Each active model supplies an interpolated immutable `ModelPose` through `prepareRagdollPresentation`. Scene and Game share that pose, skin palettes, draw transforms and conservative posed bounds through `EditorResources`; ordinary color, depth, shadow and picking use the existing GPU deformation path. Nearest Actor classification, direct receiver/shadow masks and scene lights remain unchanged. Physics drives bones without writing scene transforms or owning material resources.

The Ragdoll Editor owns a separate physics floor/world and dedicated renderer targets/environment. Its compact RagdollPreview profile occupies unused physical views 416-429, retaining ordinary skinned materials, tone mapping, application Off/SMAA and grid. It omits Glow, SSR and scene-color refraction capture. It shares only the established model preparation/deformation path and view-0 preparation; Animation, Material, Particle, Decal, Scene and Game output owners remain independent. Existing numeric IDs, 512-view capacity and native terminal-copy/readback ordering are preserved. Mouse-drag constraints, preview poses and camera motion remain transient.

Skinned ragdoll surfaces retain the existing deformation limitations: unsupported GI motion rejects history, and conformal decals do not receive on skins. A physical ragdoll uses authored simplified shapes and joints; it does not enable animated render-mesh collision, active animation-following motors, partial animation/physics blending or general dynamic Collider authoring.

### Light presets, temperature and flickering

`scene/LightAuthoring` owns the CPU light color modes, conversion, fixture/flicker catalogs and pure presentation evaluator. Both scene light aggregates retain independent `color` (authored sRGB) and `temperatureKelvin` (1000–15000, default 6500), with `colorMode` defaulting to Color. Temperature resolves through the CIE 1960/XYZ blackbody fit described by Filament and used by Godot, maximum-channel normalization and the ordinary sRGB transfer. Extraction returns the same authored-sRGB interface as existing lights; the renderer decodes once. Switching modes never infers a temperature from RGB or overwrites the inactive value. The disabled Inspector picker displays resolved temperature color.

The searchable fixture catalog has 55 point recipes and 10 directional recipes. Applying a fixture changes mode, its color/temperature, intensity and point radius atomically; it preserves enabled, GI Energy, attenuation, source size, shadows and flicker. Recipes are artistic values in the existing engine scale, not calibrated lumen/lux or new emitter shapes. The separate 24-entry flicker catalog selects one behavior with editable settings while retaining the enabled switch, seed and time offset. Continuous, electrical-failure, rhythmic and irregular-event families expose their relevant numeric controls. There is no stacked layer mixer or curve editor.

Optional `flicker` settings default disabled. Intensity and point-radius channels multiply authored base values; the color channel uses relative Kelvin offsets or sRGB tint endpoints interpolated/multiplied in linear light. Each maps one shared deterministic scalar through its own inversion and response; Color Amount blends toward the base. Playback has speed, duration, Loop/Once, delay and offset. Before the delay the base light is unchanged; Once clamps to the final sample. A fixed integer hash supplies random access by seed/time rather than consuming random state per frame. Matching settings/seed/offset synchronize independent entities regardless of extraction order, selection or visibility.

`runtime/SceneLights` owns the scene-wide Edit clock and transient Preview, Pause/Resume and Restart state. `EditorSession` samples the clock once for extraction; Scene and Game share the result. Play owns an independent clock advancing only accepted simulation time and render-frame fractions, excluding discarded catch-up time and suspension. Sampled values never enter ECS, serialized data, history or dirty state. Saved-scene thumbnails use resolved steady base lighting. The linked procedural sky sun consumes the same evaluated directional color/intensity as surfaces. Existing SSGI source signatures already observe the evaluated color/intensity/radius; temporal indirect light retains its existing reconstruction latency. Radius animation updates culling/shadow range and may invalidate point-shadow maps, while color/intensity-only changes retain their depth contents.

These additions were introduced as optional scene-v24 fields; the current scene-v25 reader preserves them with strict type/finite/range validation and no writes on load. Explicit Save persists inactive tuning as well as active settings. Same-kind Quader source refresh retains Crimson flicker and inactive temperature, while returning to Color mode for synchronized source RGB. Focused `light_authoring_core`, `light_scene_core`, `scene_lights_core`, extraction and Play-runtime checks cover this contract. Light presentation does not change material ABI39 or the per-input shader source identities.

### Shared point response and source-size shadows

Ordinary points expose the same response fields. Their defaults differ: Near Falloff 0, Specular Scale 1, Range Falloff 4, Edge Softness 1, Source Radius 0, Attenuation 2, Radius 20 m, Intensity 35 and Cast Shadows off. Ordinary authored point intensity is bounded to 0…10,000. Preserve these defaults when adding imports or adapters.

For distance `d`, near radius `n`, influence radius `R`, exponent `p`, softness `s` and attenuation `a`, the response is:

```text
t = clamp((d/R - (1-s))/s, 0, 1)
window = 1 - t^p
response = window² * max(d²+n², .01)^(-a/2)
```

The ordinary `p=4, s=1, a=2` branch keeps its original arithmetic exactly. `a=2` is inverse square; 1 is inverse distance; 0 retains only the range window. Negative exponents intentionally grow with distance until the range fade. General exponent evaluation is bounded for finite HDR output. This is Godot-style power decay with Crimson's existing near softening/numerical floor; it is not Godot's exact close-distance clamp.

See [point_light.sh](../third_party/crimson-renderer/src/shaders/point_light.sh). Source Radius does not change that equation or Lambert diffuse orientation. It broadens GGX/Smith specular response using angular emitter size. **Specular Scale 0 does not disable soft shadows.**

[point_shadow.sh](../third_party/crimson-renderer/src/shaders/point_shadow.sh) evaluates the source-zero 3×3 PCF footprint as 16 unique raw-D32 comparisons. Each texel uses its own receiver-plane reference and the equivalent separable bilinear weights. Numerical comparison tolerance is separate from the authored offsets: an IEEE single-precision `gamma(8)` allowance covers projection/reference arithmetic, and absolute-world coordinate roundoff propagates through the receiver-plane perspective-depth derivative. A fixed two-D32-unit tolerance was insufficient on translated walls near the point source. Point-shadow casters apply light view and projection separately to reduce that cancellation; the readable scene prepass retains the color pass's combined projection for depth parity. PCF and PCSS normal offsets scale with `sin(theta)` rather than `1-cos(theta)`, preserving protection near normal incidence.

At mixed contact edges, a coherent 2×2 patch of genuine blocker depths can reconstruct a missed central blocker, extrapolating at most one shadow texel. Its depth plane must differ from the receiver, and it is rejected if it predicts blocking any observed sample that matches the original, unbiased receiver plane. Contact sharpening is measured against the projected plane intersection and returns to the full filter between two and four shadow pixels. This is bounded coverage completion, not mesh adjacency recovery; finite geometry with no contradictory receiver samples remains ambiguous. The fallback uses the closest confirmed blocker/receiver physical separation, restoring full filtering between two and four receiver texels. Brightening either path additionally requires the central depth to match the receiver plane; an empty or mismatched central depth retains the filtered result. Fully lit or blocked footprints skip reconstruction, allowing for the numerical accumulation bound of the 16 weights.

Keep one terminal PCF call in `pointShadowVisibility`: `tryPointShadowVisibilitySoft` reports whether PCSS supplied a result, and all fallback conditions reach that shared call. SM5 inlines the substantial contact filter at each call site; duplicating it in individual PCSS returns increases shader size, temporary registers and compilation time.

The receiver plane itself is not a blocker. Authored depth/normal offsets still apply and can independently separate shadows from zero-thickness walls; the filter does not silently cap those values. For contact-sensitive joined walls, use **Depth Bias 0 m / Normal Bias 1 texel**; zero authored Depth Bias still includes the numerical comparison tolerance. There is no global conversion of authored settings or defaults. Positive source radius uses a bounded deterministic PCSS search/filter: 12 blocker samples, radial blocker-distance reconstruction from perspective face depth, and 16 visibility taps. Penumbra radius is proportional to `sourceRadius * (receiverDistance-blockerDistance)/blockerDistance`. Contact stays sharper than distant shadow edges.

Wide samples remap to their proper cube face rather than crossing an atlas tile into another light. Receiver-plane correction and a receiver-normal-based stable kernel preserve sloped surfaces and cube seams. It uses the existing comparison atlas/raw depth access, with no extra sampler, shadow map or depth-render pass. Source-size/attenuation edits can change shading immediately while all six depth faces remain cached. Positive size increases query work; zero depth draws is not zero shadow cost. Ordinary directional filtering retains its sharpness.

## Directional shadows for first-person cameras

Scene, Game and saved thumbnails share four stable sphere-fit cascades. Each view uses its own camera projection, position, FOV, near plane and aspect ratio; there is no separate fixed-camera Game world map or player-focus map. Practical PSSM splits blend logarithmic and uniform distances with lambda **0.8**, favoring near-camera detail. Extents are quantized, XY centers snap to texels, the final 10% of each split blends into its neighbor and the final 20% of the effective shadow range fades out. Effective range is min(camera far, authored Shadow Distance). Whole-world caster collection precedes camera receiver culling, so relevant offscreen casters remain visible in the maps.

Directional Inspector controls are **Cast Shadows**, **Shadow Distance (m)** (default 100), **Depth Bias (m)** (0.005), **Normal Bias (texels)** (1), and **Shadow Angular Diameter (°)** (default **0.53°**, range **0–2°**). The angle is the full emitter diameter and affects only directional shadow softness. It does not broaden directional specular response or change the light's energy. Missing angular data defaults to 0.53° without a scene-version bump; current v23 Save writes `shadowAngularDiameter`. Existing cast-shadow flags, distances and biases remain authored values.

At zero angle, weighted 5×5 PCF evaluates its equivalent 6×6 raw-texel footprint with 36 individual depth comparisons and continuous separable bilinear weights. Each comparison evaluates the receiver plane at that same texel center, avoiding the additional seam leakage caused by one shallow reference shared by four texels. Positive angle adds twelve raw blocker-depth probes and thirty-two bilinearly reconstructed samples for a wide penumbra; each of those samples likewise compares four depths independently. The original kernel, disk locations and authored offsets remain unchanged. Thin, exactly touching walls can still leak within the finite filter footprint, especially at grazing angles; this correction is not an exact geometric visibility system. Subtexel penumbrae and blocker-search misses fall back to weighted PCF to retain thin caster shadows; the transition to the wider filter blends over **2–3 local shadow texels**. These fixed light-space disks avoid per-frame/random rotation because the engine has no temporal antialiasing. Positive-angle paths therefore still pay blocker search in lit/hard regions, and the transition evaluates both filters. These are bounded sample counts, not evidence of a measured frame-time improvement.

The weighted PCF footprint remains the minimum shadow-map antialiasing filter. A sharp physical contact shadow also needs subpixel coverage. Directional filtering never replaces that coverage with a raw central depth comparison or an extrapolated infinite blocker plane; doing so exposed jagged shadow-map texel steps on stair silhouettes. Wider PCSS penumbrae blend from the filtered baseline.

Scene and Game supplement the cascades with finite world-geometry visibility. Immutable original-LOD triangle hierarchies are prepared on resource workers and published, with exact affine occurrences, in the existing Forward+ data atlas. Queries cover the complete finite eligible world bounds, including offscreen walls and upstream casters. Conservative hierarchy/beam tests reject empty regions before up to 32 deterministic subpixel samples. For a hard source, a strict finite-triangle coverage proof can resolve a fully covered footprint early after camera validation. Partial edges retain sampled coverage and combine with the cascades using their minimum. This retains the authored receiver far fade.

At a finite receiver corner, extrapolated footprint points can lie behind a different visible face. Camera queries condition hits and misses equally, extending to the actual camera near plane. Shadow-only casters cannot supply camera evidence; a zero-valid footprint retains the cascades. Origin offsets and certified positive intersection intervals protect the receiving plane without a second distance cutoff that could skip a neighboring wall. An independent difference-first plane interval can certify a real near hit when the ordinary sheared-depth cancellation bound is inconclusive.

Only proven fully opaque, undeformed original geometry supplies supplemental casters and camera witnesses. Faded, masked, translucent, skinned, morphed, posed, displaced or dynamically covered geometry remains represented by ordinary shadow maps. Eligible full-opacity primary opaque/masked PBR mesh receivers consume one camera-local geometry-visibility field; Alpha/faded meshes and sprites retain ordinary CSM. Unsupported or over-capacity inputs fall back to the cascades. Previews and thumbnails omit this supplement.

The existing readable prepass additionally captures exact FP32 receiver position and triangle plane when this field is needed. One full-resolution compute evaluation writes detached scratch, then an ordered publication copies four directional visibilities into a disjoint Forward+ atlas range. The source rays share one hierarchy traversal and accumulate their original sample bits per candidate triangle; camera validity still conditions each sample. Materials use exact integer-pixel point lookups rather than compiling triangle traversal into each graph. An exact bias-normal compatibility flag permits a safe CSM-zero early-out; unmatched normals still evaluate geometry. The trace never reads and writes the same atlas allocation simultaneously. This adds no material sampler, material ABI field, authored control or temporal history. The [leak investigation](LIGHT_LEAK_INVESTIGATION.md) records the saved-room evidence, research and scoped GPU measurements.

Rich Forward camera targets use reversed floating depth: near maps to one, far to zero, clears are zero and camera depth tests use Greater/Greater Equal. Main color retains stencil in `D32FS8`; readable geometry and picking use `D32F`. The maintained bgfx overlay provides the explicit format through fork API130/port15. SSR stencil admission and correction ownership remain intact. SSGI, SSAO, transmission, grid and collision overlays use matching inverse projections/device-depth conventions; SSR's separate positive linear-depth hierarchy keeps its ordinary comparisons. The authored near/far planes remain unchanged. Ordinary CPU authoring rays, the borrowed core/modeling recipe and point/directional shadow maps retain their own existing projection conventions.

This camera-depth change addresses a distinct raster-visibility error. At the saved approximately .0006994 m near plane and 36 m distance, D24 spacing is roughly .11 m, allowing a floor behind a wall to win the raster depth test. Reversed FP32 greatly reduces that storage spacing; it does not remove all vertex, interpolation or finite-sampling error. [Reed's depth precision analysis](https://developer.nvidia.com/blog/visualizing-depth-precision/) and [Godot's reverse-Z migration](https://godotengine.org/article/introducing-reverse-z/) explain the numerical basis and the raw-depth consumers that require conversion.

Receiver-plane gradients use world-position derivatives and portable matrix-row extraction. Comparison references account for the bilinear footprint; projection-dependent float tolerance remains separate from authored metre/texel offsets. Normal bias follows the geometric normal with a slope factor, and overlapping cascades share one continuous world-space normal offset. Increasing bias trades acne for detached shadows; it does not increase map resolution.

All cascades reserve the same world-space halo `H = tan(diameter / 2) * authoredShadowDistance`, with the angle converted to radians. PCSS uses `min(H, tan(diameter / 2) * meanBlockerReceiverGap)` as its world-space filter radius. At the defaults, H is about **0.4625 m**. Penumbra growth saturates after one Shadow Distance of light-space separation; farther upstream casters still cast. The cap bounds projection padding/filter support and avoids a different world-space softness limit in each cascade. Long-distance thin casters, sparse blocker sampling, finite map resolution and this deliberate saturation remain quality limits. Hardware ray tracing and temporal shadow reconstruction remain unimplemented.

The research basis is [Zhang et al.'s practical split scheme](https://developer.nvidia.com/gpugems/gpugems3/part-ii-light-and-shadows/chapter-10-parallel-split-shadow-maps-programmable-gpus), [Microsoft's cascade/stabilization guidance](https://learn.microsoft.com/en-us/windows/win32/dxtecharts/cascaded-shadow-maps), [Castaño's optimized PCF derivation](https://www.ludicon.com/castano/blog/articles/shadow-mapping-summary-part-1/) and [Fernando's PCSS paper](https://developer.download.nvidia.com/shaderlibrary/docs/shadow_PCSS.pdf). Lambda 0.8, the 12/32 sample budgets and the shared halo are Crimson choices rather than universal prescriptions from those sources. The older [ARPG shadow checkpoint](SHADOW_ARCHITECTURE_CHECKPOINT.md) retains historical fixtures and measurements only.

Point-shadow admission remains separate from direct illumination: sixteen maps, four complete dirty-map updates per frozen world frame, stable light IDs and fairness. Its frozen priority origin is the **visible Game camera eye**, otherwise the **Scene camera eye**. A missing Player mesh must not cause the free Scene camera target to choose Game's shadowed lights. Resource demand, source-to-shadow mapping and update scheduling reuse the same origin.

## Environment Ambient Light, sky and fog

One persistent active-Environment entity selects scene settings. Its transform is not a local lighting volume. The selected HDRI/studio or procedural sky supplies irradiance and roughness-prefiltered specular lighting. Procedural sun linking is explicit; the directional entity remains the direct-light source.

**Specular AA** defaults off. It reduces shimmer rather than uniformly reducing brightness; filtered highlights may broaden. It filters effective specular roughness from screen-space variation of the final shading normal, reducing undersampled highlight sparkle. Scene/Game, fixed and generated materials, SSR, glass, previews and saved-scene thumbnails share the same setting contract; material and particle preview toggles remain independent of authored scene data. `u_pbrSettings` carries Enabled, variance .15 and threshold .2 with a reserved zero lane. The optional `specularAA` JSON boolean supports normal Environment undo/redo and Save/reopen, keeps missing values off and introduces no scene-schema change. It changes shader evaluation without allocating a pass, texture or temporal history.

The shared GGX response uses the existing Schlick DFG lookup `(A,B)`: white-Fresnel directional albedo is `E = A+B`, and practical multiple-scattering compensation is `1 + F0*(1/E - 1)`. Direct and environment specular use that compensation, while diffuse retains the complementary hemispherical energy budget. Glass transmission uses the same compensated integrated reflection before Beer absorption, preserving the exact index-matched interface. These are shared lighting equations rather than extra authored controls. Environment specular and SSR use identical roughness-dependent specular AO and soft geometric-horizon visibility, so signed SSR replacement removes precisely the matching environment contribution. The horizon term is a visibility approximation, not a traced occluder. Specular AA, when enabled, raises squared GGX alpha by bounded normal variance before these evaluations; it does not change the authored Roughness value.

**Ambient Light** defaults to Source Sky, Color black, Sky Contribution 1 and Energy 1, preserving previous sky lighting. The shared Inspector controls are Source Disabled/Color/Sky, Color, Sky Contribution (0…1, Sky only), and Energy (UI 0…16). Stored Energy accepts finite nonnegative values; rendering clamps it to the finite HDR envelope 0…60,000 without rewriting data.

For decoded linear color `C`, Energy `E`, contribution `S`, diffuse sky irradiance `I` and existing environment intensity `J`:

```text
Disabled: diffuseAmbient = 0
Color:    diffuseAmbient = C * E
Sky:      diffuseAmbient = C * E * (1-S) + I * J * S
```

Energy scales the **custom color**, not the entire blend. At S=1 it has no effect; Environment Intensity controls the sky. Environment lighting Enabled/Intensity controls sky/reflections, while custom-color ambient remains independent. Ambient Source Disabled removes diffuse ambient only; reflections keep their existing environment response. This separation follows the inspected Godot renderer semantics.


Fog supports Exponential and Depth response, height density and Light Energy. **Sky Affect** (default 1) scales background fog opacity; **Aerial Perspective** (default 0) blends fog color toward the sky along the viewing ray, and **Sun Scatter** (default 0) adds Godot's broad forward scattering toward enabled directional lights. All three range from 0 to 1. Sky Affect controls only the background; Aerial Perspective and Sun Scatter also affect fog on surfaces/particles, while additive materials retain attenuation only. The existing environment sampler supplies aerial perspective without consuming material texture slots, independently of environment illumination Enabled. Surface aerial perspective follows Godot’s blurred-radiance policy: maximum roughness mip at the camera near plane, approaching the first roughness mip at the far plane. It never samples sharp mip 0 when a filtered mip exists. This prevents the sharp sky sun from being painted into finite-surface fog. It remains artistic unshadowed haze; neither aerial perspective nor Sun Scatter evaluates light visibility along the camera ray. Shadowed indoor fog requires a separate volumetric-lighting system.

Background opacity evaluates distance/height fog at the camera's far-distance proxy, scaled by Sky Affect. Exponential Density approaches zero continuously; Density 0 and Height Density 0 restore the clear sky or exposure-independent matte, and Sky Affect 0 leaves it clear with finite-surface fog still active. The provided Godot checkout's background-opacity policy is independent of density; Crimson deliberately uses density-aware transmission to satisfy these controls. Hidden backgrounds retain premultiplied fog coverage over the unexposed display matte; visible skies mix in HDR. Color/scattering precede exposure and tone mapping. The material's **Receive Fog** toggle permits black cutaway materials to remain unaffected by fog; opaque excluded surfaces still cover the fog background. It does not change shadow casting, ambient masks or occluder visibility. Grid and editor overlays keep their later exposure-independent composition.

## Tone mapping controls and lighting inspection

The Environment Inspector groups Exposure, the tone selector and curve controls, and Debanding in **Post-processing → Tonemapping**. Material/Particle Editor Environment menus retain their independent tone controls. `EnvironmentSettings::toneMappingParameters` retains all operator values while the selected operator determines which fields are visible. Reinhard White Point defaults 0 (range 0…64), preserving the unlimited legacy curve; a positive value selects extended Reinhard with that exposed HDR input reaching display white. ACES White Point defaults 1 (1…64). AgX White Point defaults 16.29 (2…64) and Contrast defaults 1.25 (1…4). Linear exposes no curve parameters. Exposure remains an independent multiplier before tone mapping, and White Point is measured in that exposed HDR domain. Preview environments keep their own values.

The optional `toneMappingParameters` JSON object writes `reinhardWhite`, `acesWhite`, `agxWhite` and `agxContrast`. Shared scene/legacy-environment serialization validates finite numbers and each range, including inactive operators; missing fields preserve previous defaults without rewriting or dirtying the source. Positive Reinhard White Point values below 0.01 use 0.01 for numerical stability; zero remains the unlimited-curve sentinel. Existing ToneMapping enum values and scene versions remain unchanged. Whole-Environment transactions preserve undo/redo, cancellation, duplication and Edit/Play isolation. Saved-scene thumbnails follow the authored curve.

`ToneMapping.cpp` is the CPU reference for `tone_mapping.sh`. The CPU computes normalization and curve coefficients through `toneMappingUniforms`; Renderer binds `u_toneCurve` and `u_toneShoulder` for every presentation, including alternating Scene/Game views. These uniforms do not enter material shaders or the generated-material ABI. Curve edits require no material compilation or environment preprocessing. Default parameters preserve the existing Reinhard/ACES/AgX output and the single final sRGB encoding.

## Optional presentation effects

**Post-processing → Pixelization / Dither / Posterization / Vignette** expose independent default-off Enabled toggles. Pixelization authors integer Pixel Size 1–128 (default 4); size 1 is neutral. Dither authors Pattern (Bayer 2×2, 4×4, 8×8 or Interleaved Gradient Noise; default Bayer 4×4), integer Size 1–16 (default 1) and Strength 0–1 (default 1); zero strength is neutral. Posterization authors integer Levels 2–256 (default 8), quantizing each perceptual display channel and decoding back to linear presentation color. Vignette authors Intensity 0–1 (default .5), Radius 0–1 (default .75) and Softness .01–1 (default .5). Zero intensity is neutral. Disabled effects retain their values.

The shared renderer applies Pixelization, then Dither, then Posterization, then Vignette in one optional raster pass after tone mapping/Glow and SMAA, before grid and collision overlays. Dither adds a centered threshold from the selected stable pattern to perceptual RGB, scaled by Strength and the interval 1/(levels−1) when Posterization is enabled or 1/16 alone. Size scales the threshold cell in screen pixels, or in pixel-block indices under Pixelization, preserving uniform blocks without aliasing the pattern. The pattern is stable between frames. The renderer decodes the result to linear presentation color; final-encoding Debanding retains its separate behavior. The pass output is a per-view RGBA16F target retaining scene depth for overlays. Pixel blocks remain crisp with SMAA enabled. HDR lighting, GI donors and refraction sources stay upstream. The effects affect Scene/Game and saved-scene thumbnails, with independent targets; numeric material diagnostic views bypass them. The existing final encode pass retains the only display encoding, and these presentation effects do not change material ABI39 or generated material source identities.

## Glow

The Environment Inspector's **Post-processing → Glow** section controls one full-scene HDR glare effect. Material and Particle Editor **Environment** menus expose the same controls for their independent transient previews. Glow defaults off and works with Environment Lighting disabled. It captures the visible sun/sky, reflections, directly lit highlights and material/particle emission. Foreground geometry covers those sources normally. A directional light needs a visible procedural-sky sun or HDRI highlight to produce a sun-disk halo. Glow adds image-space scattering; use lights or GI to illuminate nearby surfaces.

Main controls are **Enabled**, **Intensity .3**, **Blend Mode Screen**, **Spread 1**, **Highlight Threshold 1** and **Tint white**. **Levels** contains seven contributions. **Advanced** contains **Saturation 1**, **HDR Scale 2**, **HDR Luminance Cap 12**, **Anamorphic Stretch 0** and **Quality High**. There is no separate Bloom section or Core/Halo Balance.

Intensity ranges 0...10 and Spread 0...8; either zero bypasses Glow in every blend mode. Tint is an sRGB multiplier; white preserves the highlight color. Saturation ranges 0...2. Highlight Threshold is measured after exposure in HDR units (0...100000), with HDR Scale controlling the transition width above that threshold (zero is a hard cutoff). Raising Scale makes extraction more gradual; lowering HDR Luminance Cap limits the halo source before level gains without dimming the actual light, HDRI or scene. Cap zero bypasses Glow. Anamorphic Stretch runs from vertical (-1) through circular (0) to horizontal (+1). Low/High Quality makes the source-prefilter quality/cost tradeoff explicit.

The first source filter uses Karis weighting to stabilize concentrated HDR highlights. It filters radiance and reciprocal weights together, recovers the filtered color, then applies exposure and the HDR threshold/scale response once: `C * smoothstep(threshold, threshold + scale, maxRGB(C))`. At the default threshold 1, values at or below white supply no Glow. Only the extracted signal is capped by HDR Luminance Cap per RGB channel, before level gains and Intensity. Scene HDR, HDRI radiance and lighting remain intact; subsequent reductions and level gains stay linear. This follows Godot's threshold, cap and initial-filter policy while retaining Crimson's filter kernels.

**Glow → Levels** exposes Level 1 through Level 7, tightest to widest. Each 0...1 slider is an independent linear gain. Halving an isolated level halves its filtered HDR contribution; it is not renormalized to full strength. Intensity scales the sum, so changing level gains also changes overall brightness. All zero bypasses Glow. Default gains are 0, .8, .4, .1, 0, 0 and 0. Disabled settings retain their authored tuning. Blur/reconstruction filter samples normalize internally; authored level gains do not.

Spread selects the filtered image's base extent rather than separating sparse blur samples. At Spread 1 and zero stretch, High starts half resolution and Low quarter. Below Spread 1 the base can grow up to full resolution, so tighter halos can cost more memory and GPU time. Progressive source reductions stay at most 2:1 per axis. The shared FP32 pyramid uses up to five source prefilters, seven weighted levels and six reconstruction passes, at most eighteen compute dispatches. Levels beyond the widest nonzero gain are skipped. The normalized source filters use thirteen sample positions; reconstruction uses a nine-position tent at fixed one-texel spacing. Glow reads existing HDR color and needs no separate emission capture or extra geometry attachment. It never enters GI donors; grid/tools compose afterward.

**Blend Mode** selects Additive, Screen, Soft Light, Replace or Mix. Additive adds Glow in exposed HDR before tone mapping. Mix reveals an amount slider (0...1, default .5), crossfading exposed scene HDR and Glow. Replace selects Glow in that same HDR domain. Screen and Soft Light apply bounded blend equations to separately tone-mapped Glow and linear display color after editor-matte composition, preserving existing scene values above one separately. The retained Mix amount survives mode changes. These are Crimson's color-space rules; familiar blend names do not promise another renderer's identical output. Blend mode changes add no filtering pass or resource.

The shared serializer writes only `glow` with `source: "Scene"` and direct level gains. Older full-scene four-field Glow retains its controls and default gains. For the replaced emission-Glow/separate-Bloom representation, active full-scene Bloom takes precedence; otherwise active Glow's style is retained. If neither contributes, Bloom's inactive tuning is retained when present. Old normalized Bloom levels divide by their sum once; old emission Glow's Core/Halo Balance converts to seven gains. Old softness converts once to HDR Scale (`4 * threshold * softness`), including its omitted .5 default. Older representations retain omitted historical intensity/blend/level defaults; new and reset profiles use the defaults above. Writers emit only HDR Scale and cap. A current source marker prevents repeated conversion. The source of all converted settings is now the complete HDR frame. Loading does not rewrite files, mark scenes dirty or change schema versions. Settings support normal undo/redo, duplication, cancellation and Play isolation. Browser thumbnails omit Glow.

The [Glow levels audit](GLOW_LEVELS_AUDIT.md) records the source comparison, reproduced slider defects, fixes and current verification. The [previous Glow/Bloom checkpoint](GLOW_BLOOM_CHECKPOINT.md) retains historical timings and evidence for the replaced two-effect implementation; its memory/timing figures do not describe this consolidated Glow.

Geometry A stores validity/reactivity plus seven bits per RGB diffuse-response channel as an exact 23-bit integer in RGBA32F. Additional path segments multiply the decoded, bounded response at intermediate hits, keeping material color and energy loss separate from Strength. Each segment has its own Max Distance bound. Captured radiance remains free of prior GI; changing Bounces extends the path rather than increasing a feedback multiplier.

Tracing samples the full cosine hemisphere over time with independent channels of a 32×32 blue-noise table and temporal rotations. Rays clip to the actual visible frustum before their finite step budget is distributed, and each ray/path vertex jitters its marching phase while retaining the terminal endpoint. Perspective-correct depth crossings retain refinement and accepted-hit energy throughout Reach. Temporal reprojection reconstructs geometry-valid bilinear history using actual capture centers, including odd extents; per-tap plane/depth checks prevent tangential pixel displacement from discarding valid history.

The reconstruction order is trace, temporal reprojection, short-history/variance reconstruction, medium-scale filtering, wide-scale filtering and full-resolution atlas publication. Raw first/second moments use linear luminance (`.2126R + .7152G + .0722B`) in separate RGBA32F history; spatial filtering never substitutes its blurred RGB for those raw statistics. Valid history age ramps accumulation up to authored Stability and is bounded at 64. Geometry-aware neighboring statistics bootstrap variance while fewer than four valid frames have accumulated. Three geometry/luminance-guided filter stages use default steps 1/2/4 and propagate variance with squared normalized weights. Only the first, modest step-one result feeds next-frame irradiance history; wider filtering affects the displayed result. World/Character irradiance remains separate in two-layer RGBA16F arrays, allowing each compute dispatch to fit eight bindings. This is a bounded SVGF-style reconstruction, without the full A-SVGF or NRD feature set.

Rigid mesh occurrences, including independently moving instances, publish previous-minus-current world displacement and validity through an optional full-resolution RGBA16F depth-prepass MRT. Receiver history and traced donor lookup each use their own surface's displacement. Per-view previous transforms, material/geometry fingerprints and frame continuity validate correspondence. Instanced draws keep a separate previous transform for every occurrence without increasing record size or losing picking identity. Motion is invalid for new/incompatible geometry/materials, runtime-changing graph inputs and skin/morph deformation, so those receivers reject history; unsupported donors retain camera-only position/normal validation. Historical normals are not separately transported, making large rotations conservative history-rejection cases. The motion target adds eight bytes per full-resolution pixel per view and is not allocated for SSAO alone. This foundation does not implement temporal AA/upscaling.

Known authored material-energy, ordinary-light or environment-lighting changes cap the active view's history age at four for the corresponding captured-source update. This increases current-frame influence without resetting history on moving-donor hits or interpreting every missed random ray as an extinguished source. It is a known-event response rather than a general lighting-confidence estimator. Exposure, tone mapping, camera/object transforms and GI quality do not enter the source-energy fingerprint. Finite accumulation, sparse bright emitters and newly revealed/offscreen surfaces can still produce noise or lag; the reconstruction does not guarantee noise-free transport.

The first Screen Space frame after enabling/resetting contains zero GI. Camera cuts, projection/size changes, frame gaps, identity/settings/program changes and invalid geometry reject old history. Material/particle previews and thumbnails do not clear Scene/Game receiver draw histories. Separate Scene/Game owners account for active, pending and retired resources and release them before bgfx shutdown. Unsupported capabilities/allocation errors keep ordinary lighting and expose a status in the active Environment Inspector without switching authored Enabled off.

## Persistence, materials and startup

Quader UV interpolation is mesh data: None=0, Circular=1 and Quad=2. Circular mode
preserves radial/angular texture flow; Quad mode preserves ordinary inverse-bilinear
mapping. Coordinates, correction and the explicit mode survive managed packages
and model cache revision 8. Embedded and generated mesh programs reconstruct UV0
before the material UV transform. Nonlinear tangent-space normal mapping derives its
frame from the final material UV after scale/rotation, with no second normal
rotation/sign adjustment. Normalized derivatives keep frame conditioning stable
with camera distance; the bitangent follows `B = cross(N, T) * sign`. Color,
alpha coverage, depth, picking and shadow passes use the same coordinates;
ordinary UV, UV1 and triplanar mappings keep their existing behavior.
The current material generation retains this UV interface without additional material
samplers or mesh subdivision. It retains the PointShadow prior-world varying and
motion-prepass output with four lighting color outputs plus the fifth unfogged SSR source; the superseded visible-emission attachment remains removed. The 27-float/108-byte vertex layout is unchanged. Nonlinear primitives retain their original
LOD geometry until a chart-aware simplifier is available.

Preserve model slot overrides, factors, texture roles/channels, UV/tangent compatibility and reference-aware deletion policy.

An exact conventional opaque PBR subset uses the embedded model program as its complete implementation; it must pass `materialGraphFixedSurface` certification. `materialGraphLegacySurface` is an adapter and cannot certify arbitrary graphs. Unsupported expressions/coverage use generated complete pass bundles. Parameter values, texture identities/samplers and compatible UV transforms are data changes, not new shader permutations.

Warm generated bundles hydrate through content/compiler/build/dependency-aware cache validation and preflight without shaderc/jobs. True misses prepare asynchronously; the scene is never hidden behind a whole-world Preparing Materials gate. Keep the complete last-good packet, including programs, uniforms, textures, coverage and render state, until its coherent replacement publishes. Initial misses use the supported fallback, not arbitrary texture/opacity inference.

Current interactive misses skip costly surface-fragment FXC optimization for first publication, then prepare O3 after 750 ms of quiet. Background work cancels/shares according to current owner revisions. Optimized and interactive policies have distinct identities. Stage names follow their own source, and independent coverage traversal/slots avoid invalidating unchanged coverage merely because surface code changed. Native catalog scanning already discovers explicit shared-material identities; model completion does not repeatedly rediscover/reserialize them. Named engine shaders whose contents match the embedded baseline use embedded programs immediately. Release uses the paired staged shader/include/compiler family, never newer checkout sources with a potentially incompatible manifest.

`Build.cmd Release` also runs project material-cache preparation, coalescing topology/stage work and writing derived cache only. This pays a changed renderer family's custom compile cost before handoff. A new external project or genuinely new graph can still compile at runtime. Cache-only hydration, shader compilation, total startup and gameplay FPS are different measurements. The canonical implementation/limitations and scoped evidence are in [Material shader startup](MATERIAL_SHADER_STARTUP.md); do not copy historical timing tables here.

## Visual tools and focused diagnosis


During Play, focus Game and press **F1** to toggle the top-right metrics overlay. It reports FPS/frame time, main-thread CPU work, backend GPU time, backend Device VRAM where available, tracked textures/programs/models/shadows and engine draw count. Missing device/timer values show N/A. These are not OS CPU utilization or a complete per-pass GPU profiler. Input guards preserve text fields, popups and drag ownership.

For paired API measurements, the explicit `renderer_backend_benchmark` utility runs the same isolated draw-heavy and effects-heavy fixtures in fresh `--backend dx11` and `--backend dx12` processes. Each covers Game alone and simultaneous Scene/Game, defaulting to 1920×1080 per view and 120 warmup frames. `--samples 360` requires at least 360 actual distinct GPU queries from a fixed 720-frame CPU window on both APIs, covering three complete motion cycles; 16 untimed frames expose delayed results. The pinned bgfx statistics API retains only the latest completed query, so intermediate GPU frame IDs may be unavailable when several queries complete between reads. The report records actual coverage and gaps, counts no duplicate results and fails if the requested number of unique samples is unavailable. Its report and raw CSVs separate CPU preparation/submission, completed GPU query samples, renderer-owned allocations and DXGI process residency. CPU frame timings include the hidden primary-window Present and queue backpressure with VSync off on both APIs; GPU timestamps cover submitted scene/compute work. The fixture excludes authored scene loading, simulation, editor UI and visible desktop composition latency. See [README reproduction commands](../README.md#build-checks-and-user-acceptance); fixture results require their own measured report and do not establish gameplay FPS or a universal API advantage.

The benchmark disables optional per-view GPU profiling and uses the ordinary primary presentation cadence without an extra native DX11 flush. Whole-frame GPU timestamp elapsed time includes any queue-feeding gaps inside its bracket and is not an active-GPU utilization measurement. The [measured backend comparison](RENDERER_BACKEND_COMPARISON.md) records the local RTX 4090 results and the repaired DX12 query-readiness contract; earlier GPU results from the unpatched timer are superseded.

The **Scene diagnostics → Shadows** section reports maps/projections refreshed this frame and cache hits, not just allocations. Zero updates can be correct with visible cached shadows; wider PCSS still costs sampling. The dedicated Key counters differ from ordinary directional Character projections. Read [SHADOW_DIAGNOSTICS.md](SHADOW_DIAGNOSTICS.md) before interpreting allocation/deferred numbers or drawing memory/performance conclusions.

Common symptom routing:

| Symptom | Check first |
| --- | --- |
| Source Radius has no effect | Cast Shadows/admission, radius above zero, actual caster-receiver separation; specular can be disabled |
| Wall flickers at grazing movement | Receiver normal/plane consistency, bias sign, cube seam/tile addressing; test reflected/sloped geometry |
| Gray or missing textures at launch | Certified path/fallback and coherent packet state; cache/source-family/preflight diagnostics; do not erase authored textures |
| A light is visible but shadow count is lower | Distinct 4,096 direct-source versus 16-map admission and four-update budget |

## Focused verification map and future boundary

Documentation-only edits need source/link consistency checks, not an application build. Code changes use `Build.cmd Release` after implementation owners finish, followed by focused CTest selection. Ask to save/close a running renderer only immediately before that executable build. Do not run routine capture/acceptance suites or control the user's PC without permission. User visual acceptance is separate from CPU/headless evidence.
