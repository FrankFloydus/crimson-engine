# Crimson Engine: ARPG engine architecture

This is the authoritative engineering guide for the native Crimson Engine ARPG engine. Consult the sections relevant to changes in rendering, assets, scene/runtime boundaries, input, or resource lifetime. Keep it current when an agreed implementation changes these contracts.

The foundation is the native renderer and editor in this project. Work progresses through small slices with a working application at each handoff. Features described as planned are architectural commitments, not instructions to build every subsystem before the next milestone.

Primary checkout: `C:\Users\Drako\Desktop\_CRIMSON_ENGINE\crimson-engine`. Each build embeds its own checkout as the default project root; isolated worktree executables therefore resolve project assets, layouts and caches within that worktree. Application-wide Preferences retain their shared behavior. The official renderer name, CMake target, and executable are `crimson-renderer`, `crimson-renderer`, and `crimson-renderer.exe`. Renderer implementation, shaders, the ImGui/bgfx adapter, and rendering diagnostics belong in `src/crimson-renderer/`. Editor orchestration belongs in `src/editor/`, docked views in `src/tools/`, CPU scene/history/storage in `src/scene/`, Play/input/controller orchestration in `src/runtime/`, Jolt adaptation in `src/physics/`, and managed imports in `src/assets/`. `src/math/` owns the public math boundary. Keep `App` focused on composition, native lifetime and the frame loop.

### Particle-system baseline and planned extensions

[Particle system pre-work](PARTICLE_SYSTEM_PREWORK.md) defines the CPU-first effect assets, authoring workflow, research rationale and staged implementation. Steps 1–4 are implemented with broader user acceptance pending: one emitter with Point/Cone/Sphere/Box shapes, seeded variation, timing/explosiveness, optional forces, World/Local simulation, scalar appearance curves/ranges, RGBA gradients, independent effect/material history, preview/scene instances, material-owned textured Alpha/Additive sprites and ordered transparency. The next particle milestone is Step 5, Layered effects and timeline; Steps 5–14 remain planned and retain working saved effects at each handoff. Particle collision remains separate from the implemented Play character/static-Box Jolt world; particles currently pass through colliders. Native PBR material authoring and Save As from imported originals are available; imported-original editing remains milestone 2c as **Next**.

`ParticleEffectDocument` owns authored definitions, transactions and dirty state; `AssetLibrary` publishes immutable committed effect versions and preserves a currently open document's authority over background file notifications. Bounded native metadata reads and atomic storage occur at document/catalog boundaries; material, texture and geometry preparation stays with the existing resource and GPU owners. `CpuParticleSystem` owns dense records and 60 Hz scheduling. `SceneParticles` keys runtime instances by `SceneDocument::documentGeneration()` plus persistent entity ID, so registry rebuilds and transform edits preserve playback. Copied presentation values cross into renderer-owned buffers/programs. Live particles, playback and preview cameras are never serialized. Valid intermediate drags update only isolated preview; commits/undo/redo publish revisions. Color/size/intensity/opacity/orientation/billboard mode apply on extraction, Gravity/Acceleration/Drag on the next tick, rate/enabled on subsequent scheduling, and shape/launch/lifetime variation at birth. Capacity replacement clears records but retains the clock, emission phase and playback state. Seed, pre-process time, simulation space, timing or explosiveness changes replay from zero with Pause/Stop retained; identity replacement or explicit Restart/Play Effect performs a full restart. Cancellation follows the same field policy. Saving preserves playback.

Effect-level `preprocessSeconds` (0–60 s, default zero for v1–v6) completes deterministic fixed-tick simulation synchronously during each actual restart, before any first presentation is published. It uses the initial affine transform, ordinary scheduling/explosiveness/forces and authored seed; it does not invent earlier emitter motion. Scene placement/opening, Play startup, isolated preview and explicit replay use the same owner. This replaces the across-frame preparation queue that caused a visible gap on initial Play and Stop/Play. Per-tick spawn/scheduler limits, capacity and the authored time bound remain; normal live catch-up remains bounded separately. Large pre-process values/capacities can increase startup cost, as in the inspected Godot CPU approach. Finishing exposes the current warmed tick rather than an empty or one-tick-late interpolation result. Pause retains its state; Stop clears, and Play prepares again. Time edits replay under the existing schedule-edit policy, whereas movement and ordinary appearance edits do not restart it. Stopped edits retain an empty stopped instance. A finite one shot may be drained by the requested time. The startup feature does not implement Step 5 timeline/seek, which keeps its separate bounded-replay plan.

Effect schema v9 stores Billboard mode, XYZ orientation and one typed emitter, shape/ranges/direction/spread/flatness, Continuous/One shot/Looping timing, Explosiveness from 0 to 1, named Gravity/Acceleration/Drag presence/enable settings and typed appearance tracks. Readers accept v1–v9; v1–v8 explicitly migrate to Enabled billboarding with zero XYZ orientation, while newly authored effects default to Disabled; v1–v4 retain constant size/intensity/color/opacity, rotation zero and empty inactive appearance data without changing timing or references. Files before v4 receive Flatness zero; v3 RandomCone retains exact spread, Fixed retains its inactive setting, and Outward resets its formerly ignored spread to zero to retain radial appearance. Only explicit Save upgrades files. Behavior order is engine-owned, so the UI provides Add behavior, enable and remove without a stage/reordering interface. Delay applies once before the first cycle. Explosiveness compresses each cycle's rate-based birth times by (1 - explosiveness), preserving Rate × Duration and fractional counts across cycles. Zero keeps prior rate scheduling; one emits the full cycle budget at its start. Continuous emission with a positive value repeats the stored Duration, which is then exposed in the UI. One shots drain before completion and remain replayable. Older burst records remain bounded compatibility data under the optional v8 legacyBursts field; new files contain none, and the editor has no burst authoring controls. An explicit Explosiveness edit replaces those events, folding their count into the rate budget atomically or rejecting unsupported values. Legacy order prepares on definition publication; sampling and shared forces resolve once per emitter tick. Independent random channels use effect seed, emitter identity and spawn ordinal. Newborns integrate only their remaining fraction of a tick. Limits/counters cover 4,096 scheduled births and 32 scheduling segments per tick in addition to existing capacity, aggregate scene, catch-up and render limits; clipped work never builds a backlog.

`PreparedParticleAppearance` owns bounded immutable scalar/gradient segment arrays prepared on definition publication; curves own no playback clocks or document pointers. Size and Rotation support Constant, Random Range and Curve with absolute values; retained overall intensity uses those modes as Brightness beside Color. Curves evaluate interpolated normalized particle age; random appearance lanes derive from seed/emitter/spawn identity independently of compaction and other properties. No additional per-particle appearance arrays are needed for these functions. Size tracks allow 0–10,000 m (zero hides presentation), intensity 0–100,000 and rotation ±360,000 degrees. Authored curves/gradients require 2–32 stable unique keys/stops, ordered finite ages within [0,1], minimum age spacing 0.0001 and Linear/Constant interpolation. First/last ages can move freely within those constraints; evaluation holds the first value before its age and the last value after its age. This relaxes validation within native v5 while preserving older 0/1 tracks without rewriting them on load. Inactive data remains validated and retained; active ranges need values. Gradient RGBA replaces effect tint/opacity rather than multiplying the hidden constants, stores/interpolates canonical linear HDR RGB and retains linear alpha; v1–v5 decode their SDR RGB exactly once on load. All appearance modes/values/keys/stops apply live on extraction with particles, clocks and Pause state intact.

Particle authoring uses four framed macro sections in order: **Emitter Update**, **Spawn**, **Update** and **Render**. Their children are unframed collapsible subsections. Emitter Update separates emitter-wide scheduling from individual particle initialization: Timing & emission groups Enabled, Playback, Delay, Rate, Explosiveness, conditional Duration and Capacity; Simulation groups simulation space, Pre-process and Seed. Spawn contains Shape, Initial velocity and Lifetime. Update contains Forces with the existing enable/remove/add behavior controls. Render keeps complete appearance properties together, including their Constant/Random Range/Curve modes; changing modes does not relocate a property between sections. This is an editor organization, not a change to simulation stages, serialization or effect evaluation. The ordinary document gesture helpers remain shared by every subsection.

Render authoring uses collapsible Material, Orientation, Color & opacity, Size and Rotation sections; Material and Orientation start open and the other appearance sections start collapsed. `HdrColorEditor` supplies a compact swatch, expandable linear channels and independent opacity without rewriting values on open. Brightness beside Color edits the preserved overall multiplier with its existing appearance modes. `ParticleAppearanceEditor` owns editor-only selection/view state, numeric editing and Add/Remove/Reset actions. Its ImPlot 1.0 curve plots support pan/zoom, Frame and double-click key creation. The Coollab RGBA gradient widget supplies stop interaction; Crimson's adapter retains authored identities, 2–32 bounds and valid age spacing. Any key/stop is removable when more than two remain, including edge keys. Plot navigation is transient; one authored gesture forms one effect-history transaction and Escape cancels it. Collapsing a property or losing its input ownership closes/cancels the active edit coherently. Renderer particle instance attributes occupy 80 bytes: position/size, linear RGBA, rotation radians/billboard mode, and world right/up axes. Disabled billboarding uses an orthonormal emitter frame plus live authored XYZ orientation; world particles retain the frame at birth, while local particles use the current interpolated presentation transform. Scale/shear/reflection extraction follows the shared affine rotation helper and preserves square world-meter size. Enabled retains the original camera-facing vertex path; FixedY constructs a world-Y-constrained facing frame with a finite pole fallback. The independent Rotation track spins within the selected plane. Normals/tangents use the same resulting frame for Lit, normal mapping and triplanar reconstruction. The material editor Sprite preview and protected material thumbnail explicitly remain camera-facing. Material/texture multiplication, global sorting and HDR composition retain their existing contracts. Selection/culling bounds expand by the maximum authored size's half-diagonal, and preview Frame uses conservative appearance extents, so growing or rotated sprites remain represented.

Initial velocity authoring presents Direction XYZ, Speed, Spread and Flatness together with an optional Outward checkbox; no Vector/Direction or Fixed/Random-spread mode selector is exposed. A pure display helper derives direction/speed from older vector velocity and effective zero spread from Fixed mode without changing the definition; intentional launch edits publish the corresponding direction/speed settings. Scalar speed supports 0–200,000 m/s, accommodating the norm of legacy vectors whose components each supported ±100,000 m/s. Spread is a 0–180 degree cone half-angle. Flatness 0–1 suppresses the cone's perpendicular component from full 3D spread toward a fan in the emitter-local axis/tangent plane; it does not flatten sprites. Outward applies the same spread/flatness around each sampled radial direction.

World-space births transform position and launch velocity by the full affine emitter matrix, then detach; forces use world axes. Local particles simulate forces and motion in emitter coordinates and transform through the current full affine hierarchy on extraction. During Play, fixed ticks use the current simulation transform for births; local rendering and bounds use the copied interpolated presentation transform, so particles attached to a moving actor follow its rendered pose without mutating the simulation world. No ECS pointer crosses that boundary. Sprite width/height stays in world meters in both modes. Scene transform edits preserve playback; choosing a different simulation space intentionally restarts as above. No transform decomposition or per-particle ECS entity is introduced.

The particle and material editors use `ImGuiWindowFlags_NoDocking` and clear only their own saved dock assignments. Dear ImGui multi-viewports are enabled through its SDL3 platform backend and renderer-owned `ImGuiBgfx` callbacks. Each secondary native window has one persistent DXGI swap chain owned by `PlatformSurface`; resize and collapse/expand use `ResizeBuffers` after releasing backbuffer references. Ordinary resizing never recreates that chain. The pinned bgfx native-window framebuffer recreation path is bypassed for secondary windows: bgfx renders ImGui into an ordinary framebuffer backed by a renderer-owned D3D11 RGBA8 texture, then `postFrame` copies its pixels to the matching native backbuffer and presents after the application's single `bgfx::frame()`. This adds one GPU copy per presented secondary window, with no extra exposure or color encoding. View IDs retain natural numeric submission order: procedural compute 0, active-world shadows 1–96, Scene 97–103, particle preview 104–110, reserved 111, picking 112–113, thumbnail shadows 114–209, thumbnails 210–214, material preview 215–221, Game HDR/Glow/tone-map/encode 222–227, main tools 228, and platform windows 229 upward. Game omits the editor grid; Scene, Game and live preview contexts reserve three additional Glow passes. Thumbnails omit Glow. The reserved slot and identity ordering preserve picking/thumbnail readback scheduling: the pinned D3D11 backend compares remapped blit-order keys with decoded numeric view IDs, so reordering the former UI pass around those readbacks is unsafe. Every offscreen image now completes before either main or platform UI samples it; all UI windows share the existing shaders/texture owners. The wrapper is imported only after its placeholder exists, and its external texture remains owned until queued framebuffer/wrapper destruction completes; shutdown drains those retirements before releasing the renderer/context. Native operation failures log the stage, HRESULT and window details rather than routing through bgfx's fatal native-chain creation. This follows [Microsoft's resize contract](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/nf-dxgi-idxgiswapchain-resizebuffers) and [copy requirements](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-copyresource).

Platform windows are destroyed while SDL/ImGui/bgfx are still alive. When the main window cannot draw, one ready visible secondary window supplies synchronized presentation; other windows present without a second synchronization wait. Pending or occluded surfaces use a bounded sleep fallback. UI positions use desktop coordinates and the host viewport's framebuffer scale; scene navigation filters SDL events by the owning window ID. Focus in any owned editor window keeps playback active; total focus loss or no drawable windows suspends it without accumulating wall time. Closing a secondary particle or material window closes its document, while only main-window close requests exit. A main-window exit request restores its minimized host so dirty-document prompts can run. Existing dockable panels retain their layout, and built-in ImGui DPI scaling follows the host monitor without a custom theme.

Sprite shadow casting and per-particle ID picking remain separate geometry features. Mesh picking shares graph coverage/mapping and clips effective transparent opacity below .01; Masked uses its cutoff. Center sorting does not solve intersecting/self-overlapping transparency; refraction, transmission and OIT remain outside this implementation.

`MaterialGraphShader` lowers reachable expressions into deterministic mesh, picking, point-shadow and particle variants. The generated recipe records source/stage/varying/includes and a uniform manifest, while named engine shaders retain their strict existing reload interface. Topology, model and sampling-mode edits select variants; scalar/color values, UV transforms, images and sampler changes update packet data. Arbitrary compatible Multiply chains, including texture × texture, are evaluated as expressions rather than flattened to five fixed slots. Limits are 144 nodes, 288 links, 12 active texture bindings and 208 vec4 parameter rows, further constrained by device capabilities; added headroom allows migration of full earlier graphs without truncation. Graph textures use slots 0–11; generated mesh/sprite IBL uses 12–14 and shadow uses 15. Color/data/normal decoding and the shared opacity expression must agree across visible surfaces, picking and shadows.

`MaterialGraphPrograms` is the explicit main-thread GPU owner; resource workers compile CPU binaries and never call bgfx. `PreparedGraphMaterial` pins a complete program generation, uniform values, role-correct texture/sampler bindings and resource leases. Only complete current generations replace rendering; pending or failed preparation retains the last usable material and exposes a concise diagnostic. Particle packets/batching account for the actual program and parameter signature. All submitted leases and program owners retire before bgfx shutdown. Focused checks cover graph/migration/history, asset deletion, generated shader compilation/preflight, headless publication/lifetimes and canvas interaction/draw data. Hidden native pixel checks cover opacity, mixed mesh/sprite ordering and blending, including direct and radial-modulated Particle Color alpha on Lit/Masked sprites with emission; user-facing visual acceptance remains with the user. On initial preparation, embedded basic programs provide a diagnostic untextured fallback until the generated bundle is ready; they do not infer opacity from a base-color texture. Subsequent preparation or failure retains the prior complete graph packet, including its render state and bindings. A temporary fallback is never mistaken for a complete published graph.

Material mapping functions are shared in `material_mapping_functions.sh`, with `material_mapping.sh` retaining the legacy uniform wrapper: ordinary UV0/UV1 uses XY scale, Z rotation and XY offset; local triplanar mapping uses scale → Euler XYZ rotation → offset and blends the three axis projections by absolute local normal weights. Normal samples are reoriented into their projection axes before blending; ordinary normal maps follow UV rotation/reflection. Model, picking and point-shadow alpha passes use the same coordinates, sampler and mask inputs. Sprite vertices supply their real world position, unit-quad local position, camera-facing normal and rotated tangent to the common mapping functions. UV1 aliases their single UV0 domain. Migration normalizes legacy Unlit Alpha/Additive projection flags to UV0 while retaining all transform values, matching the old sprite shader's ordinary XY/Z sampling. Prepared-material signatures, streaming density and masked-shadow cache keys include mapping changes; positive tiling does not change normal strength. Missing UVs/tangents do not prevent triplanar replacements. Link scale is authored UI state and retains ratios during a gesture. All values participate in material validation, serialization-based history, live preview and committed resource publication.

The legacy version-3 `ModelMaterial::triplanarWorld` flag migrates to the UV node's World Triplanar mode, retaining Godot-style separate local/world projection. Missing legacy flags select local projection. Local mode samples raw mesh positions: scaling an entity stretches its texture coverage, while changing actual mesh dimensions adds repeats. World mode samples the fully accumulated model position and inverse-transpose world normal, so parent/entity scale increases repeats and projection remains fixed in the level under translation/rotation. At mapping scale one, one world meter is one texture period. All material maps, normal-map projection bases, picking and shadow masks select the same coordinate space. Material/thumbnail signatures and masked-shadow cache keys include the flag; texture demand accounts conservatively for the world transform's stretch. Both modes retain the same mapping transform order and sharpness-one blend weights. Sprites expose both local and world projection through their shared surface graph; legacy sprite projection flags migrate to their original UV0 sampling behavior.

`editor/MaterialPreview` owns transient mesh choice, prepared material/texture leases, an independent preview camera and HDRI request/settings. It consumes valid working `MaterialDocument::definition()` values during property drags without publishing them to asset users; only successful document commits/undo/redo publish complete revisions. The Environment menu contains HDRI pick/drop/clear, environment lighting, intensity, Y rotation, tone mapping, Glow and Show background. These values are never written into a material, effect, scene or `assets/environment.json`. Quader's material mini-viewport is the navigation reference: MMB tumbles the object, Shift+MMB pans, Ctrl+MMB rotates the preview environment, the wheel changes distance by reciprocal 1.12 steps, and double-click MMB resets the view and environment rotation. Gesture deltas use the host viewport's physical framebuffer pixels and respect widgets, popups, text input and focus ownership.

`Renderer` owns the material preview's independent HDR/composite/display targets and `EnvironmentLighting`, using views 215–221 and the application's existing single bgfx frame. Sphere is the default; Cube, Rounded Cube, Cylinder and Plane use shared built-in CPU geometry and tracked GPU model buffers. The existing sphere identity/generator stays compatible with accepted thumbnail previews. A separate sky program samples the prepared environment with the actual camera basis, intensity and rotation; HDRI preprocessing remains in CPU resource workers. Renderer submissions retain prepared leases, preserve the scene/particle/thumbnail environments and targets, and release GPU owners before bgfx shutdown. The editor requests release when its material document closes.

`AssetLibrary::preparedParticleMaterial` prepares the actual material slot through existing texture streaming, pins immutable definition/GPU leases, and retains an available last-good packet on dependency failure. CPU scene particles expose stable entity/material groups over copied presentation records, without GPU values. Renderer packets address per-frame material entries; stable depth sorting covers Alpha/Additive instances together, and only consecutive compatible packets batch. Work is bounded to 65,536 packets, 512 material entries and 1,024 particle draws per view plus GPU transient availability. Effect -> material -> texture references include persisted owners, active edits and history. Typed deletion uses the explicit soft-particle default for affected effects and the existing PBR default for models; material textures use the same role-correct replacement policy for both consumers. Open material/effect documents retain working authority over disk notifications and must close before their root asset is deleted. Ordinary material thumbnails use a sphere, with a quad for the protected particle default. The material editor offers Sprite as an explicit transient geometry choice; its graph controls coverage. Independent node previews remain opaque visualizations.

Particle gravity and optional acceleration are authored forces integrated by the CPU particle subsystem, independent of rigid-body physics. Without drag, constant-force motion uses `position += velocity * dt + acceleration * dt * dt / 2`, then `velocity += acceleration * dt`; launch velocity is assigned once at birth. Drag uses an exact constant-force/exponential damping solution with stable small-interval evaluation. New starters have zero initial velocity and fall immediately. Explicit upward launch values remain valid and are preserved in existing assets. Particle simulation does not call Jolt; static collision queries remain assigned to the particle collision milestone even though the Play controller now owns a Jolt world.

### Concrete editor and math boundaries

`App` constructs owners, initializes the window/renderer, forwards events and drives frames. `ResourceRuntime` publishes worker results, acknowledges self-writes, dispatches watched changes and coordinates shader replacement before editor drawing. `EditorSession` selects the authored or transient Play document and owns document/session actions; `PlaySession` owns runtime simulation and interpolated presentation. `EditorResources` freezes coherent prepared model groups, and `AssetPreviews` schedules isolated thumbnails/readbacks/cache writes. `SceneEditor` coordinates editor commands; `SceneViewport` owns picking, gizmos, focus and navigation input arbitration. Engine public interfaces use `Vec2/3/4`, `Quat`, `Mat3/4`, `Ray` and `Aabb` from `src/math`. Matrices are column-major, multiply column vectors and default to identity; accumulation uses explicit zero matrices. GLM is private to the math implementation. Serialization writes packed scalar arrays, while renderer and ImGuizmo adapters use explicit `.data()` boundaries. No GLM, bx, ImGui or GPU-specific math type becomes persistent scene data.

The construction grid keeps its geometric clip position unchanged and computes biased fragment depth from interpolated world position. This avoids depth precision loss when the large plane crosses the eye or near plane, while retaining depth-tested scene occlusion and Quader's analytic coverage. The existing coplanar bias is applied after projection using the backend's depth convention. Viewport collision fills/wires and markers draw before orange selection bounds; transform handles compose last. The Windows platform helper persists `WINDOWPLACEMENT` restored coordinates and maximized state atomically in project-local `crimson_window.json`, separately from authored scene data. Diagnostic/hidden/frame-limited launches do not replace the main window placement.

### Keyboard actions and ownership

Current routing has explicit owners: SDL events reach ImGui, the editor session, Game input and editor navigation; Game filters its native window and image ownership, and document shortcuts respect active text/widgets. `input/KeyboardActions.h` supplies a small reusable binding value that distinguishes layout-aware `LogicalKey` from location-based `PhysicalKey`, normalizes left/right modifiers, ignores Caps/Num Lock for shortcuts, rejects additional modifiers and ignores repeat events. `editor/PlayShortcuts` uses logical P for Start and Shift+Escape for Stop. Plain Escape retains its existing interaction-cancel/Game-release behavior.

The remaining scene/document shortcuts and navigation bindings still live in their existing owners. Rebinding configuration and UI are not implemented. Extend this foundation with stable action IDs and separate editor/game binding maps as those features are requested; input ownership must be resolved before an action reaches a document or controller. Store key identity and binding kind rather than a localized display label. Continuous movement reads held state; one-shot commands use press edges, and focus loss cancels both.

Follow [SDL's keyboard practices](https://wiki.libsdl.org/SDL3/BestKeyboardPractices): physical positions suit spatial movement controls, logical keys suit named editor commands, and Unicode/IME entry stays in SDL text-input events. A literal symbol such as `|` is a separate future binding policy: the base keycode in a key event may describe the unshifted key, so resolve the current layout and modifiers with [SDL_GetKeyFromScancode](https://wiki.libsdl.org/SDL3/SDL_GetKeyFromScancode) using `key_event=false`. Define how that binding consumes Shift/AltGr instead of confusing the resulting symbol with a physical position. Dead-key and IME composition are text input, not ordinary button bindings.

### Dependencies and resource ownership

- The application constructs services and passes explicit dependencies. Controller and gameplay code do not call ImGui or bgfx.
- Scene components/history carry persistent typed asset references, not residency handles or GPU ownership.
- The rendering boundary owns GPU meshes, material textures, environment resources, and targets. The tools adapter owns its ImGui GPU resources under the same bgfx lifetime.
- Physics owns Jolt worlds, bodies, shapes, constraints, and body-to-entity mappings. Actor/controller code uses the engine-owned adapter.
- Background decoding returns completed CPU results through publication queues. It does not create GPU resources or modify the world directly.
- The main thread initially owns authoritative world mutation and application-side render submission. Jolt may execute internal jobs; its callbacks collect facts rather than changing EnTT.

| `ResourceManager` | Immutable CPU model metadata/geometry, decoded images, materials, scene snapshots, environment bakes, shader binaries and derived-cache descriptors; workers, dependencies and retention |

| `Renderer` | Revision-aware shared model buffers, independent HDRI/procedural environment GPU resources, scene/sky/fog programs, picking and isolated model/scene/particle/material preview targets |

| `SceneDocument` | Mutable CPU scene, selection, immutable semantic edit patches and saved-state tracking |

`AssetRef<T>` preserves serialized IDs without keeping payloads resident. RAII `ResourceHandle<T>` expresses live interest; `ResourceSnapshot<T>` leases an immutable exact version. Publishing a replacement leaves old readers valid. Entries track source epoch, job generation, dependency fingerprint, published revision, state and diagnostics. Failed replacements retain the last working payload. Cache keys include identity/type/processing variant; image source decoding is shared while color/data/normal and mip policies remain distinct. CPU payload and GPU leases are separate; uploaded textures do not pin source pixels.

Two CPU workers serve a bounded deduplicated priority queue. Selected/visible content and placement take priority over browser previews. Imports stage complete packages on workers, then publish files/catalog entries on the main thread. Workers also decode images, process cgltf/MikkTSpace geometry, generate mip/LOD caches, bake HDRI environments and compile shaders. Dynamic procedural environment filtering runs in renderer-owned GPU compute work, not these CPU jobs. Workers never call bgfx/ImGui or mutate documents. Completed jobs carry generations/epochs and exact dependencies; stale work is rejected. Model/material/texture groups become visible only when coherent candidates are prepared before drawing. Existing working groups survive failed replacements.

The default soft targets are 512 MiB CPU and 512 MiB aggregate managed GPU resources, including a 64 MiB thumbnail sublimit. Idle retention is five seconds; pressure trims unpinned least-recently-used resources immediately. Pending and leased retired allocations count toward accounting. `Renderer::environmentResidentBytes` includes both HDRI resources and both procedural cube generations in aggregate GPU retention accounting. Live leases remain valid above soft limits. Model/image uploads are chunked toward 4 MiB and roughly 2 ms per frame; an individual backend call can exceed that time target. Browser requests only visible card resources. Editor/library metadata interests expire, and submitted draws/readbacks pin their actual CPU/GPU versions.

Shutdown stops watchers/new requests, cancels and joins workers/compiler processes, drains pending readbacks, releases editor/library/renderer/ImGui GPU owners before bgfx, then releases CPU caches and SDL. Async picks also carry document generation/request identity and the actual main-view resource signature; unrelated thumbnail changes do not invalidate them.

### Streaming and hot reload

Versioned texture-cache indices address independently readable, CRC-checked levels. Warm requests read required levels without full-source decoding. Cold requests first publish complete coarse physical textures whose longest edge is at most 64 pixels, then swap fully uploaded sharper allocations with valid mip tails. Color RGB filters in linear light; alpha/data stay linear; normal mips renormalize safely. All six glTF minification modes, magnification, wrapping and UV selection survive; non-mip variants are single level. Demand derives from projected bounds/UV use, shared consumers request the highest detail, selected models request native resolution, and invisible models do not refine. Picking and color rendering use identical resident alpha-cutout textures.

meshoptimizer 1.1 creates up to three compact attribute-aware LODs at half, quarter and eighth source triangle counts, capped at 1% source-relative error. LOD0 stays exact. Material boundaries, seams, normals, colors and tangent handedness constrain simplification; unsafe/useless reductions stop. Metadata/hierarchy/material references/bounds load independently from CRC-checked vertex/index payloads. Conservative affine-projected error chooses levels at one pixel with 20% hysteresis; selected models request LOD0. Complete candidates publish after chunked uploads, preserving previous buffers on failure.

A Windows watcher debounces managed sources and engine shader sources/includes for 200 ms, excluding caches/staging/archived import originals. Self-writes are acknowledged; worker fingerprinting invalidates transitive dependencies. Texture/model/material/environment/scene candidates preserve working resources on invalid changes or unexpected disappearance. Clean active scenes reload between gestures while preserving camera/surviving selection; dirty scenes offer Reload/Keep editing/Save As, and overwrite requires resolving an external-save conflict.

Shader workers use the pinned shaderc build configuration with discovered include dependencies and a versioned cache. Binary structure, reflection/uniform/sampler/layout/stage contracts and private DX11 bytecode preflight are checked before GPU creation. Compute preflight also checks the procedural filter's 8×8×1 thread group and image bindings. Renderer program families and ImGui publish together, including model/picking parity. The visible sky and procedural compute programs form one atomic reload group; a committed compute replacement invalidates both procedural owners for filtering with the new evaluator. Renderer shader signatures include all twelve program hashes. Embedded programs are startup fallback; failed compilation/interface/preflight retains the current complete program group.

## 3. Rendering and material contract

Use a right-handed, Y-up world with meters as the distance unit. Camera, picking, physics, scene transforms, and imports use consistent conventions; backend conversions belong at their adapters.

Retain the current direct-light BRDF: GGX with `alpha = perceptualRoughness * perceptualRoughness`, height-correlated Smith visibility, Schlick Fresnel, and Fresnel-weighted Lambert diffuse. The visibility term already contains the Cook-Torrance denominator; do not divide by it again.

Keep the current roughness floor of `0.045` and numerical safeguards until a measured, explicitly documented shading change replaces them. Avoid changing the material response by copying a different approximation under the same parameter names. Point lights currently remain punctual sources: their radius is an influence range, not a physical emitter size. Very low roughness concentrates their reflected energy into narrow HDR highlights; Glow can spread that reflected light as well as emission.

### Color and texture meaning

Particle colors and gradient stops use canonical linear HDR RGB in effect v6 and later (current writer v9). The shared picker presents an sRGB swatch and expandable linear channels, with opacity independent; stored HDR values remain unchanged until explicitly edited. Readers validate v1–v5 SDR bounds and decode once on load, retaining all earlier appearance and overall-intensity functions. Ordinary color editing is inside Color; the earlier constant/range/curve intensity is retained beside it as Brightness. Values are bounded to RGB 1,000,000 and the preserved multiplier to 100,000; prepared presentation accepts their finite product. Gradient sampling interpolates linear RGB/alpha directly. Changes retain live particles and clocks.

`EnvironmentSettings::glow` owns Enabled, Strength, Size/radius and Threshold independently of the environment-lighting flag. Glow defaults off for compatibility. Introduced in scene v5, it remains in v8; scene equality, validation, transactions, Play clones and extraction retain it. Legacy `assets/environment.json` reads optional Glow and saves atomically. Particle/material preview environment controls are transient and independent; browser thumbnails deliberately omit Glow. The renderer extracts exposed visible HDR color through a soft threshold into two lazily allocated half-resolution `RGBA32F` targets, then applies contiguous horizontal/vertical Gaussian blur and combines the result before the existing tone mapper. Alpha is not a Glow mask: zero-coverage additive sprites still contribute radiance. Coverage, exposure-independent editor matte and grid remain unchanged. Each live view owns its scratch targets and retirement; allocation failure retains a valid view with a diagnostic. Disabled Glow or zero Strength/Size bypasses these passes. Glow supplies a screen-space halo and does not create scene lighting.

Glow keeps its authored Gaussian width (`sigma = max(0.25, 3.25 * Size)`) and normalizes both separable passes, but samples through `ceil(7.5 * sigma)` instead of cutting off near 2.46 sigma. The previous outer sample retained roughly 4.8% of the peak weight, producing a bright square boundary around isolated HDR highlights. The extended tail preserves the Gaussian's radial profile and puts the cutoff below one display code throughout the tested mesh-radiance/exposure/Strength range. It increases the maximum per-pass sample count from 129 to 391 at Size 8; resources, pass count and disabled behavior are unchanged. Shared CPU/shader kernel checks cover fractional sizes, energy, symmetry, tails and bright impulses. Arbitrarily accumulated particle radiance is checked for finite output, not a universal invisible-tail guarantee.

- Accumulate lighting in linear HDR. Apply exposure and tone mapping once; encode the final image to sRGB once.
- Particle rendering uses a blend-capable `RGBA32F` accumulation target. Alpha stores continuous coverage: opaque draws and a visible sky write one, empty pixels clear to zero, Alpha particles use premultiplied OVER and additive particles preserve destination alpha. The resolve computes `toneMap(exposure * HDR) + (1 - coverage) * linear editor background`, replacing Step 1's inverse-Reinhard background term so dark smoke attenuates exact white. When the source background is hidden, its solid matte stays outside exposure/tone mapping; a visible sky participates in HDR. Tone mapping combined premultiplied HDR once approximates separately tone-mapping each transparent surface, and intense emission can saturate at display white. Draw the neutral grid into `RGBA16F` display-linear color and clamp/encode once to sRGB. This is Crimson's chosen integration, with regression checks for backgrounds, coverage, mixed blending and opaque rendering.
- Preserve the editor sequence: **HDR sky and surfaces with distance/height fog -> exposure and optional Glow -> selected tone mapper into linear display color + exposure-independent solid matte -> grid -> sRGB encoding and optional display-space Debanding at the 8-bit write -> ImGui tools**. Visible sky follows scene exposure; the hidden-background solid matte, grid and tools do not.

`EnvironmentSettings::toneMapping` selects Linear, ACES or AgX, with Reinhard retained as value zero/default for existing scene appearance. Scene v8 and legacy environment persistence write the optional selector and Glow settings; old files still load without rewriting. Scene equality/validation/history, Play clones and saved-scene extraction retain it. Renderer passes the selector through `u_presentParams.z` independently for Scene, Game, material/particle previews and thumbnails. Material and particle preview selectors remain transient; asset cards use fixed preview settings. `ToneMapping.cpp` supplies a CPU reference for the shared `tone_mapping.sh` equations. ACES uses Godot's SDR fitted transform with white 1; AgX uses the local Godot source's inset/outset and allenwp curve with white 16.29 and contrast 1.25. Both produce display-linear RGB; the final encode performs the only sRGB transfer. The shader retains source attribution and notices. Negative ACES fit undershoot is clamped before composing the editor matte.

`EnvironmentSettings::debanding` is an optional authored boolean, default false. The Environment Inspector exposes it under Post-processing with its own transaction. Scene equality/history, Play copies, serialization and saved-scene thumbnail keys retain it. The final presentation shader adds a small display-space dither after the single sRGB transfer and before writing the 8-bit target; it does not perturb linear HDR lighting, fog, exposure or tone mapping. Scene, Game and saved-scene thumbnails use the authored setting. Independent material/particle/model previews do not inherit it, and ImGui tools composite afterward. Missing fields in older scene and legacy environment files remain false.

The color audit confirms role-correct sRGB decoding for base-color/emission, linear normal/scalar/alpha data, linear-light color mips and display-encoded cached thumbnail PNGs. ImGui samples texture thumbnails without sRGB decode and displays already encoded rendered targets without a second encode. Raw image previews are not lit or tone mapped (except HDR source previews); material cards use fixed key/fill lighting while the Material Editor uses its independent HDRI. These lighting/exposure/curve differences can change perceived brightness without a gamma error. Focused CPU curve and hidden D3D11 readback checks cover transfer correctness and context isolation.
- Texture roles specify decoding and channel selection. Albedo is sRGB color; roughness, metalness, and normal maps are linear data.
- Environment panoramas use linear radiance for Radiance HDR and sRGB decoding for PNG/JPEG/TGA/BMP. HDR thumbnails are tone-mapped display previews; preprocessing reads the original HDR source. HDR sources cannot be assigned to material slots.
- Texture 2D nodes expose explicit channel pins. The separate legacy sphere path continues to sample standalone roughness/metalness maps from red; graph authors connect the desired channel explicitly. Migrated glTF roughness/metallic maps preserve green/blue connections.

- Importing a model preserves its authored material factors. Import is not a manual picker assignment and must not reset those factors to neutral.
- Graph value/image/sampler edits update parameters/bindings without recreating geometry or recompiling topology. Wiring, model and sampling-mode changes select generated shader variants.

Future shipping UI composites after scene tone mapping and before final encoding so scene exposure does not change HUD brightness. Its C++ presentation code reads state and emits commands; it does not own simulation rules.

### Milestone 1: IBL and normal maps (implemented)

Scene environment lighting supplies diffuse irradiance, a roughness-prefiltered specular environment, and a two-channel BRDF lookup texture. The active Environment Inspector selects HDRI / IBL or Procedural Sky with a Lighting toggle and intensity 0–10. HDRI retains the adjacent picker/clear/drag-and-drop field and Y rotation −180° to 180°; an empty assignment uses the built-in studio. Material/particle preview menus remain independent HDRI controls.

HDRI preparation/cache loading runs on initialization or source assignment, outside ordinary frame rendering. Intensity and rotation reuse prepared resources. The CPU-derived cache lives at `assets/cache/ibl/<FNV64>.ibl`; its key includes source content, preprocessing version 3, BRDF version 1, dimensions and sample counts. Cache reads validate payload hash, length and finite/range constraints; incompatible or damaged data is regenerated. Authored sources and assignments are independent of this disposable cache. Visible HDRI backgrounds sample the prepared specular cube's sharpest level; this feature does not add a separate full-resolution source panorama texture or change the cache format.

The default studio is generated as a 512×256 HDR panorama. Derived RGBA32F cubemaps comprise 16×16 diffuse faces with 512 cosine-weighted samples and 128×128 specular faces with a full eight-level mip chain and 256 GGX samples. Specular mip roughness is `0.045 + 0.955 * mip / 7`; runtime selection follows that same range. A 128×128 RG32F BRDF lookup uses 1024 GGX samples with the runtime's correlated Smith visibility, roughness convention and denominator safeguards. Source HDR radiance is bounded to finite values up to 60000 for downstream HDR stability.

Environment convolution uses filtered importance sampling to prevent small, bright HDR emitters from producing scattered reflection copies. A linear source pyramid preserves spherical radiance integrals with exact latitude and cell-overlap weights, including odd image dimensions. Each sample selects and blends source levels by its probability-derived solid angle, with a lower bound from the destination cubemap texel footprint. Longitude wraps across the panorama seam; latitude clamps at the poles. These source levels provide spatial filtering and are distinct from the output cubemap's roughness levels. The filtering change invalidates older derived caches automatically; it does not change the BRDF, material roughness floor, exposure or source assets.

Use split-sum specular recombination:

```text
specularIBL = prefilteredEnvironment * (F0 * LUT.scale + LUT.bias)
```

Store diffuse preprocessing as irradiance divided by pi and apply that normalization once. Sum environment and direct lighting in linear HDR before exposure/tone mapping.

Karis's notes provide the split-sum reference. Its analytic-light roughness adjustment must not be applied to IBL, and its selected visibility approximation must not silently replace our correlated Smith model. The notes also describe the grazing-angle limitations of the prefilter approximation. IBL does not itself supply local geometry reflections or shadowing.

Material data includes a normal-map reference and strength 0–2 with the existing adjacent picker/clear/drag-and-drop pattern. Normal assignment preserves strength. Tangent XYZ points along increasing U; the sign in tangent W reconstructs the bitangent as `cross(N,T) * W`, oriented along increasing V. Maps use +Y/OpenGL green. The sphere supplies stable tangents at its duplicated seam and poles. The shader orthogonalizes interpolated tangents, provides a safe basis for degenerate input, scales tangent XY, and renormalizes the evaluated normal. Missing maps and zero strength use the original smooth normal; conventional `(128,128,255)` flat maps evaluate neutrally, with both nearest 8-bit encodings of 0.5 treated as zero XY.

Preserve material factors, direct lights, docking, Quader navigation, the grid, existing imports, and persistence. Normal-map and environment assignment data must also survive reopening.

Focused CPU regressions cover environment preprocessing and math. The user performs visual acceptance of environment-only material response, roughness-dependent reflections, neutral/detailed normals and reopening. Historical captures are retained separately and do not impose a feature-completion workflow.

Single-scattering GGX can darken rough metals through missing microfacet multiple scattering. This remains a known limitation; a later compensation must be a consistent BRDF change rather than an exposure adjustment. Split-sum environment reflections also retain their grazing-angle approximation and do not reflect nearby geometry or provide occlusion/shadows. Point-light shadowing is implemented independently below. Area lights, advanced material layering, other shadow types, and a different light pipeline receive separate scopes.

### Procedural environment, background and fog

`EnvironmentSettings` owns the source selector plus retained HDRI/procedural/background/fog values. Source changes do not reset inactive values or release authored asset references. `SceneEnvironment::sun` is a persistent optional directional entity ID beside exposure, outside render settings. Extraction resolves its current world direction toward the sun, sRGB color, intensity and enabled state into a transient `ProceduralSun`. No link supplies gradients alone; a disabled light keeps its authored assignment but contributes no disk/halo. Missing or nondirectional references normalize to None on load, deleting the linked entity clears the reference in the same undoable operation, and duplication remaps it when both entities are copied. No automatic sun is selected or created.

Procedural Sky uses Godot's artistic upper/lower gradients and sun disk/halo. Defaults are Sky Top `(0.385,0.454,0.55)`, Sky Horizon and Ground Horizon `(0.6463,0.6558,0.6708)`, Ground Bottom `(0.2,0.169,0.133)`, Sky Curve `0.15`, Ground Curve `0.02`, Sun Size `0.5` degrees, Halo Extent `30` degrees and Halo Curve `0.15`. Color fields store sRGB and decode once. Gradient exponents are `0.6/curve`; the halo exponent is `1.6/pow(curve,1.4)`. Size edits the angular diameter stored as `sunDiameter`; its half-angle sets disk coverage. Curves must be finite/positive, and halo extent must exceed disk radius and stay at or below 180 degrees. Direct light direction/color/intensity/enabled changes also affect the visual sun and sky-derived illumination. Gradients remain authored colors; this model does not simulate atmospheric scattering or physical sunlight units.

`ProceduralSkyGpu` is a concrete renderer-owned RAII compute owner with separate live-world and saved-scene-thumbnail instances. The live instance is prepared once per frame, and Scene/Game consume its same committed sky parameters and cube handles. Two alternating complete cube sets retain the previous generation when setup/allocation fails. Each dirty update enqueues nine dispatches in an earlier compute view: 16×16 diffuse faces with 512 cosine-weighted samples and 128×128 specular faces with eight roughness levels and 256 GGX sample candidates. Cubes use RGBA16F, diffuse stores irradiance/pi, and specular uses the existing `.045`–`1` roughness convention and existing BRDF LUT. All levels are queued before publication/consumption; no partial roughness generation is exposed. Visible sky and filtering evaluate `procedural_sky.sh`; angular footprint overlap preserves a subpixel sun disk's contribution. The key includes canonical effective sky/sun parameters and evaluator/filter constants. Unchanged keys reuse resources; camera motion, Environment intensity, HDRI rotation, background and fog do not rebuild the procedural cubes. Disabled-sun-only changes do not invalidate them. GPU allocation and dispatch remain on the rendering boundary; no per-frame CPU bake or authored file is produced.

`EnvironmentBackground::show` selects the visible source independently of Lighting. New Environment creation sets it true, while default/migrated scenes retain false. A visible source renders into HDR and follows exposure/tone mapping. When hidden, `overrideColor` selects its authored sRGB solid color, initially `21/255` per channel; otherwise the application Preferences matte is used. This solid matte remains outside exposure/tone mapping and does not illuminate surfaces. The scene Inspector exposes Custom Color and its picker only while Show Background is off. `EnvironmentPresentation` confines authored source/background/fog behavior to Scene, Game and saved-scene thumbnails. Material/particle preview menus and model/material thumbnails retain their existing separate lighting/backgrounds, and their preview controls do not mutate scene values. Saved-scene thumbnail fingerprints include the active source, resolved Sun and effective background/fog settings while preserving inactive authored parameters.

`FogSettings` owns independent artistic distance/height haze. Defaults are disabled, `mode=Exponential`, sRGB color `(0.6463,0.6558,0.6708)`, `density=0.01` inverse meters, `depthBegin=10`, `depthEnd=100`, `depthCurve=1`, `depthOpacity=1`, `height=0`, signed `heightDensity=0` and `lightEnergy=1`. Inactive mode values remain authored, validated and undoable. Begin/End must be finite/nonnegative; a positive End must exceed Begin, while End zero resolves against each rendering camera's far plane. Curve must be finite/positive, Max Opacity stays in `[0,1]`, Height and signed Height Density are finite, and Light Energy is finite/nonnegative. Height Density zero disables only the height contribution.

`fog.sh` and its CPU reference implement Godot-style opacity equations. Exponential uses `distanceAmount=1-exp(-density*distanceToEye)`. Depth uses `distanceAmount=pow(smoothstep(begin,resolvedEnd,distanceToEye),curve)*depthOpacity`; the render-time Begin is clamped to `min(authoredStart,resolvedEnd-0.001)` to preserve a finite transition when the rendering camera's far plane lies below Start, without changing the saved values. Distance is measured from the rendering camera, including a follow camera's offset from the character. Height uses `heightAmount=1-exp(min(0,(worldY-height)*heightDensity))`: positive density fills below Height and negative density fills above it. Every nonzero signed density contributes; there is no small-density dead zone. Final opacity is `max(distanceAmount,heightAmount)`, so the height term is not capped by Depth Max Opacity. This is independent artistic haze; it does not integrate atmospheric scattering along a light ray.

With `T=1-opacity`, opaque/masked and ordinary alpha surfaces use `T*radiance+(1-T)*linearFogColor*lightEnergy`; alpha particles apply that result before premultiplication and leave coverage unchanged. Additive particles attenuate their radiance by T without adding fog color. Light Energy changes only fog radiance, not opacity or other lighting. Fog applies per surface/particle in HDR before exposure/tone mapping. It does not affect visible sky, empty solid matte, grid or editor overlays, and it does not change picking/shadow passes, IBL or direct-light emission. Disabled Fog bypasses both distance and height contributions. Inspector groups Exposure, Tone mapping, Debanding and Glow under Post-processing. Fog has separate transactional fields, and hiding a mode/section finalizes its owned gesture.

### Point-light shadows

`PointShadowRenderer` is a concrete renderer-owned RAII owner for depth targets, face setup, uniforms, stable light slots, cache state and diagnostics. It uses six cube-direction perspective projections per point light, stored in a D32F 2D atlas. This follows [NVIDIA's omnidirectional shadow-map construction](https://developer.nvidia.com/gpugems/gpugems/part-ii-lighting-and-shadows/chapter-12-omnidirectional-shadow-mapping); filtering compares depths before averaging visibility, following [Reeves, Salesin and Cook's PCF paper](https://graphics.pixar.com/library/ShadowMaps/paper.pdf). Native perspective depth avoids a color-depth attachment or fragment-depth output. The far plane equals the authored light radius; near is `min(0.05 m, radius * 0.01)`. Receivers within near are unshadowed.

Each face has two guard texels per side and a slightly expanded projection that renders real overlap. A fixed 3×3 kernel uses linear depth-comparison sampling at legacy model sampler slot 8 or generated graph sampler slot 15 and stays within the guarded tile. Each tap corrects its comparison depth for the receiver plane, including the bilinear footprint, so a large floor does not shadow itself differently on downward and side-facing cube faces. The plane comes from world-position derivatives evaluated before material discard; authored normals remain the separate normal-bias direction. The full sixteen-light atlas has 12×8 tiles: 12336×8224 texels, approximately 387 MiB at the default 1024 interior resolution. Capacity grows lazily through 1/2/4/8/16 lights, preserving entity-ID assignments. Preferences allow 256/512/1024, default 1024; changing resolution invalidates the allocation. Atlas bytes include pending/retired lifetimes in aggregate GPU accounting. Capability/allocation failure reports a diagnostic and disables shadow sampling for that context instead of dropping selected lights or using stale slots.

Point lights append optional version-4 `castShadows` (default false), `shadowDepthBias` (0.005 m), and `shadowNormalBias` (one shadow texel). Bias values must be finite and nonnegative. Normal bias uses the world normal before normal mapping and the local light texel footprint; depth bias moves the receiver toward the light. These address the acne/peter-panning tradeoff described in [Microsoft's shadow-depth guidance](https://learn.microsoft.com/en-us/windows/win32/dxtecharts/common-techniques-to-improve-shadow-depth-maps). Model entities append cast/receive flags, both default true and noninherited. Versions 1–7 remain readable; existing scenes are only rewritten by explicit Save. Validation, equality, duplication, field-aware history and Play snapshots retain the fields; undo does not rewind unrelated runtime poses.

`EditorResources::prepareShadows` gathers the complete extracted world before Scene/Game receiver culling, conservatively rejects meshes outside each light range, and requests geometry LOD/texture demand once per relevant light. Immutable packets retain geometry/material/alpha-texture versions. Renderer face culling and LOD selection remain independent of camera visibility and Scene-only picking revisions. Opaque and masked meshes reproduce material alpha factors, vertex alpha, selected UVs, texture/sampler/cutoff and determinant-aware/double-sided winding. Collider and Character outlines, grid, placement previews and transparent particles are excluded.

Scene and Game share one active-world shadow owner and the same interpolated transforms. Static maps are cached by world/light identity, light position/radius, caster membership/transforms, selected geometry/alpha versions and shader generation. Dirty lights redraw all six faces before receivers; color, intensity, exposure and camera motion alone do not require redraw. Saved-scene thumbnails prepare shadows from the authored saved snapshot into a separate 256-pixel-per-face atlas, avoiding overwriting active-world data before Game executes. Material/model previews bind disabled shadow state. Shadow visibility multiplies only the relevant point-light BRDF contribution, preserving IBL, emissive, other lights, exposure and final encoding.

Natural numeric pass ordering is retained: procedural compute 0, active shadow faces 1–96, Scene 97–103, particle preview 104–110, reserved 111, picking/readback 112–113, thumbnail shadow faces 114–209, thumbnail rendering/readback 210–214, material preview 215–221, Game 222–227, main tools 228 and platform windows 229 upward. One framebuffer per atlas fits the pinned 128-framebuffer cap; partial view clears affect only their face rectangles. Shader compilation/preflight and atomic hot reload include the caster program and sampler contract. Diagnostics expose active/cached/rendered lights, face and draw counts, capacity, memory and failures. Directional/spot shadows, contact-hardening filtering, translucent/particle shadows, baked lighting and ray tracing remain separate slices.

Imported meshes and the editor grid do not generate physics geometry.

Built-in Boxes accept a per-entity `modelMaterial` AssetRef override; an empty value resolves to the protected PBR default. The geometry and model asset remain immutable and shared. Inspector exposes a compatible Surface material picker (Lit PBR or Unlit, all four blends), thumbnail/name or swatch, clear and material drag/drop. Extraction forwards `materialId` to Scene, Game and saved-scene thumbnails. Prepared packets are keyed by model plus material identity while geometry/GPU residency remains keyed by the model. Assignment is a separate history field, survives duplication and runtime pose updates, and persists as an optional version-4 field. Reference/deletion preparation discovers saved, live and historical overrides and applies compatible replacements/defaults in the existing project transaction. Imported model surface assignment remains milestone 2c.

Point lights define a world-space radius, independent of entity scale, defaulting to 20 m for creation and older scene files. Scene validation accepts finite values in [0.01,100000] m; Inspector, history, serialization and extraction retain it. Selected point lights draw a world-space influence sphere using that radius, independently of entity scale. A point-light-only selection omits the generic bounds box; its center marker and influence sphere remain. Generic selection/marker/range wires default to orange, with transform axis colors and authored collision colors retained. Renderer packs inverse squared radius in the unused point-color fourth component. Both PBR fragment shaders multiply existing inverse-square attenuation by `max(1-(distance/radius)^4,0)^2`, giving zero contribution and zero slope at the boundary. The shared shader expression is exercised by CPU tests and retains the linear HDR/final sRGB contract.

`PlayerController` follows Detour path corners to an accepted left-click or held-LMB world destination, produces horizontal velocity at the Character's speed, caps final-step travel and uses a 1 cm arrival tolerance. It turns upright -Z forward toward the next route corner with shortest-yaw exponential smoothing at response 14/s. Mouse motion with LMB released never changes yaw or the destination; idle retains facing. `PlaySession` resolves the captured click or held ray against live Jolt static colliders; any nearest hit expresses movement intent, including vertical walls and disconnected roofs. Navigation resolves that hit to a complete reachable route without changing physical walkable-slope or clearance limits. Visual-only meshes do not stop the ray, and the grid supplies no movement destination. CharacterMotor accepts per-tick facing commands; scripted C++ movement without one retains movement-facing fallback. WASD is not bound to player movement. The CPU `crimson-camera` target shares Camera projection/ray code with runtime and rendering. Basic step/slope handling and wall sliding use Jolt's virtual-character update. Jumping, character-to-character contacts, moving platforms, dynamic rigid bodies, mesh colliders, animation and combat remain later slices.

`crimson-navigation` privately links [Recast and Detour](https://github.com/recastnavigation/recastnavigation), using Recast to generate traversable polygons and Detour to find and straighten complete polygon corridors. `NavigationMesh` consumes only `PhysicsWorld::staticBoxes()` accepted by Jolt, including rotated/reflected boxes; each convex collider contributes solid spans so coincident floor/wall surfaces cannot create a walkable tunnel inside the box. Mesh clearance uses capsule height/radius plus Jolt padding, 45° slope and 0.3 m step limits, at 0.1 m horizontal cells and 0.05 m height cells. Geometry revision or capsule dimensions trigger rebuild/replanning; ordinary runtime poses and speed edits do not. The strict C++ `findPath` query still requires a complete route with at most 5 cm horizontal projection and retains the exact requested endpoint. Gameplay uses `findReachablePath`: it first tries that exact route, then searches the start-connected navigation surface for the nearest point to the requested hit and builds a complete Detour corridor to that point. Disconnected roofs and islands cannot become endpoints. Reachability labels are cached with the navigation mesh; fallback spatial queries use the existing Detour polygon BV tree. `PlaySession` keeps the original hit separately from the accepted endpoint. Arrival at an approach point leaves the original request dormant until a geometry revision permits replanning; exact arrival or input cancellation completes it. One derived mesh serves the controlled capsule, bounded to 4 million global horizontal cells and 16 million cumulative Box raster cells; invalid/oversized data reports a diagnostic and yields no route. Baking is synchronous in this MVP; tiled/streamed navigation, off-mesh links and crowd avoidance remain future work. Godot's current [dependency manifest](https://github.com/godotengine/godot/blob/master/thirdparty/README.md#recastnavigation) also uses Recast 1.6.0 for 3D baking, with its own runtime path-query and avoidance systems.

Camera entities define a vertical perspective FOV and clipping planes; their local -Z axis supplies viewing direction. The first camera becomes active; Make Active in Inspector changes the persistent scene camera ID. Add Camera starts at the selected entity's world position plus `(8,10,8)` and faces that entity, using the origin when nothing is selected. Its defaults are 45° vertical FOV and clipping planes of 0.1–2048 m, independently of the editor navigation camera. Follow stores an entity ID and world-space offset, evaluates position as target position plus offset, and retains ordinary camera orientation. Assigning/replacing/clearing follow preserves the view. Explicit camera position edits change its offset; dependent target edits and runtime movement reconcile the camera's local matrix before extraction so its children, gizmo and Game image agree. Parent translation is not added twice. Target rotation does not affect follow itself, while ordinary parent rotation still affects camera orientation. Target deletion preserves the current pose and clears follow; invalid reference/parent-follow cycles are rejected. Active-camera deletion clears activation without choosing another camera. Missing activation produces an explicit Game message.

Game is an ordinary dockable ImGui window using existing native multi-viewports; View → Game also opens it in Edit mode for immediate camera composition. It owns independent physical-pixel render targets and excludes the grid, generic entity markers, transform gizmos and picking. Its optional route and collision wire/fill are clipped Game-image overlays; the Collisions master switch gates all collision wire/fill. Camera projection explicitly uses `CameraFovAxis::Vertical`, while Quader/editor navigation retains `ShorterDimension`. Scene and Game extract/cull/prepare from their own camera and size, sharing resource snapshots and max per-frame texture demand. `advanceStreaming` rotates submitted leases and starts residency collection once per owner frame; both views accumulate residency and keep separate entity LOD hysteresis. Resource leases from every submission stay pinned through GPU completion. Orthographic projection remains outside this slice.

Play opens, expands and focuses Game, then automatically gives it gameplay input without a click. ImGui focus selects its tab; a detached Game also receives an SDL native-window focus request. Activation waits for that native owner to exist and gain keyboard focus. Clicking its image reacquires input after editing, and Escape releases it. The image has its own interactive item so holding a click cannot be mistaken for a window-move gesture or an unrelated widget capture. SDL events are filtered by originating native window and explicit Game image ownership, including when Scene and Game share the main native window. Text/widgets, modal interactions, clicking other panels, hiding/closing Game and focus loss clear held/pending input. Editor navigation and scene shortcuts cannot consume the same gesture as the player. Closing Game stops Play; Stop leaves Game open as an authored-camera preview.

## 5. Simulation and editor lifecycle

`PlaySession` uses 60 Hz fixed simulation with at most eight catch-up ticks per rendered frame; excess wall time is discarded and counted. Rendering is independent and interpolates character translation and shortest-path facing in a separate presentation scene, including its dependent camera and visual hierarchy. Physics and runtime particles advance once per tick, regardless of the number of views. These are initial engineering bounds, not production hardware-performance guarantees.

Game input captures one pending button-down point and ray using the camera, desktop image rectangle and physical target dimensions that produced the displayed image. Normalized image coordinates map to target pixels, including detached windows and framebuffer scaling. The UI acknowledges the native click without replacing it with later cursor coordinates or replaying it through a later follow-camera pose; a blocked-to-Game handoff retains the original press coordinates. Accepted clicks resolve before fixed stepping, so a render frame with no tick still retains the command. An owned image press also starts held-LMB steering: subsequent samples use the current cursor and latest displayed-camera projection, including when the cursor stays still while the follow camera moves. `PlaySession` samples held destinations at most 20 times per second and replans only after a 5 cm raw-hit change; unchanged accepted or rejected requests do not repeat Detour queries. Navigation geometry is still rebuilt only for collider/capsule changes. Button release retains the last accepted route. Leaving the image pauses retargeting; ray misses or queries with no reachable walking surface retain that route, while blocked hits choose a reachable approach point. A cancellation revision clears controller destinations even if focus is lost and reacquired in one frame. Escape, capture, focus loss, native-window migration, Stop, player replacement and authored player-pose changes clear stale movement. Held UI state alone cannot rearm a canceled gesture. No jump/action input is introduced in this slice. Suspend/focus handling clears pending input and accumulated wall time so resuming does not replay a catch-up burst.

The Character's saved Show Route option draws the remaining path plus three projected great circles as a 0.15 m wire sphere marking the latest clicked or held Collider hit, independently of the resolved walking endpoint. These overlays are clipped to the Game image and visible through geometry, rendered with the same camera/physical aspect as that frame. The hit is retained after release, arrival and input cancellation, including unreachable requests, and cleared on Stop or a missed click. The live hit and path create no scene entity, physics shape or saved state.

The character motor owns each collision-resolved actor pose; future dynamic bodies will own their physics poses. Rendering never writes interpolated values back into the world. Scene edits reconcile static bodies/characters at safe boundaries. An explicit character transform edit teleports its motor and clears velocity. An active transform gesture holds affected Character descendants and any Character on the edited entity's parent/follow dependency paths, so child or follow-camera gizmos retain stable baselines while unrelated simulation continues. Jolt types, handles and worker behavior remain behind `PhysicsWorld`, never in serialized scene data or ImGui code.

Play creates an independent transient `SceneDocument` from the authored scene, including unsaved edits. Scene, Outliner, Inspector and Game operate on that runtime document while Play is active; both views observe deliberate scene edits and simulation. The authored document retains its selection, dirty state, saved token and undo/redo history unchanged. Stop destroys runtime physics/particles/document state, discards all Play scene edits and returns to that original document. Runtime scene saving is blocked; New/Open scene, asset deletion and application exit defer their authored-document action until Play has stopped, then use the original document's existing dirty-state and transaction rules. No runtime poses enter scene files. Background resource preparation shares imported assets and GPU caches across Play/Stop. Independent material/effect documents retain their own authored save lifecycle. Document/world generation checks and interaction cancellation prevent pending picks/placements or selections from referring to the discarded world.

Custom game UI remains C++ authored. No UI framework, gameplay screen, animation system, or audio implementation is required to complete the first three milestones.

## 6. Build checks, user acceptance and future AI workflow

For documentation-only changes, verify consistency, status labels, and entry-point links. No application build is required.

For each implementation slice, use one incremental Release build after implementation owners finish, then focused CPU checks. Repeat or broaden checks only when failures or unresolved concerns justify it. Keep launching separate from building; preserve the user's project assets, assignments and dock layout. Report actual checks in the handoff and leave feature acceptance to the user.

Computer control, including mouse/keyboard automation and interaction with the user's applications, requires the user's permission. Noninteractive screenshots are allowed. Do not run routine native acceptance/capture suites or maintain `VERIFICATION.md` as a completion requirement; that file is historical evidence. The older capture scripts and smoke modes remain optional manual diagnostics.

`--project-root PATH` selects assets, persistence, layout and derived cache for isolated diagnostics. `--ibl-smoke` requires an explicit disposable project root and creates/assigns fixtures there; follow it with `--scenario ibl-reopen` in the same root to exercise reopening. Environment-only `ibl-*` scenarios cover metals/dielectrics, roughness, neutral/detail/zero-strength normals and extremes. These are targeted diagnostic modes, not the ordinary project launch path.

`Verify-Models.ps1` retains isolated `--model-smoke`, `model-reopen` and `model-sphere` scenarios for the older preview path. These mutating diagnostics reject the authored project root and are not the ordinary scene-authoring workflow.

## 7. Research references

The Khronos Simple Engine tutorial is the architecture reference for clear subsystem boundaries, explicit dependencies, RAII ownership and presentation separation; adapt those ideas to SDL3/bgfx.
