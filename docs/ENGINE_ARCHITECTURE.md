# Crimson Engine: first-person game engine architecture

This is the authoritative engineering guide for the native Crimson Engine first-person game engine. Consult the sections relevant to changes in rendering, assets, scene/runtime boundaries, input, or resource lifetime. Keep it current when an agreed implementation changes these contracts.

The foundation is the native renderer and editor in this project. Work progresses through small slices with a working application at each handoff. Keep implemented contracts distinct from planned interfaces; a planned design is not an implemented feature or authorization to start that slice.

## 1. Direction and implementation status

### Current game scope

Crimson now targets an offline single-player first-person action game. DUSK and Quake inform the requested movement and camera feel: WASD locomotion, direct mouse look, jumping, lateral camera tilt and smooth stair traversal. The eye camera remains authored in the editor, with runtime look and smoothing applied only to presentation. The former isometric ARPG player recipe and click-to-move input have been replaced; precise conversion of that built-in recipe preserves older scenes and leaves custom camera work intact.

The FPS controller and camera foundation is implemented. Actors, enemy navigation, collision layers, Tags, Attributes and Gameplay Effects remain reusable systems. Weapons, combat rules, inventory, loot, progression, audio and game UI need their own agreed slices; their design does not follow automatically from the former ARPG direction or from the DUSK/Quake references. Historical renderer checkpoints and D2R research describe the origin and measured limits of current rendering code, rather than prescribing the new game's camera or lighting style. Further work follows the requested first-person feature slice; deferred renderer, particle and scalability plans are not automatic game milestones.

### Composed actors and scene migration

Scene schema **v23** stores optional Actor/Visual Root, Movement, Character Controller, Navigation Agent, Player Input and other capabilities on ordinary entities. `MovementComponent` owns jump, acceleration, friction and movement-camera response; Player Input stores mouse preferences and input enablement. Older `motor` and Player Input movement values convert in memory; writers emit only `movement`. Light Rigs and Darkness Reveal are retired capabilities. SceneCamera stores lens values and Camera Follow stores target, world offset and translation-free affine basis. Add Player is a composed creation recipe with Movement, Controller, Player Input and a child eye camera, with no navigation dependency.

### Particle-system baseline and planned extensions

[Particle system pre-work](PARTICLE_SYSTEM_PREWORK.md) defines the CPU-first effect assets, authoring workflow, research rationale and staged implementation. Steps 1–4 are implemented with broader user acceptance pending: one emitter with Point/Cone/Sphere/Box shapes, seeded variation, timing/explosiveness, optional forces, World/Local simulation, scalar appearance curves/ranges, RGBA gradients, independent effect/material history, preview/scene instances, material-owned textured Alpha/Additive sprites and ordered transparency. The next particle milestone is Step 5, Layered effects and timeline; Steps 5–14 remain planned and retain working saved effects at each handoff. Particle collision remains separate from the implemented Play character/static-Collider Jolt world; particles currently pass through colliders. Native and imported glTF/GLB material authoring are available; per-instance imported material-slot assignment is implemented in milestone 2c with user acceptance pending.

`ParticleEffectDocument` owns authored definitions, transactions and dirty state; `AssetLibrary` publishes immutable committed effect versions and preserves a currently open document's authority over background file notifications. Bounded native metadata reads and atomic storage occur at document/catalog boundaries; material, texture and geometry preparation stays with the existing resource and GPU owners. `CpuParticleSystem` owns dense records and 60 Hz scheduling. `SceneParticles` keys runtime instances by `SceneDocument::documentGeneration()` plus persistent entity ID, so registry rebuilds and transform edits preserve playback. Copied presentation values cross into renderer-owned buffers/programs. Live particles, playback and preview cameras are never serialized. Valid intermediate drags update only isolated preview; commits/undo/redo publish revisions. Color/size/intensity/opacity/orientation/billboard mode apply on extraction, Gravity/Acceleration/Drag on the next tick, rate/enabled on subsequent scheduling, and shape/launch/lifetime variation at birth. Capacity replacement clears records but retains the clock, emission phase and playback state. Seed, pre-process time, simulation space, timing or explosiveness changes replay from zero with Pause/Stop retained; identity replacement or explicit Restart/Play Effect performs a full restart. Cancellation follows the same field policy. Saving preserves playback.

Effect-level `preprocessSeconds` (0–60 s, default zero for v1–v6) completes deterministic fixed-tick simulation synchronously during each actual restart, before any first presentation is published. It uses the initial affine transform, ordinary scheduling/explosiveness/forces and authored seed; it does not invent earlier emitter motion. Scene placement/opening, Play startup, isolated preview and explicit replay use the same owner. This replaces the across-frame preparation queue that caused a visible gap on initial Play and Stop/Play. Per-tick spawn/scheduler limits, capacity and the authored time bound remain; normal live catch-up remains bounded separately. Large pre-process values/capacities can increase startup cost, as in the inspected Godot CPU approach. Finishing exposes the current warmed tick rather than an empty or one-tick-late interpolation result. Pause retains its state; Stop clears, and Play prepares again. Time edits replay under the existing schedule-edit policy, whereas movement and ordinary appearance edits do not restart it. Stopped edits retain an empty stopped instance. A finite one shot may be drained by the requested time. The startup feature does not implement Step 5 timeline/seek, which keeps its separate bounded-replay plan.

Effect schema v9 stores Billboard mode, XYZ orientation and one typed emitter, shape/ranges/direction/spread/flatness, Continuous/One shot/Looping timing, Explosiveness from 0 to 1, named Gravity/Acceleration/Drag presence/enable settings and typed appearance tracks. Readers accept v1–v9; v1–v8 explicitly migrate to Enabled billboarding with zero XYZ orientation, while newly authored effects default to Disabled; v1–v4 retain constant size/intensity/color/opacity, rotation zero and empty inactive appearance data without changing timing or references. Files before v4 receive Flatness zero; v3 RandomCone retains exact spread, Fixed retains its inactive setting, and Outward resets its formerly ignored spread to zero to retain radial appearance. Only explicit Save upgrades files. Behavior order is engine-owned, so the UI provides Add behavior, enable and remove without a stage/reordering interface. Delay applies once before the first cycle. Explosiveness compresses each cycle's rate-based birth times by (1 - explosiveness), preserving Rate × Duration and fractional counts across cycles. Zero keeps prior rate scheduling; one emits the full cycle budget at its start. Continuous emission with a positive value repeats the stored Duration, which is then exposed in the UI. One shots drain before completion and remain replayable. Older burst records remain bounded compatibility data under the optional v8 legacyBursts field; new files contain none, and the editor has no burst authoring controls. An explicit Explosiveness edit replaces those events, folding their count into the rate budget atomically or rejecting unsupported values. Legacy order prepares on definition publication; sampling and shared forces resolve once per emitter tick. Independent random channels use effect seed, emitter identity and spawn ordinal. Newborns integrate only their remaining fraction of a tick. Limits/counters cover 4,096 scheduled births and 32 scheduling segments per tick in addition to existing capacity, aggregate scene, catch-up and render limits; clipped work never builds a backlog.

`PreparedParticleAppearance` owns bounded immutable scalar/gradient segment arrays prepared on definition publication; curves own no playback clocks or document pointers. Size and Rotation support Constant, Random Range and Curve with absolute values; retained overall intensity uses those modes as Brightness beside Color. Curves evaluate interpolated normalized particle age; random appearance lanes derive from seed/emitter/spawn identity independently of compaction and other properties. No additional per-particle appearance arrays are needed for these functions. Size tracks allow 0–10,000 m (zero hides presentation), intensity 0–100,000 and rotation ±360,000 degrees. Authored curves/gradients require 2–32 stable unique keys/stops, ordered finite ages within [0,1], minimum age spacing 0.0001 and Linear/Constant interpolation. First/last ages can move freely within those constraints; evaluation holds the first value before its age and the last value after its age. This relaxes validation within native v5 while preserving older 0/1 tracks without rewriting them on load. Inactive data remains validated and retained; active ranges need values. Gradient RGBA replaces effect tint/opacity rather than multiplying the hidden constants, stores/interpolates canonical linear HDR RGB and retains linear alpha; v1–v5 decode their SDR RGB exactly once on load. All appearance modes/values/keys/stops apply live on extraction with particles, clocks and Pause state intact.

Particle authoring uses four framed macro sections in order: **Emitter Update**, **Spawn**, **Update** and **Render**. Their children are unframed collapsible subsections. Emitter Update separates emitter-wide scheduling from individual particle initialization: Timing & emission groups Enabled, Playback, Delay, Rate, Explosiveness, conditional Duration and Capacity; Simulation groups simulation space, Pre-process and Seed. Spawn contains Shape, Initial velocity and Lifetime. Update contains Forces with the existing enable/remove/add behavior controls. Render keeps complete appearance properties together, including their Constant/Random Range/Curve modes; changing modes does not relocate a property between sections. This is an editor organization, not a change to simulation stages, serialization or effect evaluation. The ordinary document gesture helpers remain shared by every subsection.

Render authoring uses collapsible Material, Orientation, Color & opacity, Size and Rotation sections; Material and Orientation start open and the other appearance sections start collapsed. `HdrColorEditor` supplies a compact swatch, expandable linear channels and independent opacity without rewriting values on open. Brightness beside Color edits the preserved overall multiplier with its existing appearance modes. `ParticleAppearanceEditor` owns editor-only selection/view state, numeric editing and Add/Remove/Reset actions. Its ImPlot 1.0 curve plots support pan/zoom, Frame and double-click key creation. The Coollab RGBA gradient widget supplies stop interaction; Crimson's adapter retains authored identities, 2–32 bounds and valid age spacing. Any key/stop is removable when more than two remain, including edge keys. Plot navigation is transient; one authored gesture forms one effect-history transaction and Escape cancels it. Collapsing a property or losing its input ownership closes/cancels the active edit coherently. Renderer particle instance attributes occupy 80 bytes: position/size, linear RGBA, rotation radians/billboard mode, and world right/up axes. Disabled billboarding uses an orthonormal emitter frame plus live authored XYZ orientation; world particles retain the frame at birth, while local particles use the current interpolated presentation transform. Scale/shear/reflection extraction follows the shared affine rotation helper and preserves square world-meter size. Enabled retains the original camera-facing vertex path; FixedY constructs a world-Y-constrained facing frame with a finite pole fallback. The independent Rotation track spins within the selected plane. Normals/tangents use the same resulting frame for Lit, normal mapping and triplanar reconstruction. The material editor Sprite preview and protected material thumbnail explicitly remain camera-facing. Material/texture multiplication, global sorting and HDR composition retain their existing contracts. Selection/culling bounds expand by the maximum authored size's half-diagonal, and preview Frame uses conservative appearance extents, so growing or rotated sprites remain represented.

These widgets are editor dependencies, separate from particle schema and CPU evaluation. [ImPlot 1.0](https://github.com/epezent/implot/tree/v1.0) is supplied by the existing pinned vcpkg manifest and linked only where plot widgets are used. Its adapter releases only the current plot's unused LMB capture to its own drag handles/insertion; this handles ImGui 1.92 mouse ownership while retaining MMB/wheel navigation. [Coollab `imgui_gradient`](https://github.com/Coollab-Art/imgui_gradient/tree/6fcb6b814839e2adb6d41edc9b27e42a02114c83) is vendored under `third_party/imgui_gradient` at commit `6fcb6b814839e2adb6d41edc9b27e42a02114c83` under BSL-1.0, retaining its license and patch notes. Its Crimson patch uses linear RGB interpolation, straight linear alpha and left-held Constant interpolation rather than adopting different color/alpha semantics from a widget. `src/tools/` owns the adapter and gesture routing; no widget handles/types enter serialized effects or particle records. The authoring follow-up passed Release and the focused checks recorded in the particle pre-work checkpoint.

Initial velocity authoring presents Direction XYZ, Speed, Spread and Flatness together with an optional Outward checkbox; no Vector/Direction or Fixed/Random-spread mode selector is exposed. A pure display helper derives direction/speed from older vector velocity and effective zero spread from Fixed mode without changing the definition; intentional launch edits publish the corresponding direction/speed settings. Scalar speed supports 0–200,000 m/s, accommodating the norm of legacy vectors whose components each supported ±100,000 m/s. Spread is a 0–180 degree cone half-angle. Flatness 0–1 suppresses the cone's perpendicular component from full 3D spread toward a fan in the emitter-local axis/tangent plane; it does not flatten sprites. Outward applies the same spread/flatness around each sampled radial direction.

World-space births transform position and launch velocity by the full affine emitter matrix, then detach; forces use world axes. Local particles simulate forces and motion in emitter coordinates and transform through the current full affine hierarchy on extraction. During Play, fixed ticks use the current simulation transform for births; local rendering and bounds use the copied interpolated presentation transform, so particles attached to a moving actor follow its rendered pose without mutating the simulation world. No ECS pointer crosses that boundary. Sprite width/height stays in world meters in both modes. Scene transform edits preserve playback; choosing a different simulation space intentionally restarts as above. No transform decomposition or per-particle ECS entity is introduced.

The particle and material editors use `ImGuiWindowFlags_NoDocking` and clear only their own saved dock assignments. Dear ImGui multi-viewports are enabled through its SDL3 platform backend and renderer-owned `ImGuiBgfx` callbacks. Each secondary native window has one persistent DXGI swap chain owned by `PlatformSurface`; resize and collapse/expand use `ResizeBuffers` after releasing backbuffer references. Ordinary resizing never recreates that chain. The pinned bgfx native-window framebuffer recreation path is bypassed for secondary windows: bgfx renders ImGui into an ordinary framebuffer backed by a renderer-owned RGBA8 resource for the selected Direct3D 11 or Direct3D 12 backend, then `postFrame` performs the matching native copy to the backbuffer and presents after the application's single `bgfx::frame()`. This adds one GPU copy per presented secondary window, with no extra exposure or color encoding. View IDs retain the current natural numeric submission order from `RenderTypes.h` and the [canonical view map](../third_party/crimson-renderer/README.md#pass-and-resource-contracts), with 512 compiled view slots, main tools at 496, diagnostic readback at 503 and native platform views at 504–511. Glow compute reconstruction uses the reserved post-processing slots without renumbering presentation/readback boundaries. Game omits the editor grid; thumbnails omit Glow. Identity ordering preserves picking/thumbnail readback scheduling: the pinned D3D11 backend compares remapped blit-order keys with decoded numeric view IDs, so reordering the former UI pass around those readbacks is unsafe. Every offscreen image now completes before either main or platform UI samples it; all UI windows share the existing shaders/texture owners. The wrapper is imported only after its placeholder exists, and its external texture remains owned through queued framebuffer/wrapper destruction and any required native GPU fence; shutdown drains those retirements before releasing the renderer/context. Native operation failures log the stage, HRESULT and window details rather than routing through bgfx's fatal native-chain creation. This follows [Microsoft's resize contract](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/nf-dxgi-idxgiswapchain-resizebuffers) and [copy requirements](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-copyresource).

DX12 platform surfaces retain the selected device and the same direct command queue used by pinned bgfx, obtained through its device private interface. A terminal ImGui view switches away from all platform render targets before native copies. Native command lists transition the imported image from pixel-shader resource to copy source and the matching backbuffer from present to copy destination, then restore both states. Three bounded allocator/list slots retain their submitted resources behind queue fences; a busy ring defers presentation rather than reusing an in-flight allocator. A copy marker permits diagnostic readback, while a second marker queued after `Present` covers DXGI presentation work before slot reuse, resize or close releases backbuffers. A marker before `Present` does not provide that lifetime guarantee. Offscreen targets retire only after bgfx has released their wrappers and a queue fence covers remaining GPU work. `ImGuiBgfx::platformResidentBytes()` includes current, candidate and retired external targets, native swap-chain buffers and the tiny terminal target; DX12 target accounting uses allocation information. Driver-owned command metadata is outside those allocation totals.

A DX12 fence timeout retains the native chain and backbuffer references; it does not prove GPU completion. A failed queue signal latches the surface into a failed state, marks unfenced work and prevents further copies or allocator reuse. Bounded recovery attempts establish a later completion marker when possible. Exceptional shutdown quarantines native owners until confirmed device removal or both GPU completion and bgfx-wrapper retirement are proven; without that proof they remain retained for process lifetime. Quarantined owners clear callbacks that borrowed editor/test state, and their allocations remain included in aggregate platform memory accounting. Normal shutdown drains and releases all platform resources.

## 2. Engine boundaries and interfaces

Introduce these boundaries incrementally as their features land. Start with concrete classes and clear source ownership. Keep ordinary headers and `.cpp` files; a plugin framework, generic service locator, DLL ecosystem, or general job graph is not required.

### Concrete editor and math boundaries

`App` constructs owners, initializes the window/renderer, forwards events and drives frames. `ResourceRuntime` publishes worker results, acknowledges self-writes, dispatches watched changes and coordinates shader replacement before editor drawing. `EditorSession` selects the authored or transient Play document and owns document/session actions; `PlaySession` owns runtime simulation and interpolated presentation. `EditorResources` freezes coherent prepared model groups, and `AssetPreviews` schedules isolated thumbnails/readbacks/cache writes. `SceneEditor` coordinates editor commands; `SceneViewport` owns picking, gizmos, focus and navigation input arbitration. Engine public interfaces use `Vec2/3/4`, `Quat`, `Mat3/4`, `Ray` and `Aabb` from `src/math`. Serialization writes packed scalar arrays, while renderer and ImGuizmo adapters use explicit `.data()` boundaries. No GLM, bx, ImGui or GPU-specific math type becomes persistent scene data.

The construction grid keeps its geometric clip position unchanged and computes biased fragment depth from interpolated world position. The existing coplanar bias is applied after projection using the backend's depth convention. Viewport collision fills/wires and markers draw before orange selection bounds; transform handles compose last. Diagnostic/hidden/frame-limited launches do not replace the main window placement.

### Editor UI conventions

These rules apply to the scene editor, asset document editors and future editor panels. Use Dear ImGui's default theme, font and sizing; requested axis accents and selection/collision colors are semantic colors, not a custom theme.

- Document editors put **File** and **Edit** in the top menu bar. File owns Save, Save As and Close; Edit owns Undo/Redo with their existing shortcuts and current command labels. The scene's main menu may add New/Open and project actions in those same menus.

- Property groups use collapsible sections with concise names. Related controls stay beside their property; keep asset picker, thumbnail/name, clear and drag-and-drop behavior consistent. Material properties and particle properties use the same section conventions.
- Transform uses a label above one horizontal X/Y/Z row for each of Position, Rotation and Scale. Fields have thin axis-colored strips. The Scale row offers a proportion lock; editing retains the affine matrix contract and forms one undo operation.
- Panel bodies contain property labels/values, document state, actionable errors and necessary confirmation consequences. Do not put explanatory paragraphs, usage instructions, implementation notes or tutorials there. Use a short tooltip only when it helps operate a control; omit long explanations or document them here or in README.

### Keyboard actions and ownership

Current routing has explicit owners: SDL events reach ImGui, the editor session, Game input and editor navigation; Game filters its native window and image ownership, and document shortcuts respect active text/widgets. `input/KeyboardActions.h` supplies a small reusable binding value that distinguishes layout-aware `LogicalKey` from location-based `PhysicalKey`, normalizes left/right modifiers, ignores Caps/Num Lock for shortcuts, rejects additional modifiers and ignores repeat events. `editor/PlayShortcuts` uses logical P for Start and Shift+Escape for Stop. It checks text/popup ownership when the edge arrives and again after panels draw, drops stale edges on focus/window/keymap changes, and submits an explicit action at the next safe session boundary. P only starts; Shift+Escape stops even during a held Game click or ordinary scene drag. Text entry, popups and pending document actions retain ownership. Plain Escape retains its existing interaction-cancel/Game-release behavior.

The remaining scene/document shortcuts and navigation bindings still live in their existing owners. Rebinding configuration and UI are not implemented. Extend this foundation with stable action IDs and separate editor/game binding maps as those features are requested; input ownership must be resolved before an action reaches a document or controller. Store key identity and binding kind rather than a localized display label. Continuous movement reads held state; one-shot commands use press edges, and focus loss cancels both.

Follow [SDL's keyboard practices](https://wiki.libsdl.org/SDL3/BestKeyboardPractices): physical positions suit spatial movement controls, logical keys suit named editor commands, and Unicode/IME entry stays in SDL text-input events. A literal symbol such as `|` is a separate future binding policy: the base keycode in a key event may describe the unshifted key, so resolve the current layout and modifiers with [SDL_GetKeyFromScancode](https://wiki.libsdl.org/SDL3/SDL_GetKeyFromScancode) using `key_event=false`. Define how that binding consumes Shift/AltGr instead of confusing the resulting symbol with a physical position. Generate labels through [SDL_GetKeyName](https://wiki.libsdl.org/SDL3/SDL_GetKeyName) and refresh layout-dependent labels when the keymap changes. Dead-key and IME composition are text input, not ordinary button bindings.

### Dependencies and resource ownership

- The application constructs services and passes explicit dependencies. Controller and gameplay code do not call ImGui or bgfx.
- Scene components/history carry persistent typed asset references, not residency handles or GPU ownership.
- The rendering boundary owns GPU meshes, material textures, environment resources, and targets. The tools adapter owns its ImGui GPU resources under the same bgfx lifetime.
- Physics owns Jolt worlds, bodies, shapes, constraints, and body-to-entity mappings. Actor/controller code uses the engine-owned adapter.
- Background decoding returns completed CPU results through publication queues. It does not create GPU resources or modify the world directly.
- The main thread initially owns authoritative world mutation and application-side render submission. Jolt may execute internal jobs; its callbacks collect facts rather than changing EnTT.

`AssetRef<T>` holds a canonical UUID reference without keeping payloads resident. `resources/AssetId` wraps the pinned `stduuid` library; newly authored assets use system-generated UUIDs and immutable content-addressed model packages use name UUIDs. Legacy path-shaped IDs are accepted only by conversion readers. `assets/ContentStorage` resolves UUIDs through `.crimson/asset-locations.json`; a file location is never the authored identity. RAII `ResourceHandle<T>` expresses live interest; `ResourceSnapshot<T>` leases an immutable exact version. Publishing a replacement leaves old readers valid. Entries track source epoch, job generation, dependency fingerprint, published revision, state and diagnostics. Failed replacements retain the last working payload. Cache keys include identity/type/processing variant; image source decoding is shared while color/data/normal and mip policies remain distinct. CPU payload and GPU leases are separate; uploaded textures do not pin source pixels.

`ContentStorage::registerAssetPaths` validates a complete group under the storage mutex and publishes one index revision; empty or identical groups do not write. Quader commits collect all newly published package/material/image locations into that group instead of replacing the full index for every file. If scene publication fails, its transaction restores files and refreshes the cached location snapshot from the restored index. Windows atomic writes and rollback copies retain the old target and complete temporary while retrying transient access/sharing/lock failures for at most 500 ms, with bounded backoff. Read-only and directory targets fail immediately; permanent publication failures retain path-specific diagnostics and never fall back to deleting or truncating the working file.

Two CPU workers serve a bounded deduplicated priority queue. Selected/visible content and placement take priority over browser previews. Imports stage complete packages on workers, then publish files/catalog entries on the main thread. Workers also decode images, process Assimp/MikkTSpace geometry, generate mip/LOD caches, bake HDRI environments and compile shaders. Dynamic procedural environment filtering runs in renderer-owned GPU compute work, not these CPU jobs. Workers never call bgfx/ImGui or mutate documents. Completed jobs carry generations/epochs and exact dependencies; stale work is rejected. Model/material/texture groups become visible only when coherent candidates are prepared before drawing. Existing working groups survive failed replacements.

The default soft targets are 512 MiB CPU payload retention and 512 MiB streamable GPU asset retention. The latter covers model geometry, material textures and completed rendered thumbnails; it is not a total VRAM limit. Fixed shadow atlases, HDRI/procedural lighting resources and post-process targets retain explicit owners and separate byte accounting, but do not subtract from the streamable asset target: evicting material textures cannot reclaim those targets. Pending and leased retired asset allocations count toward their owners' accounting, and live leases remain valid above soft limits. Ordinary scene-resource idle retention is five seconds; pressure trims unpinned least-recently-used resources immediately. Rendered thumbnail images and raw texture thumbnails each have a bounded 64 MiB LRU working set and remain cached while they fit. Cards render at their displayed pixel size including DPI, capped at 512, so 128-pixel cards cost 64 KiB each. Completed PNGs can be reloaded after GPU eviction without rendering the model again. Model/image uploads are chunked toward 4 MiB and roughly 2 ms per frame; an individual backend call can exceed that time target. Browser requests only visible card resources. Editor/library metadata interests expire, and submitted draws/readbacks pin their actual CPU/GPU versions.

Shutdown stops watchers/new requests, cancels and joins workers/compiler processes, drains pending readbacks, releases editor/library/renderer/ImGui GPU owners before bgfx, then releases CPU caches and SDL. Async picks also carry document generation/request identity and the actual main-view resource signature; unrelated thumbnail changes do not invalidate them.

### Streaming and hot reload

Versioned texture-cache indices address independently readable, CRC-checked levels. Warm requests read required levels without full-source decoding. Cold requests first publish complete coarse physical textures whose longest edge is at most 64 pixels, then swap fully uploaded sharper allocations with valid mip tails. Color RGB filters in linear light; alpha/data stay linear; normal mips renormalize safely. All six glTF minification modes, magnification, wrapping and UV selection survive; non-mip variants are single level. Demand derives from projected bounds/UV use, shared consumers request the highest detail, selected models request native resolution, and invisible models do not refine. Picking and color rendering use identical resident alpha-cutout textures.

Material and node previews request Selected texture priority at their actual display footprint. Selected requests clear pressure inherited from ordinary scene demand. A coherent coarse texture packet can draw immediately while sharper levels arrive; stale source versions and incomplete graph programs retain the previous coherent packet. Reset View remains a camera operation and does not depend on mip refinement.

Static material node previews use the canonical image evaluator at authored resolution and reduce the completed result for visible 128-pixel inline images and the pinned 256-pixel flat view. Cached image Value outputs reuse the host's generated source and immutable CPU mip data; arbitrary static branches use the same evaluator without synchronous GPU readback. Flat Scalar/Vector2 images display numerical channels directly; Color/Color4 images use one sRGB color conversion and alpha/checker composition. The preview-only transfer has its own display-cache identity and never changes canonical source values. Pending previews own their decoded-input requests independently of the shared material cache, so a later warm Resize lookup cannot drop their last resource interest before publication. Those temporary requests end once the image job captures immutable source snapshots, or when the preview is superseded, fails, expires or closes. Source identity includes active upstream values and asset revisions, independently of full-material Output connectivity. A 150 ms edit debounce, two new requests per frame, eight pending display branches and a 256-entry bound constrain presentation work. Hidden entries expire after 500 ms; existing UI leases retain last-good images while replacements are pending. Contextual or animated outputs retain renderer previews. Double left click changes only the transient preview target; double clicking that node again restores the full material.

Steady frame preparation fingerprints already prepared graph packets (programs, uniforms, sampler state and texture versions), plus explicit material draw state, instead of serializing authored graph JSON for every model/view/shadow caster. Lowering computes an authored runtime-expression fingerprint once, including disconnected node-preview branches, so Time/Panner edits replace runtime packets even when their initial uniforms and shader topology match. Material compatibility and graph UV requirements are cached against weak immutable source versions; a replacement version is validated afresh. Live texture residency, source coherence, Time/Panner evaluation and shader publication continue through the existing preparation paths.

Generated shader jobs use per-stage source identities. Coverage branches have their own deterministic traversal and occupy the first shared parameter/sampler slots, independently of surface traversal. Picking emits only the relevant opacity expression; shadow passes emit Mask coverage only. Surface-only topology changes therefore retain compatible coverage binaries. Cache hydration can reuse individual preflighted pass pairs, while GPU publication still requires a complete coherent five-pass generation. Material and node-preview owners share source-epoch cache hashing and dependency discovery. Genuine runtime misses use an explicitly keyed interactive compilation tier before full optimization in the background; build preparation always produces optimized shaders. Both tiers retain the same source/compiler/ABI validation and last-good publication contracts.

Startup material discovery skips model metadata work when a package explicitly references shared native materials already covered by the material catalog. Implicit imported materials and references to the package's own imported sidecars retain migration. Only newly created/discovered sidecars dirty the material catalog; resource publication batches its refresh and acknowledges actual authored writes. Existing sidecars and unrelated authored materials are not reread for each unchanged model publication. External file changes retain the normal refresh path.

#### Large-scene resource and shadow direction

The deferred [large-scene performance implementation guide](LARGE_SCENE_PERFORMANCE_GUIDE.md) preserves source findings, current integration points, staged algorithms, correctness requirements and the required before/after measurement procedure. It is a future implementation reference. Select work from measured first-person workloads and the requested slice; these proposals neither establish implemented features nor select the next game milestone.

The 512 MiB asset target is a conservative implementation default, not the intended world-size limit or a validated high-end desktop budget. Clustered Forward+ removes the old sixteen-point-light direct-light ceiling; its 4,096-source capacity, cluster storage/assignment cost, dense-overlap shading, uniform-resolution shadow allocations and uncompressed RGBA8 texture uploads remain scaling constraints. Removing fixed targets from asset-cache trimming repairs a residency bug; it does not establish large-world readiness. Cluster data and upload buffers have a separate renderer owner/accounting path rather than consuming the streamable-asset retention target.

The next scalability work should follow measured frame and memory costs, with these contracts:

- Select active positional shadow lights from the union of Scene/Game camera demand before preparing casters. Keep off-camera geometry that can shadow visible receivers. Persistent world bounds and spatial light/caster relationships must avoid a full scene scan for each light as the world grows.
- Use bounded physical shadow storage, stable tile ownership, projected-size resolution and hysteresis. Keep the quality setting as a maximum, reclaim invisible tiles under pressure, and pack directional cascades without reserving mostly empty full-width rows. Preserve the current six-face projection/filtering initially; changing to dual paraboloids is a separate image-quality decision.
- Cache immutable caster/resource packets and dirty affected lights from scene/resource changes. A static shadow-cache hit should avoid rebuilding material bindings and draw matrices. Moving crowds subsequently need separate static/dynamic shadow work instead of redrawing the whole static level for every actor movement.
- Derive configurable asset targets from an actual adapter/OS budget with headroom for fixed render targets, upload overlap, external applications and integrated GPUs. Track wanted, resident, pending and leased retired allocations separately. Preserve drawable coarse resources under pressure and prevent oscillating promotion/eviction; increasing a constant is not sufficient.
- Add role-correct GPU block-compressed mip caches (with supported-format fallbacks), shared materials/geometry, and spatial world streaming. File compression alone does not reduce GPU texture memory. Perform decoding, compression, cache building and shader compilation off the frame submission thread, and bound publication/upload work.

Reference audit: the supplied Godot 4.7-beta checkout explicitly disables ordinary imported-texture streaming in `editor/import/resource_importer_texture.cpp` and creates full imported image/mip allocations in `scene/resources/compressed_texture.cpp` and `servers/rendering/renderer_rd/storage_rd/texture_storage.cpp`. Each performance slice needs a reproducible representative workload: cold and warm import, static and freely rotating eye cameras, first-person traversal, moving shadow casters, Scene plus Game, and browser scrolling. Report CPU preparation/submission, GPU frame time, upper-percentile frame time, cache activity and allocation peaks with image/material correctness. The small Quader room is a regression case, not proof of representative first-person level or enemy-workload performance. These items are target work, not implemented systems.

For static primitives, meshoptimizer 1.1 creates up to three compact attribute-aware LODs at half, quarter and eighth source triangle counts, capped at 1% source-relative error. LOD0 stays exact. Material boundaries, seams, normals, colors and tangent handedness constrain simplification; unsafe/useless reductions stop. Metadata/hierarchy/material references/bounds load independently from CRC-checked vertex/index payloads. Skin/morph primitives retain only their original level until deformation-aware simplification is implemented. Complete candidates publish after chunked uploads, preserving previous buffers on failure.

Distinct managed model IDs may share the same content-addressed geometry cache. Shader dependency/recipe indexes use the same idempotent publisher. Readers close their file handles after reading bytes/JSON, before CPU validation or dependency processing, so shared caches do not fail an unnecessary Windows replacement while another resource is preparing them. Publication diagnostics identify the destination path.

Texture/model/material/environment/scene candidates preserve working resources on invalid changes or unexpected disappearance. Shader workers use pinned shaderc with discovered include dependencies and a versioned content cache. ResourceManager shader wrappers use file-state guards around the loader; `compileShader` independently owns content-based identity and before/after compilation validation, including compiler contents and build/recipe contracts. File states do not replace content identity. A compiler-reported dependency subset needs no second invocation; newly discovered inputs require validation against the expanded set. Structure, reflection/uniform/sampler/layout/stage contracts and private SM5/DXBC bytecode preflight shared by DX11 and DX12 precede GPU creation. Renderer Steps 1–3 are implemented foundations, with broader visual acceptance still pending. Later renderer work follows its requested slice and does not automatically precede further first-person gameplay work. Preserve linear HDR, one final sRGB encode and the current visuals when changing infrastructure. Describe artistic behavior as Crimson policy; screenshots alone cannot establish D2R's light types, caster masks or shadow composition.

Use a right-handed, Y-up world with meters as the distance unit. Camera, picking, physics, scene transforms, and imports use consistent conventions; backend conversions belong at their adapters.

The shared direct-light BRDF uses GGX with `alpha = perceptualRoughness * perceptualRoughness`, height-correlated Smith visibility and Schlick Fresnel. Practical Turquin compensation uses the existing scale/bias DFG lookup: `E = clamp(A+B, 1e-5, 1)`, `W = 1 + clamp(F0,0,1)*(1/E-1)` and compensated directional response `R = (F0*A + F90*B)*W`. Direct specular uses W; Lambert diffuse uses the complementary directional budget `D = (1-clamp(R,0,1))*(1-metallic)*base`. The visibility term already contains the Cook-Torrance denominator; do not divide by it again. This is an energy-preserving directional approximation, not a full reciprocal multiple-scattering BSDF.

Visible triangles with smooth shading normals behind the view direction still receive direct light when `N·L` is positive; clamp signed `N·V` for the GGX denominator instead of discarding their lighting. Direct lighting, environment diffuse and SSGI donor/receiver response reuse one per-fragment LightingEnergy evaluation. Raw view-angle Schlick Fresnel must not erase rough diffuse illumination at grazing views. The preview sphere includes the same implementation as embedded models and generated mesh/sprite materials. Glass transmission and its fog correction consume the same compensated R before Beer absorption; SSR replaces the matching compensated environment contribution. Environment reflection and SSR share roughness/NoV-dependent specular AO and approximate soft geometric-horizon attenuation from the actual triangle normal.

Environment **Specular AA** defaults off. Its optional JSON boolean follows normal Environment history/Save behavior without a scene-version change or writes on load. Enabled filtering adds bounded final-normal derivative variance in squared GGX-alpha space; fixed variance .15 and threshold .2 travel in `u_pbrSettings`. Normal/roughness derivatives precede cutout discard. Reflection GGX/DFG/SSR keep their `0.045` numerical floor after filtering; the transmission cone uses raw filtered roughness, preserving clear glass at authored zero. Independent previews expose their own toggles and saved-scene thumbnail signatures include the setting. No pass, texture, sampler or temporal history is added by AA.

Point Radius is finite influence range. Source Radius zero retains the GGX/Smith/Schlick response with common energy compensation; positive values broaden that point's GGX specular response using squared angular emitter size and enable contact-hardening PCSS in its shadow query. Lambert diffuse orientation, influence radius and cached shadow projection stay independent. Specular Scale independently multiplies the point's specular contribution. The extension is shared by fallback/generated mesh and lit-sprite paths. Narrow reflected HDR highlights can contribute to Glow as well as emission.

The renderer retains the complete frame through its queued-frame lease retirement; the caller may release or advance its source data immediately. Independently authored environments in those two requests are outside this shared-world contract. Independent material/particle previews and thumbnails remain immediate isolated requests, using the same validated per-view pass contract. The plan validates this recipe; bgfx retains backend synchronization and concrete owners retain allocation/retirement. It is not a barrier compiler, general scheduler or transient-resource allocator.

Previous SSGI capture/history and current outputs have distinct logical versions, including ping-pong history/metadata and trace/filter reuse. ### Clustered Forward+ local lighting

The [Forward+ checkpoint](FORWARD_PLUS_CHECKPOINT.md) preserves correctness coverage, synthetic and frozen-room measurements, artifact identities and reproduction commands for this implementation.

`ClusteredLightingGpu` owns camera-local light records, upload storage, a combined RGBA32F BRDF/data atlas, uniforms and retired GPU allocations. GPU compute (`cs_cluster_lights.sc`) conservatively intersects each point-light sphere with perspective cells built from initially 32-pixel tiles and 24 logarithmic positive-view-depth slices. Tile size doubles until the grid fits 262,144 cells; for example, a 5120×2880 viewport uses 64-pixel tiles. This reduces culling precision while retaining light coverage. Cells use a top-left pixel origin and index `(depth * tilesY + y) * tilesX + x`. Near/far and FOV match the camera projection. Light centers outside the view, near-plane crossings and a camera inside a light sphere remain conservative. No opaque depth reduction is used, so the same cell assignment supports transparent meshes and lit particles.

Active valid sources compact into GPU light records, each retaining its original source index and selected shadow index. Each cluster stores a bitset over those compact records, using one bit per record and enough words for the active count. There is no independent sixteen-light truncation per cluster. Capacity is 4,096 source point lights and 262,144 clusters per camera, additionally constrained by adapter texture dimensions and RGBA32F compute-write support. Heavy overlap still evaluates every influencing light and increases shading cost. Assignment cost also depends on cluster count and uploaded lights; this first slice does not add a persistent CPU world/light spatial index. Capability or storage failures report a diagnostic rather than publishing a truncated cluster list.

Generated mesh/sprite shaders read `clustered_lighting.sh` through the existing BRDF binding at stage 14; the atlas stores the unchanged BRDF lookup, point records and cluster masks together. Material texture stages 0–11, environment cubes 12–13 and the shadow comparison binding 15 retain their capacity. Fallback material paths consume the same clustered lighting contract. This does not add material samplers or change the linear HDR BRDF, opacity, fog, exposure, tone mapping or final sRGB encoding. Independent render targets/cameras own independent cluster data so Scene, Game, previews and thumbnails cannot overwrite one another's queued inputs. Exact light/camera/configuration snapshots reuse unchanged GPU records and masks; color/intensity/shadow metadata edits update records without rebuilding masks while the influencing spheres and compact order remain equivalent. GPU owners retire replacements and release their resources before bgfx shutdown.

`ClusteredLighting` is a pure CPU conservative reference with reusable compact lists and explicit capacity failures. It is an oracle/test helper, not the production frame assignment path. A diagnostic all-lights reference path evaluates the same source records without cluster culling for hidden image comparisons; it is not an editor setting. Focused tests cover dense source counts above sixteen, sphere/view intersections, camera variations, source-to-shadow mapping and visual equivalence against that reference. Source records carry independent direct-receiver roles; it does not prune the shared lists using opaque depth because transparent receivers must retain their light coverage.

Local-light records contain six `Vec4` texels: position/intensity, linear color/inverse squared range, view-space influence sphere, shadow index/Source Radius/direct receiver bits/reserved zero, near-falloff radius squared/Specular Scale/range exponent/edge softness, and row five containing attenuation exponent / (GI Energy - 1) / 0 / 0. Every point culls around its actual source with finite Radius .01-100,000 m; no shifted fill footprint or enlarged shadow range remains. `point_light_record.sh` defines stride; reflected `u_clusterRecordLayoutV6` guards compute and fragment indexing, including GI/AO. Older five-texel response meanings fail preflight. Record uploads reserve whole atlas rows before masks. Response-only edits update records without rebuilding equivalent culling spheres/masks. The sixth texel adds 64 KiB at 4,096 lights per record buffer/atlas region, plus row alignment; no float quantization or packed-role coupling is used for attenuation. Source-size and attenuation controls add no sampler, pass or shadow map.

### Color and texture meaning

Particle colors and gradient stops use canonical linear HDR RGB in effect v6 and later (current writer v9). The shared picker presents an sRGB swatch and expandable linear channels, with opacity independent; stored HDR values remain unchanged until explicitly edited. Readers validate v1–v5 SDR bounds and decode once on load, retaining all earlier appearance and overall-intensity functions. Ordinary color editing is inside Color; the earlier constant/range/curve intensity is retained beside it as Brightness. Values are bounded to RGB 1,000,000 and the preserved multiplier to 100,000; prepared presentation accepts their finite product. Gradient sampling interpolates linear RGB/alpha directly. Changes retain live particles and clocks.

`EnvironmentSettings::glow` owns the optional full-scene HDR Glow effect, exposed under Environment Post-processing and independent preview Environment menus. It includes visible emission, sun/sky and reflected/direct highlights. Controls are Enabled, Intensity, Blend Mode, Spread, Highlight Threshold, Tint, seven independent level gains, Saturation, Threshold Softness, Anamorphic Stretch and Quality. New settings default disabled.

Glow exposes Intensity (`strength`, 0...10), Spread (`radius`, 0...8), Highlight Threshold (0...100000 exposed HDR units), Tint (authored sRGB), seven independent 0...1 level gains and Blend Mode (Additive/Screen/Soft Light/Replace/Mix, default Additive). Mix shows its retained 0...1 amount, default .5. Advanced contains Saturation (0...2), Threshold Softness (0...1), Anamorphic Stretch (-1...1, vertical to horizontal) and Low/High Quality, default High. Default Intensity is .1; Spread and Threshold are 1 and Softness .5.

Glow Additive adds exposed HDR radiance before tone mapping, Mix crossfades the exposed scene and Glow in HDR, and Replace selects Glow in HDR. Screen and Soft Light apply bounded blend equations to separately tone-mapped Glow and linear display color after exposure-independent editor-matte composition, preserving scene values above one separately; they do not blend sRGB-encoded values. Blend mode and the retained Mix value add no pass/resource or material ABI change. Serializer names are exactly `Additive`, `Screen`, `SoftLight`, `Replace` and `Mix`; missing values use Additive and .5, with strict enum/type/finite/range checks.

`GlowGpu` owns one multiscale FP32 pyramid per view and reads the original scene HDR target. It includes visible emission, sun/sky, reflections and directly lit highlights; there is no separate Bloom effect or emission attachment. Spread and Anamorphic Stretch select the filtered base extent rather than spacing sparse reconstruction taps farther apart. At Spread 1 and zero stretch, High starts half resolution and Low quarter. Lower Spread can raise either dimension up to full resolution, so quality, memory and GPU cost depend on the actual extent.

Source reduction uses at most five progressive prefilters, each at most 2:1 per axis, with a normalized thirteen-position filter and explicit FP32 bilinear reads. `fog.sh` and its CPU reference implement Godot-style opacity equations. Exponential uses `distanceAmount=1-exp(-density*distanceToEye)`. This is independent artistic haze; it does not integrate atmospheric scattering along a light ray.

Additive particles attenuate their radiance by T without adding fog color. Light Energy changes only fog radiance, not opacity or other lighting. Fog applies per surface/particle in HDR before exposure/tone mapping. The sky/empty background evaluates the same transmittance at a radial proxy distance equal to the camera far plane, with endpoint world height `eyeY + rayY * far`; Sky Affect scales the resulting opacity. Zero Exponential Density and zero Height Density return exact clear coverage, and positive densities blend continuously. Sky Affect 0 preserves the background while finite surfaces retain fog. Godot's source supplies the Sky Affect, Aerial Perspective and Sun Scatter color model; its density-independent sky opacity is deliberately replaced by density-aware transmission here. Aerial Perspective blends Color × Light Energy toward view-ray sky radiance; Sun Scatter adds enabled directional-light color/intensity times `pi * pow(max(dot(viewRay,towardSun),0),8)`. Both also affect finite surface/particle fog, reusing the existing specular environment sampler without consuming a material texture slot. Additive draws retain attenuation only. `fs_sky` draws premultiplied fog over hidden matte coverage, or mixes it into a visible sky, in Background before geometry even with no visible sky or valid environment cube; it writes neutral GI donor outputs. Fog remains independent of environment illumination Enabled. Material exclusions and transparent coverage retain their existing composition over this background. Disabled fog schedules no extra background draw and restores the selected sky or exposure-independent solid matte. Grid and editor overlays retain their later display-space composition. Fog does not change picking/shadow passes, IBL or direct-light emission. Inspector groups Exposure, Tone mapping, Debanding and Glow under Post-processing. Fog has separate transactional fields, and hiding a mode/section finalizes its owned gesture.

`MaterialOutputNode::receiveFog` is a persisted material setting exposed as **Material → Receive Fog**. The optional graph field defaults true for older content; legacy conversion and model metadata retain the same default. It contributes to value and prepared-packet signatures without changing shader topology. Canonical `ModelMaterial`, immutable graph packets and particle material packets carry the flag. Each mesh/sprite draw binds fog parameters with the effective enable bit `environment.fog.enabled && material.receiveFog`; the shared view parameters remain immutable, and the next draw binds its own policy. Generated and fallback Lit/Unlit paths share this behavior across all blend modes, Scene/Game and scene thumbnails. No extra shader variant, texture binding, framebuffer or render pass is required. Fog exclusion leaves opacity, depth tests/writes, picking and shadow casting unchanged. The Material Editor's existing independent preview environment remains separate from scene fog. A black cutaway surface uses an opaque Unlit black material with fog off; Glow remains a later independent effect.

### Screen-space reflections

`EnvironmentSettings::ssr` owns opt-in current-frame SSR independently of diffuse GI/AO and Environment Lighting. `SsrSettings` retains disabled tuning: Strength 1, Medium quality, Max Distance 50 m, Depth Tolerance .05 m, Max Roughness .6 and Ray Bias .002 m. The Environment Inspector presents these under Reflections; shared scene/environment serialization validates types and physical ranges, defaults missing fields off and retains schema v23 without dirtying or rewriting on load. Thumbnail fingerprints include only effective SSR tuning. Source ownership is canonical; Engine supplies authoring and GPU acceptance fixtures.

Each active view owns an unfogged RGBA32F opaque radiance pyramid and an RG32F positive linear-view-depth min/max pyramid, plus detached scratch for lower mip reductions. The winning opaque fragment stores positive linear view depth in source mip-zero alpha; sky stores zero. Depth initialization reads that alpha directly, avoiding device-depth quantization, and the first color reduction converts it to coverage. SSR alone allocates no readable device-depth target and records no geometry prepass; combined glass retains an early readable-depth prepass for transmission, while GI/AO keep their existing depth contract. Conservative overlapping source footprints retain odd-size edge texels and thin donors. The immutable donor source precedes opaque SSR correction and excludes transparent/additive appearance, SSR output, fog, Glow, tone mapping, matte and tools. Refraction captures the completed opaque result afterward. Scene/Game, previews and thumbnail owners never exchange inputs. Disabled or zero-strength SSR records no effect work and releases its allocations through ordinary retirement. At 1920×1080, the two pyramids and scratch use about 79 MiB per active view, excluding optional GI/AO/refraction readable-depth storage.

Optional reflection-only mesh/sprite variants evaluate each receiver's exact graph normal, roughness, coverage and dielectric/conductor response, including DX12 Height; DX11 and sprites retain their ordinary geometry. They bind graph0–11, source12, prefiltered environment13, depth hierarchy14 and the existing BRDF/AO atlas15. Opaque/cutout corrections depth-test against their already-written surface; ordinary Alpha/refraction corrections remain adjacent to the surface in the existing stable transparent queue. Unlit, Additive, node previews and non-Lit diagnostics bypass SSR. This retains twelve material textures without a new authoring pin or material flag. Lit opaque/ordinary Alpha families publish seven variants, glass nine, Unlit/Additive five and node previews one.

Full-resolution deterministic rays traverse min/max Hi-Z with Low/Medium/High budgets of 64/128/256 iterations per ray and four refinement steps. Rough materials use 1/4/12 visible-GGX angular samples; roughness below .1 uses one mirror ray. Misses remain in the sample denominator, and roughness confidence fades from half the maximum to its cutoff. Projection and cell crossing retain perspective-correct depth and directional half-open cell ownership. Level-zero validation accepts only the interval behind the visible surface; offscreen, self-hit, clear-depth or exhausted rays retain environment fallback. Residual per-ray footprints sample radiance and opaque coverage from the HDR pyramid, allowing several donor surfaces within one rough footprint. The removed whole-tile donor-plane predicate could erase stairs and even continuous ground because conservative odd-size depth support differs from geometric mip-cell corners. Donor derivatives prefer the closest-depth usable neighbor in each axis and estimate only the isotropic footprint, with at most fourfold grazing stretch and incidence one when a plane is unavailable; inferred backfaces never override an already validated depth hit. Requested footprints retain their size for continuous screen-edge confidence while sampled LOD clamps to the available pyramid. The signed RGB correction is coverage × confidence × receiver fog transmittance × matching specular BRDF/AO × (screen radiance − baseline environment radiance). Environment rotation, intensity, roughness LOD and index-matched Fresnel behavior agree with the surface. Alpha and RGB matte throughput remain unchanged. HDR saturation is deferred until composition completes so a dark screen hit can remove a bright environment reflection without losing direct or transmitted energy.

SSR uses the current prepared geometry and has no temporal history or stochastic ray jitter. It does not recover hidden surfaces, offscreen geometry, arbitrary transparent donors, multiple reflection bounces or planar reflections. Current shader generator v36/material ABI35 adds the fifth unfogged source MRT; the former emission-only Glow attachment remains removed. `ssr_core`, environment/scene tests and focused DX12/DX11 `ssr_render_*` fixtures cover the new contract.

The perspective-correct depth interpolation follows the construction described by McGuire and Mara in [Efficient GPU Screen-Space Ray Tracing](https://jcgt.org/published/0003/04/04/paper.pdf); Crimson traverses its min/max hierarchy rather than adopting that paper's complete DDA loop. Rough reflection directions independently implement the visible-normal mathematics in Heitz's [Sampling the GGX Distribution of Visible Normals](https://jcgt.org/published/0007/04/01/paper.pdf). The local Unreal 5.8 raster SSR sources informed the one-sided hit interval, angular roughness sampling and roughness confidence fade; its temporal reconstruction is not part of this implementation. The [SSR and PBR review](SSR_AND_PBR_REVIEW.md) records the corrected rough-hit regression, remaining estimator/energy/filtering limitations and a research-backed sequence toward spatiotemporal reflection reconstruction; proposed stages are not implemented features.

### Glass and screen-space refraction

`MaterialOutputNode::refraction` enables optional dielectric transmission only for Lit/Translucent, through the shared `materialRefractionActive` capability. It defaults off; Transmission defaults 1, IOR 1.5, Thickness 0 world-space meters, Attenuation Color linear white and Attenuation Distance 1 positive world-space meter. Optical defaults are finite and bounded to their physical authoring domains; IOR and thickness have no artificial upper ceiling. Graph schema 13 appends their pins without renumbering existing semantics and remains inside native material v6. Readers accept schemas 1–13 with disabled optical defaults for older content, and load never rewrites files. Opacity remains coverage. IOR owns dielectric reflection while active, retaining the dormant Specular value/link; all disabled optical branches remain authored dependencies but consume no active shader/streaming work. Changes, cancellation, Save and undo/redo use ordinary MaterialDocument transactions.

Transmission replaces the corresponding dielectric diffuse contribution and is suppressed by Metallic. The surface GGX response uses IOR-derived dielectric F0; transmitted throughput combines the complement of the shared compensated directional DFG reflection budget, Transmission, nonmetal fraction and Beer–Lambert absorption. Authored Thickness is independent of object scale and estimates travel through a parallel slab; the shader projects its Snell-refracted exit position rather than tracing the actual far mesh surface or a background intersection. Roughness selects deterministic HDR color-pyramid filtering with a distance-dependent footprint; it adds no temporal history. IOR exactly 1 removes interface reflection, macroscopic distortion and rough-transmission blur while retaining volume absorption. Thickness 0 removes macroscopic displacement and absorption.

Each enabled mesh subdraw or particle sprite occupies one adjacent transmission/surface pair in the shared sorted transparent queue. Transmission reads the immutable opaque-plus-sky HDR mip chain with existing readable opaque depth, using material samplers 0–11, scene color 12, prefiltered environment 13, depth 14 and the BRDF atlas 15. The second draw restores ordinary lighting/shadow bindings and adds reflected/remaining diffuse/emission RGB without changing destination alpha. Foreground rejection and bounded screen-edge fallback avoid using invalid refracted scene samples. For coverage `q`, throughput `K`, fogged background `B` and local surface response `S`, transmission supplies `q*K*B` with premultiplied OVER; the additive surface supplies `q*(fog(S)-K*fog(0))`. Both fog evaluations use the ordinary affine surface fog, preserving the foreground fog contribution without applying it twice to captured background. Receive Fog off reduces the local surface term to `q*S`. A separate view-local RGBA16F target carries RGB transmission of the uncovered editor matte, initialized from `1 - snapshot.alpha`; presentation applies it outside scene exposure and tone mapping. It adds about 15.8 MiB per 1080p view, bringing snapshot, filtering scratch and matte storage to about 68.5 MiB before optional readable depth, while retaining two geometry draws and twelve material texture slots.

Scene, Game, material/particle previews and thumbnails use the same capability on DX12 and DX11. Opaque snapshot/mips and readable depth are scheduled only when an admitted material requires them, with independent view-owned resources and explicit render-plan dependencies. Transparent objects preserve opaque auxiliary GI data and remain excluded from GI donors/receiver histories. The snapshot excludes transparent materials, so glass does not refract itself, other transparent objects, hidden scene surfaces or offscreen indoor geometry. Existing transparent sorting limits remain. This slice adds no nested-media/camera-inside model, measured back-face thickness, colored shadows, caustics, dispersion, ray tracing or temporal antialiasing.

### Point-light shadows

`PointShadowRenderer` is a concrete renderer-owned RAII owner for depth targets, face setup, uniforms, stable light slots, cache state and diagnostics. It uses six cube-direction perspective projections per point light, stored in a D32F 2D atlas. This follows [NVIDIA's omnidirectional shadow-map construction](https://developer.nvidia.com/gpugems/gpugems/part-ii-lighting-and-shadows/chapter-12-omnidirectional-shadow-mapping); filtering compares depths before averaging visibility, following [Reeves, Salesin and Cook's PCF paper](https://graphics.pixar.com/library/ShadowMaps/paper.pdf). Native perspective depth avoids a color-depth attachment or fragment-depth output. The far plane equals the authored light radius; near is `min(0.05 m, radius * 0.01)`. Receivers within near are unshadowed.

`ShadowLightSelection` separates sixteen resident point maps from the four-update frame budget and 4,096-light Forward+ source capacity. Eligible lights have enabled shadows, finite positions and positive finite radius/intensity. A frozen world priority origin selects the sixteen best squared-distance/radius-squared influences, with persistent-light-ID ties. The frozen origin is the visible Game camera's eye, or the Scene camera's eye when Game has no render request. Player mesh presence and the unrelated editor camera target cannot redirect Game admission. Legacy isolated callers without a finite origin preserve source-order selection. Zero entity IDs in renderer fixtures retain source-index-derived fallback identities. Caster preparation and surface lookup use the same source-to-selected-index mapping; a source light at index 63 can occupy selected shadow index 0. The shadow owner then maps selected indices to stable atlas slots by light identity. Unadmitted lights retain direct illumination. Admission hysteresis, budgeted per-light resolution and more resident maps remain future work.

Each face has two guard texels per side and a slightly expanded projection that renders real overlap. Source Radius zero uses a fixed 3×3 kernel with linear depth-comparison sampling at legacy model sampler slot 8 or generated graph sampler slot 15 and stays within the guarded tile. Each tap corrects its comparison depth for the receiver plane, including the bilinear footprint, so a large floor does not shadow itself differently on downward and side-facing cube faces. The plane comes from world-position derivatives evaluated before material discard; authored normals remain the separate normal-bias direction. The full sixteen-light atlas has 12×8 tiles: 12336×8224 texels, approximately 387 MiB at the default 1024 interior resolution. Capacity grows lazily through 1/2/4/8/16 lights, preserving entity-ID assignments. Preferences allow 256/512/1024, default 1024; changing resolution invalidates the allocation. Atlas bytes include pending/retired lifetimes in aggregate GPU accounting. Capability/allocation failure reports a diagnostic and disables shadow sampling for that context instead of dropping selected lights or using stale slots.

Point lights append optional version-4 `castShadows` (default false), `shadowDepthBias` (0.005 m), and `shadowNormalBias` (one shadow texel). Bias values must be finite and nonnegative. Normal bias uses the world normal before normal mapping and the local light texel footprint; depth bias moves the receiver toward the light. These address the acne/peter-panning tradeoff described in [Microsoft's shadow-depth guidance](https://learn.microsoft.com/en-us/windows/win32/dxtecharts/common-techniques-to-improve-shadow-depth-maps). Model entities append cast/receive flags, both default true and noninherited. Versions 1–7 remain readable; existing scenes are only rewritten by explicit Save. Validation, equality, duplication, field-aware history and Play snapshots retain the fields; undo does not rewind unrelated runtime poses.

`EditorResources::prepareShadows` gathers the complete extracted world before Scene/Game receiver culling, conservatively rejects meshes outside each light range, and aggregates geometry LOD/texture demand across relevant point lights and both cameras' directional cascades before preparing each caster once. Immutable packets retain geometry/material/alpha-texture versions. Renderer face culling and LOD selection remain independent of camera visibility and Scene-only picking revisions. Opaque and masked meshes reproduce material alpha factors, vertex alpha, selected UVs, texture/sampler/cutoff and determinant-aware/double-sided winding. Collider and Character outlines, grid, placement previews and transparent particles are excluded.

Scene and Game share one active-world shadow owner and the same interpolated transforms. Static maps are cached by world/light identity, light position/radius, caster membership/transforms, selected geometry/alpha versions and shader generation. `ShadowUpdateScheduler` permits four complete dirty point-light updates (24 cube faces) per world frame, shared across both camera submissions. New or moved light projections take priority, followed by distance to the frozen focus; deferred age eventually outranks that priority to prevent starvation. All six faces publish atomically. Pending caster-only changes may retain their previous coherent map; a new/moved projection is unshadowed until its complete replacement is submitted. This bounds work at the cost of a few frames of shadow-content latency under sustained overload. Color, intensity, attenuation, Source Radius, exposure and camera motion alone do not require redraw. Saved-scene thumbnails prepare all admitted shadows from their authored snapshot into a separate 256-pixel-per-face atlas without the interactive update cap, avoiding incomplete captures or active-world overwrites. Material/model previews bind disabled shadow state. Shadow visibility multiplies only the relevant point-light BRDF contribution, preserving IBL, emissive, other lights, exposure and final encoding.

Natural numeric pass ordering is retained; the current combined point/directional schedule is listed below and defined in `RenderTypes.h`. One framebuffer per atlas fits the pinned 128-framebuffer cap; partial view clears affect only their face rectangles. Shader compilation/preflight and atomic hot reload include the caster program and sampler contract. Diagnostics expose active/cached/rendered lights, face and draw counts, capacity, memory and failures. Positive point Source Radius adds contact-hardening PCSS as described above. Spot shadows, translucent/particle shadow casting, baked lighting and ray tracing remain separate slices.

### Material height displacement

The Output graph owns optional Height and `MaterialTessellation` values: disabled by default, Amount 0.1 in mesh-local units, Midpoint 0.5, uniform integer Factor 8 and Height Texture LOD 0. Height accepts scalar graph math and explicit linear-data samples with ordinary RGB-to-R conversion, UV0/UV1 and local/world triplanar mapping. Displacement clamps Height to 0–1, subtracts Midpoint and offsets along the interpolated local normal before the complete mesh transform. Selecting Tessellation changes topology; control values update the prepared packet without compiling another compatible program. Disabling it retains authored links and removes the active Height branch.

Material ABI/generator 32 publishes native DX12 patch vertex/hull stages plus a generated domain stage for mesh color, depth, selection/material-slot picking and point/directional shadows. Those passes evaluate the same Height expression; coverage remains a separate graph concern. Scene/Game, mesh material previews and mesh thumbnails consume the shared implementation. DX11, node previews and particle sprites keep ordinary geometry without changing authored settings. Enabled mesh materials request original LOD0; a coarser resident level can remain visible while original geometry streams; host streaming demand and renderer/shadow culling expand local bounds by `abs(amount) * max(midpoint,1-midpoint)` before the complete affine transform. Height displacement is visual and leaves CPU collision geometry unchanged.

Time-dependent Height and world-projected Height that changes with object transforms invalidate the relevant shadow content and reject unsupported GI receiver history through the existing dynamic-material contract. Rigid, compatible displacement retains ordinary object motion; this does not transport arbitrary per-point height deformation into motion vectors. The same complete-generation cache, shader preflight and last-good packet publication apply to domain stages. Hardware tessellation remains DX12 only; adaptive factors and Vulkan tessellation are separate work.

`MeshShading` is a per-model occurrence value: Use Mesh Normals (default), Flat or Smooth, authored under Inspector → Model → Shading and serialized as optional `meshShading` in scene v23. Source normals always control height displacement. Flat derives the rasterized triangle normal and a matching normal-map frame. Smooth regenerates angle-weighted normals inside existing position/authored-normal charts, preserving hard edges and deformation identities. Optional 12-byte normal streams are shared per geometry LOD and requested through the existing streaming budget; ordinary modes alias the original normal without copying vertices. Animated Smooth rebuilds normals from the deformed positions using compact shared adjacency and a separate compute pass.

Smooth tessellated domains evaluate four neighboring complete Height expressions along orthogonal mesh-local directions built from the longest source edge and the triangle plane. Their barycentric velocities retain actual local distances, avoiding the amplification from nearly parallel source-edge probes. Active Height texture dimensions, available mip levels and current corrected UV0/UV1 or triplanar mappings reduce each probe footprint toward a 1/16-texel radius, with precision floors limiting further shrinking. Fractional Height LOD uses the finer contributing mip for this conservative bound. The affine base derivative is analytical; only displacement offsets are subtracted before the inverse-transpose normal transform. The differential change reaches the selected smooth normal and tangent before fragment interpolation. Color and material-coverage passes agree on this normal, including world-triplanar sampling. The center Height evaluation and authored Height Texture LOD remain unchanged; material ABI/generator stays 32.

Patches remain three-control-point triangles with uniform integer subdivision. Smooth shading does not supply geometry between tessellated vertices: high-frequency Height on long triangles can still alias, and increasing Factor alone does not guarantee its removal. Height Texture LOD can trade relief detail for a lower-frequency geometric signal; suitable finer source triangles provide more samples. This slice adds neither adaptive subdivision nor derivative-map filtering. The metric and finite-difference approach follows the principles in [PBRT's bump-mapping derivation](https://pbr-book.org/3ed-2018/Materials/Bump_Mapping) and [Mikkelsen's surface-gradient framework](https://jcgt.org/published/0009/03/04/paper-lowres.pdf), while the probe bounds are Crimson implementation choices. See the [shared Height contract](../third_party/crimson-renderer/docs/MATERIAL_HEIGHT_DISPLACEMENT.md) for sampling and compilation details.

Mode changes preserve positions, displacement directions, bounds, silhouettes and CPU collision. Batch/population, shadow-content and GI-history signatures include the effective mode; pending Smooth data retains authored-normal shading until coherent publication. Existing hard charts are retained rather than automatically bevelled or stitched.

The [Height gradient stability checkpoint](HEIGHT_GRADIENT_STABILITY_CHECKPOINT.md) records the thin-Quad regression, saved stair-mesh captures, measured GPU cost and remaining geometric/normal sampling limits.

### Directional shadows and dynamic material inputs

Scene, Game and saved thumbnails use the same four stable cascades. The former fixed-camera Game world projection and independent player-focus projection have been removed. The historical [shadow checkpoint](SHADOW_ARCHITECTURE_CHECKPOINT.md) and [quality correction](SHADOW_QUALITY_CORRECTION.md) preserve earlier measurements; they do not define the current projection or filtering policy.

Directional lights retain Cast Shadows, Shadow Distance (default 100 m), Depth Bias (0.005 m) and Normal Bias (one texel), and add **Shadow Angular Diameter (°)** (default 0.53°, range 0–2°). This is the full source diameter: zero selects filtered hard shadows; positive values estimate blocker-dependent penumbrae. Missing Angular Diameter defaults to 0.53° in memory, and current scene writers include the optional v23 field. Creation enables shadows; missing historical Cast Shadows fields remain disabled. Authored light direction determines the projections independently of actor facing.

`DirectionalShadowMath` divides min(camera far, Shadow Distance) using the practical logarithmic/uniform split scheme with lambda 0.8. This favors near first-person detail over the former fixed 0.1/0.3/0.6/1 distances. Sphere-fit extents are quantized, centers snap to shadow texels and overlap covers each split's final 10%; the final 20% of Shadow Distance fades visibility to unshadowed. Complete world caster collection precedes camera receiver culling, and intersecting upstream casters extend light-space depth. Resource demand and renderer submission use the same projection math and orthographic LOD footprint.

The shared filter follows receiver-plane-corrected PCF and PCSS. Hard or subtexel-soft shadows use a weighted 5×5 PCF kernel evaluated with nine bilinear depth comparisons (a 6×6 raw-texel footprint). This minimum antialiasing footprint is preserved at contacts; there is no directional post-filter binary contact reconstruction. Positive angular diameter uses twelve raw blocker probes and thirty-two bilinear comparison samples on fixed light-space disks, with a smooth 2–3 texel transition from PCF. Blocker-search misses fall back to weighted PCF to preserve thin shadows; the transition evaluates both filters. Fixed disks avoid adding temporal noise without TAA. Mathematical matrix rows are extracted through row-vector multiplication consistently across HLSL/GLSL. Geometric receiver-plane correction, slope-scaled normal bias and projection-dependent numerical tolerance protect sloped surfaces; normal maps do not choose the bias plane. Both cascades in an overlap use one continuously blended world-space normal offset.

Every cascade includes the same world-space sampling halo `H = tan(AngularDiameter / 2) * authoredShadowDistance`. The estimated filter radius is `min(H, tan(AngularDiameter / 2) * meanBlockerReceiverGap)`, with angles converted to radians. Penumbra growth therefore saturates after one Shadow Distance of light-space separation. Farther upstream casters still cast; the cap bounds sampling and projection padding rather than clipping caster distance. This common world cap prevents cascade-dependent penumbra caps. Shadow Distance, resolution, angular size and sparse blocker sampling still impose finite detail and quality limits; this is filtered shadow mapping, without ray tracing or temporal reconstruction.

The practical split scheme follows [Zhang et al., GPU Gems 3 Chapter 10](https://developer.nvidia.com/gpugems/gpugems3/part-ii-light-and-shadows/chapter-10-parallel-split-shadow-maps-programmable-gpus); stabilization follows the constraints described in [Microsoft's cascaded-shadow guidance](https://learn.microsoft.com/en-us/windows/win32/dxtecharts/cascaded-shadow-maps). The optimized PCF footprint follows [Ignacio Castaño's shadow mapping article](https://www.ludicon.com/castano/blog/articles/shadow-mapping-summary-part-1/), and contact hardening follows [Fernando's PCSS paper](https://developer.download.nvidia.com/shaderlibrary/docs/shadow_PCSS.pdf). Lambda 0.8, the 12/32 sample budgets and the world halo are Crimson implementation choices.

Directional content remains cached per projection. Each dirty projection uses a depth-only fullscreen clear of its guarded tile before caster submission; cached sibling tiles remain intact in the same sequential physical view. Scene, Game and thumbnail light blocks each contain four 2×2 tiles. This spends more Game shadow storage/work than the former one-world/one-focus policy to distribute detail through a freely rotating perspective view. Point and directional maps share one D32F atlas/comparison binding, retaining all twelve generated-material texture stages and existing IBL stages. Texture/sampler separation, variable per-light resolution, static/dynamic point-map splitting and spatial caster queries remain later work.

Within one shadow submission, caster collection computes common instance/primitive bounds, transforms, material bindings and coverage fingerprints once across point and directional targets. Target masks reject unrelated geometry before expensive work; each target selects its resident LOD and builds its own ordered caster list/signature. Unique submitted geometry and graph leases remain pinned. This is per-call preparation reuse, without mutable cross-frame scene caches or persistent world spatial queries.

Directional cascades share one scissored view per light/camera. View layout 2 uses the maintained bgfx port 14 compiled with `BGFX_CONFIG_MAX_VIEWS=512`, preserving numeric identity ordering for draws, blits and native copies. Active-world shadows occupy 1–104; Scene uses 112–159, particle preview 160–183, picking/readback 184–185, thumbnail shadows 192–291, thumbnail rendering/readback 296–328, material preview 336–359 and Game 368–415. Gaps within profiles reserve later stages. Tools use 496, diagnostics readback 503 and eight native platform slots 504–511; DX12 retains its terminal copy boundary. Exclusive external graph frames keep their separate 248-view lease limit. `RenderTypes.h`, `RenderPassPlan` and the renderer manifest define the exact layout/provenance contract. Both camera contexts reserve shadow storage before submission; live, pending and retired allocations remain accounted and released before bgfx shutdown.

Graph schema v13, within native material v6, adds optional Refraction and optical Output values and retains optional Height/tessellation values introduced in v8 with disabled defaults for older graphs. It retains the Desaturation, Contrast, ContrastRGB, HueShift and Grunge kinds and independent Grunge layer contributions, including Stains Opacity and Leaks Opacity, without renumbering kinds/pins. Readers accept graph schemas 1–13 and convert older Grunge style settings to explicit layer values in memory; writes contain only the current representation. Clamp is the current name for the existing scalar 0–1 saturation operation; existing values, custom names and links remain intact. Panner retains Crimson Mapping and uniform-transform restrictions; Time provides transient game/real seconds and optional period. Generated programs retain stable authored hashes and patch runtime parameter rows at bind. One material context serves a world frame; picking captures the displayed context and thumbnails use zero. Active time-dependent masked coverage and dynamic Height invalidate the relevant point/directional shadow content. Arithmetic, authoring and clock conventions are maintained in `MATERIAL_NODE_AUTHORING.md`.

Image adjustments accept scalar/RGB Input and a scalar amount, with finite disconnected defaults shown inline and in properties. Desaturation uses `gray + (rgb-gray)*saturation` with linear Rec.709 luminance: 0 is grayscale, 1 preserves the source and values above 1 increase saturation. Contrast converts to luminance and uses `0.5+(value-0.5)*contrast`; ContrastRGB uses the same equation per channel. Both default to 1. HueShift defaults to 0 signed degrees and rotates HSV hue modulo 360 while preserving value/saturation, including HDR strength. The adjustment outputs remain unclamped linear values; CPU uniform evaluation, generated shading and node previews share these equations. Contrast exposes scalar Value and replicated RGB; the color adjustments expose RGB and R/G/B. Uniform inputs keep the expressions uniform, and parameter edits retain shader topology.

Grunge combines dirt specks, stains, scratches, leaks and noise into one deterministic generated texture. Dirt specks, stains, scratches and leaks each have an independent opacity contribution to the same image, with zero removing that layer's contribution. Common defaults are Seed 0, Tiling 1, Coverage 0.5, Disorder 0.5 and Detail 0.5. Layers adds Base Noisiness 0.55, Dirt Specks Opacity 0.62, Stains Opacity 0.35, Scratches Opacity 0.84, Leaks Opacity 0, Sharpen 0.63, Large Variation Intensity 0.9 and Invert Dirt false, exposed through existing transactions in the node and Inspector. Each active Grunge uses one of the shared twelve Texture 2D/Grunge sampler slots; mapped sampling is shared by material, node-expression, picking and masked-shadow passes.

`assets/GrungeGenerator` synthesizes one canonical 1024×1024 linear RGBA8 image with identical RGB channels and opaque alpha. ResourceManager workers generate immutable pixels and mip payloads; AssetLibrary's TextureStreamer owns main-thread GPU upload/publication, retention and leases, with allocations included in its normal residency accounting. The content key includes generation settings, source resolution and generator revision. Tiling and Mapping apply while sampling and do not rebake the source. Noise/layer changes regenerate asynchronously without changing shader topology; coherent last-good images and material packets remain visible until replacements are usable. Bump the generator revision when its pixel equations change. No external bitmap, separate Asset Browser entry or authored image file is involved; only the settings persist in the material graph.

The Grunge node embeds a 160-logical-pixel square using a 256-pixel display image, and explicit Start Previewing/Value/RGB preview displays a flat 1024-pixel image without changing the material's 3D preview geometry choice. Value previews show raw numerical grayscale; RGB previews use one sRGB display conversion. Both derive from the same canonical linear pixels sampled at runtime, with repeat sampling for Tiling. The graph requests visible images only and retains bounded per-node last-good leases while generation is pending; preview state does not publish document edits. The readable local Adobe Substance Designer `grunge_concrete.sbs` graph informed the layered control names and composition. Crimson's generator is independently implemented and does not claim pixel-identical Adobe output.

Modifier operations follow UE 5.8 semantics. Continuous evaluation is `((NativeResolved + AddBase) * MultiplyAdditive / DivideAdditive * MultiplyCompound) + AddFinal`, then bounds. Additive multiply/divide use bias sums; compound multiply uses products. The first qualifying Override in deterministic application/modifier order wins. Instant/periodic operations run sequentially on Base but publish and clamp the final dependency graph atomically. Magnitudes are literals or registered C++ calculations with declared scalar parameters and read-only source/target attribute/tag snapshots. Specs capture once; reapplication captures again. Unknown native attributes, missing calculations or invalid magnitudes reject the complete application. A known attribute that has not yet been materialized is a valid target.

Stacking is per asset: None, Aggregate by Source or Aggregate by Target, with immutable generation part of group identity. Limit zero means unlimited. Duration refresh, optional extension cap, period reset, expiration policy, overflow denial/clear and stack-count scaling are independent fields. Accepted capped reapplication replaces captures and recalculates contributions even if count does not change. Additive operations scale by count, additive multiply/divide use `1+(m-1)*count`, compound uses `pow(m,count)` and Override is unscaled. Extend adds remaining plus incoming duration; subsequent expiration refresh uses the stored extended duration. Denied overflow does not refresh; optional clear removes the old group before rejection. Overflow effect chains are outside this slice.

Asset tags identify effects. Source/target Required and Blocked tags gate applications. Granted tags contribute while an effect is active, with reference counts across overlapping effects and authored tags; they never mutate authored scene Tags. Ongoing inhibition, immunity, chains, live cross-actor captures, abilities, input binding, costs/cooldowns, targeting, cues/VFX, networking and prediction remain later slices.

`PlaySession::applyEffect(source,target,assetId)` returns status/diagnostic and an optional active handle. Removal accepts a handle and optional stack count; active snapshots and readiness are explicit. Existing Base helper APIs route through the same instant backend. Command-bar application targets the yellow ShowDebug Attributes actor, uses the designated Player as source when available, and resolves an exact UUID or an unambiguous quoted asset name. RemoveEffect removes all active versions/stacks of that definition on the target; it does not undo permanent instant or periodic changes.

## 5. Simulation and editor lifecycle

Play's passive Game-image metrics overlay uses the current ImGui style and is visible by default. F1 toggles it only in focused Game during Play, outside text/IME, modal and drag/drop capture. Its temporary visibility state survives Play/Stop within the editor session. `App` supplies completed wall-frame and main-thread preparation/submission timings through `EditorSession`; the CPU sample excludes explicit `bgfx::frame` and native presentation waits. `GameView` samples completed bgfx GPU timestamps and driver device-memory counters, plus explicit texture/program/model/shadow owner bytes. Unknown counters display N/A. Timings/draws cover the whole editor frame and device-memory figures can include other applications. A CPU-only sampler updates the readout at roughly 4 Hz; the overlay adds no scene fields or interactive hit targets.

`PlaySession` uses 60 Hz fixed simulation with at most eight catch-up ticks per rendered frame; excess wall time is discarded and counted. Rendering is independent and interpolates character translation and shortest-path facing in a separate presentation scene, including its dependent camera and visual hierarchy. Physics and runtime particles advance once per tick, regardless of the number of views. These are initial engineering bounds, not production hardware-performance guarantees.

`ScenePlayerInput` stores `enabled=true`, `mouseSensitivity=0.10` degrees/logical mouse pixel and `invertY=false`. `MovementComponent` stores its independent `enabled=true`, `jumpHeight=1.1` m, `groundAcceleration=45` m/s², `groundFriction=8` per second, `airAcceleration=12` m/s², `airControl=0.35`, `strafeTilt=3` degrees, `tiltResponse=12` per second and `stairSmoothingTime=0.10` seconds. All numeric controls validate finite bounded values, and the Inspector uses ordinary transactional property gestures with undo/redo/cancellation. Movement top speed remains resolved `Stats.MovementSpeed`. Physical W/A/S/D positions supply normalized ground-plane axes relative to mouse yaw; view pitch cannot add vertical movement. Ground acceleration approaches the target velocity, friction brakes when released, and air acceleration scaled by Air Control preserves contact-resolved momentum while steering.

Space queues a press edge independently of render ticks. A pending edge survives frames with no fixed step; physics owns a 120 ms landing buffer and 100 ms coyote window and converts authored jump height to ballistic takeoff velocity. Key repeat cannot produce another jump. Rising motion disables floor snap and stair probes until appropriate support returns; ceiling contacts clear upward velocity. Escape, capture/focus loss, native-window migration, Stop, player replacement and authored player-pose changes clear stale commands and pending jump state. Suspend handling also discards accumulated wall time so resuming does not replay a catch-up burst.

Mouse look consumes accumulated relative motion directly without delta-time scaling, updates even on render frames with no simulation tick, and clamps pitch to ±89°. `PlaySession` retains transient yaw/pitch and the exact residual affine camera basis, preserving authored eye offset, lens, roll, scale/shear and handedness. Collision-resolved lateral velocity relative to view yaw drives Strafe Tilt, normalized by movement speed and eased exponentially at Tilt Response; zero response applies immediately. Authored camera edits establish a new baseline while unrelated document edits retain the current look. After interpolation and authored follow resolution, `Scene::applyRuntimeCameraPose` applies only the presentation camera's local matrix through its parent inverse. It changes pose revision without changing authored follow values, scene revision/generation, dirty state or history. The simulated document and saved scene never receive mouse-look or tilt transforms.

First-person stair compensation is transient, with its response authored under Movement → Stair Smoothing (s). `PhysicsWorld` uses Jolt v5.5's native `ExtendedUpdate` and exposes the complete signed vertical displacement over discontinuous support through `characterStepHeight` for the completed tick. This includes capsule rounding and settling during ordinary sweeps as well as stair/floor helpers. Continuous travel tangent to the same support plane is excluded using contact-plane and foot-displacement distances rather than equality of noisy triangle-mesh contact normals; jumps, unsupported falls and landing ticks are also excluded. `PlaySession` adds the opposite terrain correction to its camera compensation and returns it toward zero using an exact critically damped spring at `2 / stairSmoothingTime` per second. It retains the full correction across closely spaced steps; a fixed offset cap would release part of each new rise directly into the camera. The authored time ranges from 0 to 1 second: lower values are faster and higher values are softer. Zero clears compensation and velocity immediately, including without a simulation tick, and schedules no further smoothing. Presentation evaluates the spring analytically between physics ticks while canceling terrain displacement at the actor's interpolation fraction, avoiding artificial velocity corners at tick boundaries. An existing residual may continue easing during a jump; ballistic motion supplies no new compensation. Horizontal motion, direct mouse look and collision-resolved motor poses retain their existing behavior. A world-collision ray clamps only the additional vertical camera displacement, retaining a clearance of at least 0.05 m or the camera near plane, whichever is larger. Camera/player identity, authored pose and traversal-profile changes, transform locks, suspension and Play teardown reset the transient smoothing state. The optional v23 `movement.stairSmoothingTime` field defaults to 0.10 seconds when absent, retaining the prior response without writes on load. Its Inspector gesture uses normal scene undo/redo and cancellation; saving persists the setting and Play edits remain temporary. Positive live response changes retain the current camera look and stair compensation. Old `motor` and Player Input movement values convert to `MovementComponent` on load; Save writes `movement` and input-only Player Input settings without a scene-version bump.

Each Navigation Agent's saved Show Route controls its remaining-path Game overlay. Paths remain transient, clipped to the Game image and projected with that frame's camera. FPS input creates neither routes nor click markers; independent actor route state remains available through the command/query interface.

The character motor owns each collision-resolved actor pose; future dynamic bodies will own their physics poses. Rendering never writes interpolated values back into the world. Scene edits reconcile static bodies/characters at safe boundaries. An explicit character transform edit teleports its motor and clears velocity. An active transform gesture holds affected Character descendants and any Character on the edited entity's parent/follow dependency paths, so child or follow-camera gizmos retain stable baselines while unrelated simulation continues. Jolt types, handles and worker behavior remain behind `PhysicsWorld`, never in serialized scene data or ImGui code.

Play creates an independent transient `SceneDocument` from the authored scene, including unsaved edits. Scene, Outliner, Inspector and Game operate on that runtime document while Play is active; both views observe deliberate scene edits and simulation. The authored document retains its selection, dirty state, saved token and undo/redo history unchanged. Stop destroys runtime physics/particles/document state, discards all Play scene edits and returns to that original document. Runtime scene saving is blocked; New/Open scene, asset deletion and application exit defer their authored-document action until Play has stopped, then use the original document's existing dirty-state and transaction rules. No runtime poses enter scene files. Background resource preparation shares imported assets and GPU caches across Play/Stop. Independent material/effect documents retain their own authored save lifecycle. Document/world generation checks and interaction cancellation prevent pending picks/placements or selections from referring to the discarded world.

Custom game UI remains C++ authored. A gameplay UI framework, animation state graph and audio implementation remain separate slices from the implemented controller and imported clip playback.
