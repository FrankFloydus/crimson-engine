# Crimson Engine: ARPG engine architecture

This is the authoritative engineering guide for the native Crimson Engine ARPG engine. Consult the sections relevant to changes in rendering, assets, scene/runtime boundaries, input, or resource lifetime. Keep it current when an agreed implementation changes these contracts.

The foundation is the native renderer and editor in this project. Work progresses through small slices with a working application at each handoff. Features described as planned are architectural commitments, not instructions to build every subsystem before the next milestone.

Project root: `C:\Users\Drako\Desktop\_CRIMSON_ENGINE\crimson-engine`. The official renderer name, CMake target, and executable are `crimson-renderer`, `crimson-renderer`, and `crimson-renderer.exe`. Renderer implementation, shaders, the ImGui/bgfx adapter, and rendering diagnostics belong in `src/crimson-renderer/`. Editor orchestration belongs in `src/editor/`, docked views in `src/tools/`, CPU scene/history/storage in `src/scene/`, Play/input/controller orchestration in `src/runtime/`, Jolt adaptation in `src/physics/`, and managed imports in `src/assets/`. `src/math/` owns the public math boundary. Keep `App` focused on composition, native lifetime and the frame loop.

### Particle-system baseline and planned extensions

[Particle system pre-work](PARTICLE_SYSTEM_PREWORK.md) defines the CPU-first effect assets, authoring workflow, research rationale and staged implementation. Native PBR material authoring and Save As from imported originals are available; imported-original editing remains milestone 2c as **Next**.

`ParticleEffectDocument` owns authored definitions, transactions and dirty state; `AssetLibrary` publishes immutable committed effect versions and preserves a currently open document's authority over background file notifications. Bounded native metadata reads and atomic storage occur at document/catalog boundaries; material, texture and geometry preparation stays with the existing resource and GPU owners. `CpuParticleSystem` owns dense records and 60 Hz scheduling. `SceneParticles` keys runtime instances by `SceneDocument::documentGeneration()` plus persistent entity ID, so registry rebuilds and transform edits preserve playback. Copied presentation values cross into renderer-owned buffers/programs. Live particles, playback and preview cameras are never serialized. Valid intermediate drags update only the isolated preview in place; commits/undo/redo publish revisions and update referencing instances in place. Color/size/intensity apply on extraction, gravity on the next tick, emission controls on subsequent scheduling, and initial velocity/lifetime at birth. Capacity replacement clears live records but retains the clock, emission phase and playback state; identity replacement or explicit Restart/Play Effect performs a full restart. Cancellation restores authored values without rewinding time. Saving the revision preserves playback. Limits/counters cover emitter capacity, particles cleared by capacity edits, aggregate scene instances/capacity, spawning, catch-up and rendering omissions.

The particle and material editors use `ImGuiWindowFlags_NoDocking` and clear only their own saved dock assignments. Dear ImGui multi-viewports are enabled through its SDL3 platform backend and renderer-owned `ImGuiBgfx` callbacks. Each secondary native window has one persistent DXGI swap chain owned by `PlatformSurface`; resize and collapse/expand use `ResizeBuffers` after releasing backbuffer references. Ordinary resizing never recreates that chain. The pinned bgfx native-window framebuffer recreation path is bypassed for secondary windows: bgfx renders ImGui into an ordinary framebuffer backed by a renderer-owned D3D11 RGBA8 texture, then `postFrame` copies its pixels to the matching native backbuffer and presents after the application's single `bgfx::frame()`. This adds one GPU copy per presented secondary window, with no extra exposure or color encoding. View IDs retain natural numeric submission order: Scene 0–3, particle preview 4–7, reserved 8, picking 9–10, thumbnails 11–15, material preview 16–19, Game HDR/tone-map/encode 20–22, main tools 23, and platform windows 24 upward. Game needs three passes because it omits the editor grid. Keeping ID 8 unused preserves picking/thumbnail readback indices: the pinned D3D11 backend compares remapped blit-order keys with decoded numeric view IDs, so reordering the former UI pass around those readbacks is unsafe. Every offscreen image now completes before either main or platform UI samples it; all UI windows share the existing shaders/texture owners. The wrapper is imported only after its placeholder exists, and its external texture remains owned until queued framebuffer/wrapper destruction completes; shutdown drains those retirements before releasing the renderer/context. Native operation failures log the stage, HRESULT and window details rather than routing through bgfx's fatal native-chain creation. This follows [Microsoft's resize contract](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/nf-dxgi-idxgiswapchain-resizebuffers) and [copy requirements](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-copyresource).

Platform windows are destroyed while SDL/ImGui/bgfx are still alive. When the main window cannot draw, one ready visible secondary window supplies synchronized presentation; other windows present without a second synchronization wait. Pending or occluded surfaces use a bounded sleep fallback. UI positions use desktop coordinates and the host viewport's framebuffer scale; scene navigation filters SDL events by the owning window ID. Focus in any owned editor window keeps playback active; total focus loss or no drawable windows suspends it without accumulating wall time. Closing a secondary particle or material window closes its document, while only main-window close requests exit. A main-window exit request restores its minimized host so dirty-document prompts can run. Existing dockable panels retain their layout, and built-in ImGui DPI scaling follows the host monitor without a custom theme.

Particle references participate in the authored usage/replacement/deletion transaction. Clearing/deleting a shared effect assignment preserves the emitter entity and its affine hierarchy; deleting an instance leaves its shared effect intact. The currently open effect document must be closed before its managed asset can be deleted. Failed loads retain the previous usable definition where available and report the affected reference.

### Concrete editor and math boundaries

`App` constructs owners, initializes the window/renderer, forwards events and drives frames. `ResourceRuntime` publishes worker results, acknowledges self-writes, dispatches watched changes and coordinates shader replacement before editor drawing. `EditorSession` selects the authored or transient Play document and owns document/session actions; `PlaySession` owns runtime simulation and interpolated presentation. `EditorResources` freezes coherent prepared model groups, and `AssetPreviews` schedules isolated thumbnails/readbacks/cache writes. `SceneEditor` coordinates editor commands; `SceneViewport` owns picking, gizmos, focus and navigation input arbitration. `MaterialDocument` owns material authoring, `tools/MaterialEditor` presents its property/document controls, and `editor/MaterialPreview` coordinates the isolated mini-viewport and accepted input. `ScenePanels` contains Outliner/Inspector views and document commands. `AssetBrowserPanel` owns browser interaction; its CPU `BrowserCatalog` stores virtual folders/aliases without changing managed IDs. Keep these concrete dependencies out of `App`; no service locator or general job graph is required.

Engine public interfaces use `Vec2/3/4`, `Quat`, `Mat3/4`, `Ray` and `Aabb` from `src/math`. Matrices are column-major, multiply column vectors and default to identity; accumulation uses explicit zero matrices. GLM is private to the math implementation. Serialization writes packed scalar arrays, while renderer and ImGuizmo adapters use explicit `.data()` boundaries. No GLM, bx, ImGui or GPU-specific math type becomes persistent scene data.

### Dependencies and resource ownership

- The application constructs services and passes explicit dependencies. Controller and gameplay code do not call ImGui or bgfx.
- Scene components/history carry persistent typed asset references, not residency handles or GPU ownership.
- The rendering boundary owns GPU meshes, material textures, environment resources, and targets. The tools adapter owns its ImGui GPU resources under the same bgfx lifetime.
- Physics owns Jolt worlds, bodies, shapes, constraints, and body-to-entity mappings. Actor/controller code uses the engine-owned adapter.
- Background decoding returns completed CPU results through publication queues. It does not create GPU resources or modify the world directly.
- The main thread initially owns authoritative world mutation and application-side render submission. Jolt may execute internal jobs; its callbacks collect facts rather than changing EnTT.

| Owner | Current responsibility |
| --- | --- |
| `ResourceManager` | Immutable CPU model metadata/geometry, decoded images, materials, scene snapshots, environment bakes, shader binaries and derived-cache descriptors; workers, dependencies and retention |
| `AssetLibrary` | Managed imports/catalog/storage, authored reference policy and transactions; `TextureStreamer` owns image/material texture and image-thumbnail GPU allocations |
| `Renderer` | Revision-aware shared model buffers, independent environment resources, scene/sky programs, picking and isolated model/scene/particle/material preview targets |
| `ImGuiBgfx` | ImGui program/font GPU resources, native platform display surfaces and retirement queues |
| `SceneDocument` | Mutable CPU scene, selection, immutable semantic edit patches and saved-state tracking |

`AssetRef<T>` preserves serialized IDs without keeping payloads resident. RAII `ResourceHandle<T>` expresses live interest; `ResourceSnapshot<T>` leases an immutable exact version. Publishing a replacement leaves old readers valid. Entries track source epoch, job generation, dependency fingerprint, published revision, state and diagnostics. Failed replacements retain the last working payload. Cache keys include identity/type/processing variant; image source decoding is shared while color/data/normal and mip policies remain distinct. CPU payload and GPU leases are separate; uploaded textures do not pin source pixels.

Two CPU workers serve a bounded deduplicated priority queue. Selected/visible content and placement take priority over browser previews. Imports stage complete packages on workers, then publish files/catalog entries on the main thread. Workers also decode images, process cgltf/MikkTSpace geometry, generate mip/LOD caches, bake environments and compile shaders. They never call bgfx/ImGui or mutate documents. Completed jobs carry generations/epochs and exact dependencies; stale work is rejected. Model/material/texture groups become visible only when coherent candidates are prepared before drawing. Existing working groups survive failed replacements.

The default soft targets are 512 MiB CPU and 512 MiB aggregate managed GPU resources, including a 64 MiB thumbnail sublimit. Idle retention is five seconds; pressure trims unpinned least-recently-used resources immediately. Pending and leased retired allocations count toward accounting. Live leases remain valid above soft limits. Model/image uploads are chunked toward 4 MiB and roughly 2 ms per frame; an individual backend call can exceed that time target. Browser requests only visible card resources. Editor/library metadata interests expire, and submitted draws/readbacks pin their actual CPU/GPU versions.

Shutdown stops watchers/new requests, cancels and joins workers/compiler processes, drains pending readbacks, releases editor/library/renderer/ImGui GPU owners before bgfx, then releases CPU caches and SDL. Async picks also carry document generation/request identity and the actual main-view resource signature; unrelated thumbnail changes do not invalidate them.

### Streaming and hot reload

Versioned texture-cache indices address independently readable, CRC-checked levels. Warm requests read required levels without full-source decoding. Cold requests first publish complete coarse physical textures whose longest edge is at most 64 pixels, then swap fully uploaded sharper allocations with valid mip tails. Color RGB filters in linear light; alpha/data stay linear; normal mips renormalize safely. All six glTF minification modes, magnification, wrapping and UV selection survive; non-mip variants are single level. Demand derives from projected bounds/UV use, shared consumers request the highest detail, selected models request native resolution, and invisible models do not refine. Picking and color rendering use identical resident alpha-cutout textures.

meshoptimizer 1.1 creates up to three compact attribute-aware LODs at half, quarter and eighth source triangle counts, capped at 1% source-relative error. LOD0 stays exact. Material boundaries, seams, normals, colors and tangent handedness constrain simplification; unsafe/useless reductions stop. Metadata/hierarchy/material references/bounds load independently from CRC-checked vertex/index payloads. Conservative affine-projected error chooses levels at one pixel with 20% hysteresis; selected models request LOD0. Complete candidates publish after chunked uploads, preserving previous buffers on failure.

A Windows watcher debounces managed sources and engine shader sources/includes for 200 ms, excluding caches/staging/archived import originals. Self-writes are acknowledged; worker fingerprinting invalidates transitive dependencies. Texture/model/material/environment/scene candidates preserve working resources on invalid changes or unexpected disappearance. Clean active scenes reload between gestures while preserving camera/surviving selection; dirty scenes offer Reload/Keep editing/Save As, and overwrite requires resolving an external-save conflict.

Shader workers use the pinned shaderc build configuration with discovered include dependencies and a versioned cache. Binary structure, reflection/uniform/sampler/layout/stage contracts and private DX11 bytecode preflight are checked before GPU creation. Renderer program families and ImGui publish together, including model/picking parity. Embedded programs are startup fallback; failed compilation/interface/preflight retains the current complete program group.

### Identity and persistence

Persist stable asset and authored-object identities. Keep source locations readable and project-relative. Runtime entity references include world identity and entity generation. Do not retain component pointers across structural registry changes or queued work.

Never serialize temporary EnTT, Jolt, or bgfx handles. Introduce versioned serialization as new asset/scene data lands. Existing imports, material factors/map paths, and dock layout must remain usable when identity support is added.

Current material persistence writes version 2 of `assets/material.json`, adding `normalMap` and `normalStrength`; existing unversioned material files load with a neutral missing normal map and strength 1. Version 1 of `assets/environment.json` stores `map`, `enabled`, `intensity` and `rotation` in degrees. An empty environment path selects the built-in studio. Both files use managed project-relative source IDs; missing/unsupported assignments produce a diagnostic and fall back safely. Environment state is independent of material resets. Assets and `crimson_ui.ini` follow the optional `--project-root` location.

Model IDs are project-relative paths to versioned package manifests under `assets/models/<unique-id>/manifest.json`. Packages retain the original document and normalized managed geometry/image dependencies, so reopening never depends on the source folder. The older version-1 `assets/preview.json` remains preserved for the legacy single-model path; ordinary scene authoring uses native scene assets.

Model import identity is a worker-computed SHA-256 over the original document, normalized document and all managed buffer/image bytes. Unchanged complete inputs reuse a surviving package and its stable model/image/material IDs, including legacy packages without identity metadata. New packages use content-derived identities; main-thread publication rechecks worker-verified candidates and resolves concurrent duplicate requests before catalog registration. Changed content creates a distinct asset instead of implicitly replacing existing scene references. Tombstoned identities are not reused. Existing duplicate packages are never consolidated automatically, and reuse preserves browser folders/aliases.

Version-4 scene files live at `assets/scenes/<unique-id>.crimson-scene`. They contain a display name, active Environment/Camera/player-character IDs, optional saved preview camera and entity records: persistent 64-bit IDs encoded as hexadecimal strings, names, parent IDs, sibling order, full local matrices and optional model/light/Environment/particle-reference/Character/Collider/Camera components. Camera definitions retain follow target ID and world-space offset; Character defines capsule height/radius and speed; Collider defines Box size. Versions 1, 2 and 3 remain readable; version-1 scene-level environment/exposure migrates into an active Environment in memory. Only explicit Save writes version 4. Paths remain managed/project-relative. Complete validation precedes document replacement; malformed data, cycles, missing parents, invalid matrices and light-budget violations preserve the current document/history. Missing asset references remain identifiable and survive saves. Atomic saves preserve prior identity/dirty state on failure. `assets/editor-session.json` keeps the last scene, editor cameras, panel visibility and legacy-preview recovery separately. New scenes remain empty; no active Environment uses studio and exposure 1. Additional Environment nodes/duplicates remain inactive until Make Active; deleting the active node clears activation, and undo restores both.

The `Scene` owns the EnTT registry. Persistent entity IDs are independent of registry handles; validated registry replacements invalidate runtime handles through a generation and increment the scene revision. Components contain identity, parent/order, a full affine local matrix and optional model, particle-effect, light and Environment data. Imported model nodes remain read-only asset internals instead of becoming editable EnTT entities. Light extraction supports up to four directional and sixteen point lights; creation, duplication and loading enforce those limits.

Reparenting computes `inverse(newParentWorld) * oldWorld`, retaining shear, reflection and nonuniform scale. Cycles and singular parents are rejected atomically. Multiple selection operates on topmost selected roots, so selected descendants are transformed, deleted or duplicated once. ImGuizmo manipulates a stable orthonormal proxy; its delta applies to the original world matrices, then converts back through the parent inverse. A single root uses its origin as pivot; a group uses its union-bounds center. The UI must not decompose/recompose persistent matrices through Euler angles or discard shear silently.

Outliner selection follows Quader's retained multi-selection drag and Ctrl/Shift range conventions. F2 edits names inline. Empty background is the unparent target; no common root is displayed. Group/Ungroup are atomic document commands, retaining world matrices and stable IDs. Inspector edits the primary entity's name and local Position/Rotation/Scale through explicit X/Y/Z fields, following Quader's property layout and gesture boundaries. UI rotation is in degrees with Quader's XYZ Euler convention (`Rz * Ry * Rx`); engine math uses radians. Full affine local matrices remain authoritative. Viewing a transform never recomposes it, and channel edits preserve the unedited translation/stretch/reflection rather than replacing the entire matrix with a lossy TRS approximation. Captured gesture values keep numeric rotation stable during edits and commit one undo command. Raw matrix coefficients are not ordinary Inspector controls. Viewport gizmos use T/R/E/F without an operation toolbar or drag-status text.

Directional lights and their viewport arrows both transform the authored local -Z vector through the accumulated world matrix and normalize it. They must not reconstruct forward from cross(X,Y), which loses authored forward under reflection/shear. Quader's direct-axis policy is the reference; its -Y asset convention is not adopted by Crimson.

`InspectorTransform` owns buffered transform fields, captured gesture matrices and the active ImGui scalar identity. A released, deactivated or clipped field finalizes its owned transaction rather than relying only on one-frame deactivation events. Opening Edit explicitly finishes an owned panel edit before querying history, and releases that field's text buffer so it cannot reapply a value after Undo. Viewport gestures retain separate ownership. Zero scales are valid finite scene data and participate in normal history/save/reopen behavior; the renderer hides collapsed draws with a dedicated diagnostic rather than conflating them with nonfinite data. Restoring the transform restores drawing and clears that diagnostic.

`SceneShortcuts` reads the production ImGui focus/input guards for scene commands; tests use that same routing rather than a second shortcut implementation. `SceneDiagnostics` merges renderer/resource messages into a dockable panel with `NoFocusOnAppearing`. Asynchronous diagnostics, including a zero-scale draw becoming hidden, must not take keyboard focus from the Inspector and block the next scene Undo.

Browser cards share a footprint with a letterboxed square thumbnail and selection-only borders. Size ticks are 16/32/64/128/256/512, default 128. The synthetic parent **..** card accepts navigation/moves, while remaining outside rename/delete/selection/payload operations. Multi-drags show a count card; bounded tooltips are suppressed during drag/context/modal interaction. `assets/browser.json` stores virtual folders/display aliases without moving dependencies or changing IDs. Mixed moves validate atomically. Typed drags retain compatible image assignment; viewport model ghosts use delivery's grid intersection/fallback, have no persistent/pick IDs, and prepared delivery commits one batch command. Document replacement cancels pending placements.

Successful model-payload delivery explicitly transfers keyboard focus from the source browser to the viewport. Scene Delete remains an undoable document command; Browser Delete is a separate asset-file action restricted to browser focus with no active widget or drag. Deferred preparation does not steal focus back if the user subsequently chooses another panel.

Model thumbnails render with isolated studio lighting and a bounds-framed three-quarter camera. PBR material thumbnails apply native linear material definitions/bindings to one shared radius-1 sphere, with UV0/UV1 and analytic tangents; sprite-compatible material thumbnails use a quad. Godot's `EditorMaterialPreviewPlugin` is the PBR thumbnail setup reference: camera (0,0,3), 45-degree field of view, fixed key/fill directional lighting. The sphere shares tracked renderer geometry with the live material editor; material previews do not use legacy sphere assignment functions. Saved-scene thumbnails use the persisted editor camera; older scenes use combined bounds. Isolated targets/readbacks share the scheduler and retain leases through completion. Source/dependency/version signatures key GPU/PNG previews; cache writes run on workers. Capture requires texture versions matching the fingerprinted sources. Preview activity does not alter scene content or the active render environment.

`AssetReferenceManager` indexes authored usages independently of residency. Stable read-only imported materials live under `assets/materials`; primitive indices retain parallel material references. Missing original bytes are bypassed only by these explicit mappings; unexpected disappearance remains corruption. Deleted sidecars are not regenerated, and retained package images/materials remain independently discoverable after model deletion.

Scene-file deletion stays outside entity undo. Staged files, same-volume quarantine and a recovery journal support rollback/recovery. This follows Godot's `DependencyRemoveDialog` filesystem-index/deletion-set check. Confirmation shows only counts, omitting zero categories and the selected-file list. The document history holds up to 256 semantic commands as immutable before/after patches of affected entity values, scene properties and selection IDs. Selection, camera navigation, focusing and asset import are outside scene history.

Transform parenting serves imported nodes and attachments. Spatial queries serve collision, nearby actors, visibility, and ground targeting; the transform hierarchy is not the proximity-query structure.

## 3. Rendering and material contract

Use a right-handed, Y-up world with meters as the distance unit. Camera, picking, physics, scene transforms, and imports use consistent conventions; backend conversions belong at their adapters.

Retain the current direct-light BRDF: GGX with `alpha = perceptualRoughness * perceptualRoughness`, height-correlated Smith visibility, Schlick Fresnel, and Fresnel-weighted Lambert diffuse. The visibility term already contains the Cook-Torrance denominator; do not divide by it again.

Keep the current roughness floor of `0.045` and numerical safeguards until a measured, explicitly documented shading change replaces them. Avoid changing the material response by copying a different approximation under the same parameter names.

### Color and texture meaning

- Accumulate lighting in linear HDR. Apply exposure and tone mapping once; encode the final image to sRGB once.
- Particle rendering uses a blend-capable `RGBA32F` accumulation target. Alpha stores continuous coverage: opaque draws write one, empty pixels clear to zero, Alpha particles use premultiplied OVER and additive particles preserve destination alpha. Step 2 resolves `Reinhard(exposure * HDR) + (1 - coverage) * linear editor background`, replacing Step 1's inverse-Reinhard background term so dark smoke attenuates exact white. The background is a display matte outside exposure/tone mapping; opaque output is unchanged. Tone mapping combined premultiplied HDR once approximates separately tone-mapping each transparent surface, and intense emission can saturate at display white. Draw the neutral grid into `RGBA16F` display-linear color and clamp/encode once to sRGB. This is Crimson's chosen integration, with regression checks for backgrounds, coverage, mixed blending and opaque rendering.
- Preserve the editor sequence: **HDR scene -> exposure/Reinhard into linear display color + exposure-independent background -> grid -> sRGB viewport image -> ImGui tools**. Grid, background and tools remain independent of scene exposure.
- Texture roles specify decoding and channel selection. Albedo is sRGB color; roughness, metalness, and normal maps are linear data.
- Environment panoramas use linear radiance for Radiance HDR and sRGB decoding for PNG/JPEG/TGA/BMP. HDR thumbnails are tone-mapped display previews; preprocessing reads the original HDR source. HDR sources cannot be assigned to material slots.
- Standalone roughness/metalness maps retain their current red-channel behavior. glTF imports preserve packed roughness in green and metalness in blue through explicit channel metadata.
- Material factors multiply their maps. Manual first assignment to an empty albedo/roughness/metalness slot retains the current neutral-factor behavior; replacement preserves edited factors and clearing removes only the map.
- Importing a model preserves its authored material factors. Import is not a manual picker assignment and must not reset those factors to neutral.
- Material edits update parameters/bindings without recreating geometry or rebuilding shaders.

Future shipping UI composites after scene tone mapping and before final encoding so scene exposure does not change HUD brightness. Its C++ presentation code reads state and emits commands; it does not own simulation rules.

### Milestone 1: IBL and normal maps (implemented)

The sphere editor has scene-level environment lighting: diffuse irradiance, a roughness-prefiltered specular environment, and a two-channel BRDF lookup texture. The Lights tab provides the environment picker/clear/drag-and-drop field, enable toggle, intensity 0–10, and Y rotation −180° to 180°. An empty assignment uses the built-in studio; renderer preparation failures remain visible in the panel.

Preparation/cache loading runs on initialization or source assignment, outside ordinary frame rendering. Intensity and rotation reuse prepared resources. The CPU-derived cache lives at `assets/cache/ibl/<FNV64>.ibl`; its key includes source content, preprocessing version 3, BRDF version 1, dimensions and sample counts. Cache reads validate payload hash, length and finite/range constraints; incompatible or damaged data is regenerated. Authored sources and assignments are independent of this disposable cache.

The default studio is generated as a 512×256 HDR panorama. Derived RGBA32F cubemaps comprise 16×16 diffuse faces with 512 cosine-weighted samples and 128×128 specular faces with a full eight-level mip chain and 256 GGX samples. Specular mip roughness is `0.045 + 0.955 * mip / 7`; runtime selection follows that same range. A 128×128 RG32F BRDF lookup uses 1024 GGX samples with the runtime's correlated Smith visibility, roughness convention and denominator safeguards. Source HDR radiance is bounded to finite values up to 60000 for downstream HDR stability.

Environment convolution uses filtered importance sampling to prevent small, bright HDR emitters from producing scattered reflection copies. A linear source pyramid preserves spherical radiance integrals with exact latitude and cell-overlap weights, including odd image dimensions. Each sample selects and blends source levels by its probability-derived solid angle, with a lower bound from the destination cubemap texel footprint. Longitude wraps across the panorama seam; latitude clamps at the poles. These source levels provide spatial filtering and are distinct from the output cubemap's roughness levels. The filtering change invalidates older derived caches automatically; it does not change the BRDF, material roughness floor, exposure or source assets.

Use split-sum specular recombination:

```text
specularIBL = prefilteredEnvironment * (F0 * LUT.scale + LUT.bias)
```

Store diffuse preprocessing as irradiance divided by pi and apply that normalization once. Sum environment and direct lighting in linear HDR before exposure/tone mapping.

Karis's notes provide the split-sum reference. Its analytic-light roughness adjustment must not be applied to IBL, and its selected visibility approximation must not silently replace our correlated Smith model. The notes also describe the grazing-angle limitations of the prefilter approximation. IBL does not itself supply local geometry reflections or shadowing.

Material data includes a normal-map reference and strength 0–2 with the existing adjacent picker/clear/drag-and-drop pattern. Normal assignment preserves strength. Tangent XYZ points along increasing U; the sign in tangent W reconstructs the bitangent as `cross(N,T) * W`, oriented along increasing V. Maps use +Y/OpenGL green. The sphere supplies stable tangents at its duplicated seam and poles. The shader orthogonalizes interpolated tangents, provides a safe basis for degenerate input, scales tangent XY, and renormalizes the evaluated normal. Missing maps and zero strength use the original smooth normal; conventional `(128,128,255)` flat maps evaluate neutrally, with both nearest 8-bit encodings of 0.5 treated as zero XY.

Preserve material factors, direct lights, docking, Quader navigation, the grid, existing imports, and persistence. Normal-map and environment assignment data must also survive reopening.

Focused CPU regressions cover environment preprocessing and math. The user performs visual acceptance of environment-only material response, roughness-dependent reflections, neutral/detailed normals and reopening. Historical captures are retained separately and do not impose a feature-completion workflow.

Single-scattering GGX can darken rough metals through missing microfacet multiple scattering. This remains a known limitation; a later compensation must be a consistent BRDF change rather than an exposure adjustment. Split-sum environment reflections also retain their grazing-angle approximation and do not reflect nearby geometry or provide occlusion/shadows. Area lights, advanced material layering, shadows, and a different light pipeline receive separate scopes.

## 4. Models and the first controllable actor

### Milestone 2: actual glTF/GLB import

Managed import feeds **independent scene entities**. One Import button accepts images and glTF/GLB files together; all usable assets and saved scenes appear in one browser. Importing and placing remain separate. Model placement preserves authored dimensions, orientation and internal node transforms; the scene entity supplies its independent root matrix. F frames the selected entity/subtrees by moving the editor camera. Scene navigation orbits the camera target without querying the old sphere.

Supported geometry includes indexed/nonindexed triangles, converted strips/fans, 8/16/32-bit indices, interleaved/normalized and sparse attributes, UV0/UV1 and vertex colors. Missing normals use flat faces; normal-mapped primitives without tangents use MikkTSpace with corner splits. Selected scene roots use the declared default scene, otherwise the first scene, otherwise parentless nodes. Hierarchy transforms are preserved with inverse-transpose normals, mirrored winding and tangent handedness; singular transformed draws are skipped with diagnostics.

Imported material factors are linear and separate from the sphere's editor-sRGB factors. Core metallic-roughness supports base color/alpha, packed G/B roughness/metallic, normal scale, emissive, indirect AO, double-sided rendering and OPAQUE/MASK. Color textures decode sRGB while scalar/normal maps remain linear. Texture bindings preserve UV selection/wrap/magnification and all six glTF minification modes through role-correct mip streaming. Missing UVs or sets beyond UV1 are rejected.

BLEND materials, skins, morph targets, points/lines and unsupported required extensions fail import. Animations, imported cameras/lights and optional unsupported extensions produce warnings while core static content remains usable. Managed imports stage and validate complete dependencies before publication; failed files in a mixed batch do not prevent other valid imports. GPU preparation failures retain usable scene resources and report diagnostics.

**Milestone 2b: scene authoring is implemented; user acceptance is pending.** New/save/save-as/open/delete operate on native scene assets. ### Milestone 3: Play, character movement and game cameras

**Implemented; user acceptance is pending.** Outliner Add creates Character, Collider, Camera and Box entities. Character holds capsule dimensions and movement speed; the first character becomes the scene's player, with explicit Make Player for later choices. The upright capsule origin is at its feet. Jolt `CharacterVirtual` owns collision-resolved motion and gravity against explicit static Box bodies. The capsule requires unit world scale, an upright rigid transform and no Character ancestor. Visuals are ordinary child model entities, allowing independent scale, forward-axis correction and alignment. Particle children use the same scene hierarchy.

Box is a centered one-meter cube stored as the ordinary model reference `builtin:mesh-box-v1`, with immutable shared CPU geometry and the protected default PBR material. It has its own persistent identity, separate from material-preview meshes, with no import package or sidecar. The existing model preparation, picking and GPU cache paths render it. The Box visual never adds implicit collision. A separate Collider entity may be parented to a visual; its positive local Box dimensions and transform define collision independently, with parent scale applied once. Static Box bodies accept nonzero scale and rotation but reject collapsed or sheared world matrices with diagnostics. They cannot be attached beneath a Character. Imported meshes and the editor grid do not generate physics geometry.

Built-in Boxes accept a per-entity `modelMaterial` AssetRef override; an empty value resolves to the protected PBR default. The geometry and model asset remain immutable and shared. Inspector exposes a compatible Lit PBR Opaque/Mask picker, thumbnail/name or swatch, clear and material drag/drop. Extraction forwards `materialId` to Scene, Game and saved-scene thumbnails. Prepared packets are keyed by model plus material identity while geometry/GPU residency remains keyed by the model. Assignment is a separate history field, survives duplication and runtime pose updates, and persists as an optional version-4 field. Reference/deletion preparation discovers saved, live and historical overrides and applies compatible replacements/defaults in the existing project transaction. Imported model surface assignment remains milestone 2c.

Point lights define a world-space radius, independent of entity scale, defaulting to 20 m for creation and older scene files. Scene validation accepts finite values in [0.01,100000] m; Inspector, history, serialization and extraction retain it. Renderer packs inverse squared radius in the unused point-color fourth component. Both PBR fragment shaders multiply existing inverse-square attenuation by `max(1-(distance/radius)^4,0)^2`, giving zero contribution and zero slope at the boundary. The shared shader expression is exercised by CPU tests and retains the linear HDR/final sRGB contract.

`PlayerController` follows Detour path corners to an accepted left-click or held-LMB world destination, produces horizontal velocity at the Character's speed, caps final-step travel and uses a 1 cm arrival tolerance. It turns upright -Z forward toward the next route corner with shortest-yaw exponential smoothing at response 14/s. Mouse motion with LMB released never changes yaw or the destination; idle retains facing. `PlaySession` resolves the captured click or held ray against live Jolt static colliders; the nearest hit must have a walkable normal within 45°. Visual-only meshes and the grid supply no movement destination. CharacterMotor accepts per-tick facing commands; scripted C++ movement without one retains movement-facing fallback. WASD is not bound to player movement. The CPU `crimson-camera` target shares Camera projection/ray code with runtime and rendering. Basic step/slope handling and wall sliding use Jolt's virtual-character update. Jumping, character-to-character contacts, moving platforms, dynamic rigid bodies, mesh colliders, animation and combat remain later slices.

`crimson-navigation` privately links [Recast and Detour](https://github.com/recastnavigation/recastnavigation), using Recast to generate traversable polygons and Detour to find and straighten complete polygon corridors. `NavigationMesh` consumes only `PhysicsWorld::staticBoxes()` accepted by Jolt, including rotated/reflected boxes; each convex collider contributes solid spans so coincident floor/wall surfaces cannot create a walkable tunnel inside the box. Mesh clearance uses capsule height/radius plus Jolt padding, 45° slope and 0.3 m step limits, at 0.1 m horizontal cells and 0.05 m height cells. Geometry revision or capsule dimensions trigger rebuild/replanning; ordinary runtime poses and speed edits do not. Incomplete/unreachable paths are rejected, nearest-polygon horizontal adjustment is limited to 5 cm, and the final destination remains the original world hit. Unreachable requests can be retried after live geometry changes. One derived mesh serves the controlled capsule, bounded to 4 million global horizontal cells and 16 million cumulative Box raster cells; invalid/oversized data reports a diagnostic and yields no route. Baking is synchronous in this MVP; tiled/streamed navigation, off-mesh links and crowd avoidance remain future work. Godot's current [dependency manifest](https://github.com/godotengine/godot/blob/master/thirdparty/README.md#recastnavigation) also uses Recast 1.6.0 for 3D baking, with its own runtime path-query and avoidance systems.

Camera entities define a vertical perspective FOV and clipping planes; their local -Z axis supplies viewing direction. The first camera becomes active; Make Active and the Game selector change the persistent scene camera ID. Add Camera starts at the selected entity's world position plus `(8,10,8)` and faces that entity, using the origin when nothing is selected. Its defaults are 45° vertical FOV and clipping planes of 0.1–2048 m, independently of the editor navigation camera. Follow stores an entity ID and world-space offset, evaluates position as target position plus offset, and retains ordinary camera orientation. Assigning/replacing/clearing follow preserves the view. Explicit camera position edits change its offset; dependent target edits and runtime movement reconcile the camera's local matrix before extraction so its children, gizmo and Game image agree. Parent translation is not added twice. Target rotation does not affect follow itself, while ordinary parent rotation still affects camera orientation. Target deletion preserves the current pose and clears follow; invalid reference/parent-follow cycles are rejected. Active-camera deletion clears activation without choosing another camera. Missing activation produces an explicit Game message.

Game is an ordinary dockable ImGui window using existing native multi-viewports; View → Game also opens it in Edit mode for immediate camera composition. It owns independent physical-pixel render targets and excludes the grid, entity markers, gizmos and picking. Camera projection explicitly uses `CameraFovAxis::Vertical`, while Quader/editor navigation retains `ShorterDimension`. Scene and Game extract/cull/prepare from their own camera and size, sharing resource snapshots and max per-frame texture demand. `advanceStreaming` rotates submitted leases and starts residency collection once per owner frame; both views accumulate residency and keep separate entity LOD hysteresis. Resource leases from every submission stay pinned through GPU completion. Orthographic projection remains outside this slice.

Play opens, expands and focuses Game, then automatically gives it gameplay input without a click. ImGui focus selects its tab; a detached Game also receives an SDL native-window focus request. Activation waits for that native owner to exist and gain keyboard focus. Clicking its image reacquires input after editing, and Escape releases it. The image has its own interactive item so holding a click cannot be mistaken for a window-move gesture or an unrelated widget capture. SDL events are filtered by originating native window and explicit Game image ownership, including when Scene and Game share the main native window. Text/widgets, modal interactions, clicking other panels, hiding/closing Game and focus loss clear held/pending input. Editor navigation and scene shortcuts cannot consume the same gesture as the player. Closing Game stops Play; Stop leaves Game open as an authored-camera preview.

## 5. Simulation and editor lifecycle

`PlaySession` uses 60 Hz fixed simulation with at most eight catch-up ticks per rendered frame; excess wall time is discarded and counted. Rendering is independent and interpolates character translation and shortest-path facing in a separate presentation scene, including its dependent camera and visual hierarchy. Physics and runtime particles advance once per tick, regardless of the number of views. These are initial engineering bounds, not production hardware-performance guarantees.

Game input captures one pending button-down point and ray using the camera, desktop image rectangle and physical target dimensions that produced the displayed image. Normalized image coordinates map to target pixels, including detached windows and framebuffer scaling. The UI acknowledges the native click without replacing it with later cursor coordinates or replaying it through a later follow-camera pose; a blocked-to-Game handoff retains the original press coordinates. Accepted clicks resolve before fixed stepping, so a render frame with no tick still retains the command. An owned image press also starts held-LMB steering: subsequent samples use the current cursor and latest displayed-camera projection, including when the cursor stays still while the follow camera moves. `PlaySession` samples held destinations at most 20 times per second and replans only after a 5 cm ground-point change; unchanged accepted or rejected requests do not repeat Detour queries. Navigation geometry is still rebuilt only for collider/capsule changes. Button release retains the last accepted route. Leaving the image pauses retargeting; invalid or unreachable held samples retain that route. A cancellation revision clears controller destinations even if focus is lost and reacquired in one frame. Escape, capture, focus loss, native-window migration, Stop, player replacement and authored player-pose changes clear stale movement. Held UI state alone cannot rearm a canceled gesture. No jump/action input is introduced in this slice. Suspend/focus handling clears pending input and accumulated wall time so resuming does not replay a catch-up burst.

Game's session-local Click marker option draws three projected great circles as a 0.15 m wire sphere touching the latest clicked or held ground hit. It is an explicit diagnostic overlay, clipped to the Game image and visible through geometry, rendered with the same camera/physical aspect as that frame. The hit is retained after release, arrival and input cancellation, including unreachable requests, and cleared on Stop or a missed/invalid-ground click. It creates no scene entity, physics shape or saved state.

The character motor owns each collision-resolved actor pose; future dynamic bodies will own their physics poses. Rendering never writes interpolated values back into the world. Scene edits reconcile static bodies/characters at safe boundaries. An explicit character transform edit teleports its motor and clears velocity. An active transform gesture holds affected Character descendants and any Character on the edited entity's parent/follow dependency paths, so child or follow-camera gizmos retain stable baselines while unrelated simulation continues. Jolt types, handles and worker behavior remain behind `PhysicsWorld`, never in serialized scene data or ImGui code.

Play creates an independent transient `SceneDocument` from the authored scene, including unsaved edits. Scene, Outliner, Inspector and Game operate on that runtime document while Play is active; both views observe deliberate scene edits and simulation. The authored document retains its selection, dirty state, saved token and undo/redo history unchanged. Stop destroys runtime physics/particles/document state, discards all Play scene edits and returns to that original document. Runtime scene saving is blocked; New/Open scene, asset deletion and application exit defer their authored-document action until Play has stopped, then use the original document's existing dirty-state and transaction rules. No runtime poses enter scene files. Background resource preparation shares imported assets and GPU caches across Play/Stop. Independent material/effect documents retain their own authored save lifecycle. Document/world generation checks and interaction cancellation prevent pending picks/placements or selections from referring to the discarded world.

Custom game UI remains C++ authored. No UI framework, gameplay screen, animation system, or audio implementation is required to complete the first three milestones.

## 7. Research references

The Khronos Simple Engine tutorial is the architecture reference for clear subsystem boundaries, explicit dependencies, RAII ownership and presentation separation; adapt those ideas to SDL3/bgfx. The EnTT documentation informs registry/component/view usage, not a requirement to adopt every EnTT facility. Their API examples and advanced feature lists do not mandate a service locator, generic framework or additional engine work.

The recursive review covered the overview, sections 1–7, section 9 and their linked descendants, including the shared appendix: 69 pages total. Section 8 (mobile) was excluded.
