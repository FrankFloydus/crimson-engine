# Crimson Engine repository instructions

Native Windows x64 first-person action game engine and editor: C++20, MSVC, CMake, SDL3, bgfx with Direct3D 12 by default and optional Direct3D 11, and Dear ImGui docking. The official renderer target/executable is `crimson-renderer` / `crimson-renderer.exe`.

## Current game direction

- The game now uses first-person movement and an editor-authored eye camera. DUSK and Quake are references for movement and camera feel: WASD, direct mouse look, jumping and lateral camera tilt. Keep new gameplay and level work consistent with that perspective.
- The former isometric ARPG player recipe and click-to-move input have been replaced. Retain precise legacy scene conversion and custom authored cameras; do not reintroduce the old player mode. Enemy and externally commanded actor navigation remain independent reusable systems.
- Actors, collision, navigation, gameplay tags, Attributes and Gameplay Effects remain implemented foundations. Their presence does not define weapons, combat, inventory, loot or progression rules for the new game; implement those only within an agreed feature slice.
- Historical D2R and ARPG renderer checkpoints remain evidence for existing code and measurements. They do not set the current game scope or require a fixed camera, a particular player-light rig, or the rest of the reference game's pipeline. Use the current architecture and lighting guide for implemented behavior and limits.

## Current implementation contracts

These checkpoints describe the implementation as of 2026-10-20. Preserve them when changing the relevant system; consult the linked architecture sections for full details instead of reconstructing decisions from old checkpoints or experiments.

### First-person player, camera and stairs

- `runtime/GameInput` owns physical WASD, relative mouse look and Space jump edges while Game owns input. `PlaySession` owns transient look, strafe tilt and camera presentation; `physics/CharacterMotor` / `PhysicsWorld` own the collision-resolved capsule. Player input requires no Navigation Agent, volume or bake. Movement speed comes from resolved `Stats.MovementSpeed`; acceleration, friction, air control, jump height and view response belong to `MovementComponent`, presented as Movement directly after Transform.
- Preserve the [project Jolt overlay](cmake/vcpkg-ports/joltphysics/README.md), which backports opposing-contact stair probes into pinned Jolt 5.5.0. Both probes follow the blocking terrain riser independently of camera/body facing, including A/D strafing and oblique spiral-stair approaches. Virtual characters remain blockers in every sweep but cannot select the riser direction; their requested velocities differ from Crimson's no-pushing contact policy. The contact must oppose movement; profile step/slope limits and capsule clearance still apply. Change the overlay and rebuild through the wrapper; never edit extracted dependencies under `build/`.
- The Player's real child/follow camera remains editable in the Inspector and through camera authoring. Preserve its authored offset, lens and affine basis; runtime look, tilt and stair compensation affect only the interpolated presentation camera, never saved transforms, follow settings or history. The First Person template uses a 1.65 m eye offset, 75° vertical FOV, 0.05 m near and 2048 m far planes.
- Stair smoothing uses the complete supported vertical terrain correction, including capsule rounding and settling outside Jolt's stair helpers. Exclude continuous travel on the actual support plane, upward jumps, unsupported falls and landing ticks. Keep native Jolt `ExtendedUpdate` traversal; do not alter physical movement to disguise camera jitter. Presentation samples the critically damped return analytically between fixed ticks and cancels terrain displacement at the same interpolation fraction. Retain full accumulated compensation and the world-collision camera-clearance guard; a fixed 0.5 m offset cap reintroduces jolts on closely spaced stairs.
- **Movement → Stair Smoothing (s)** authors `stairSmoothingTime` in [0,1], default 0.10 s. Lower is faster, higher is softer, and zero clears pending compensation immediately even without a physics tick. Positive live edits preserve current look and compensation. Camera/player identity, authored pose/profile edits, transform locks, suspension and Play teardown reset transient state. Preserve 60 Hz fixed simulation, responsive render-frame mouse look and explicit Scene/Game input ownership.

### Renderer backends and shader publication

- Direct3D 12 is the application default. **Edit → Preferences → Rendering → Renderer (restart required)** selects DX12 or DX11 for the next launch; `--renderer dx11|dx12` overrides it for one process without saving. `GraphicsBackend.h`, `EditorPreferences`, `app/Options` and `App` own selection before bgfx initialization. Backend choice is application data, never a scene/Environment property. The Engine rich Forward+/PBR path does not implement Vulkan. The shared renderer separately implements borrowed Vulkan for Quader's modeling/editor path.
- **Rendering → Antialiasing** selects Off/SMAA live, default SMAA. The host supplies this presentation preference through `SceneSettings::antiAliasing` to Scene/Game and material/particle previews; asset cards use fixed SMAA. Shared `core::Smaa` implements reference SMAA 1x High after tone mapping and before editor overlays with explicit edges/weights/blend passes, linear reconstruction and one final encoding. RawData and picking remain unfiltered. Temporal AA/upscaling and offscreen MSAA remain unimplemented. Preserve material ABI 32 and focused `smaa_render_core`/DX11 checks.
- Both APIs use the same SM5/DXBC shader family and material cache contract. The historical `dx11` shader build token does not mean the running renderer is DX11. Keep embedded programs, shader manifests, generated material interfaces, reload validation and cache generator identity coherent; never edit generated headers manually. See [material shader startup](docs/MATERIAL_SHADER_STARTUP.md).
- Current material generation is v32, retaining explicit None/Circular/Quad UV0 interpolation, the PointShadow prior-world varying/optional rigid-motion depth-prepass MRT and four surface color outputs. The superseded emission-only Glow MRT and `u_glowSource` are removed. Preserve `u_clusterRecordLayoutV6`, six texels per point record, twelve material texture slots and the 27-float/108-byte mesh layout. Update every producer/consumer and the cache identity together when changing that ABI. Tone-curve coefficients are presentation-only and stay outside the generated-material ABI.
- Material Output **Height** and **Tessellation** were introduced in graph schema8 inside native material v6; the current writer uses schema10, readers accept graph schemas 1–10 and missing fields default off without writes on load. DX12 mesh color/depth/picking/point-shadow/directional-shadow variants share native hull/domain displacement; DX11, node previews and particles retain ordinary geometry. Preserve explicit Linear Data height sampling, clamp Height to 0–1, mesh-local signed Amount (default 0.1), Midpoint 0.5, uniform Factor 8 (1–64) and explicit Height LOD 0 (0–16). Disabling retains links and excludes active Height work. Enabled meshes request original LOD0 and expand conservative local bounds before the full affine transform. Dynamic Height invalidates relevant shadow content and unsupported GI history; collision stays CPU geometry. Keep native domain recipes/manifests, four-stage publication, embedded stages and generator/ABI 32 coherent.
- Preserve the pinned vcpkg baseline and the [project bgfx overlay](third_party/crimson-renderer/cmake/vcpkg-ports/bgfx/README.md). `d3d12-texture-upload.patch` fixes small-mip upload descriptors and staging written ranges; `d3d12-timer-fence.patch` waits for the command list containing timestamp resolution. Modify the overlay sources and rebuild through the wrapper, not extracted dependencies under `build/`.
- `PlatformSurface` and `ImGuiBgfx` own native secondary-window presentation. DX12 resources require both bgfx-wrapper retirement and confirmed queue completion; the marker after `Present` protects backbuffer reuse/resize/close. A timeout is not proof of completion. Preserve bounded allocator reuse, queued retirement and accounting. Do not reorder numeric view IDs casually: readbacks, compute-before-graphics sorting and the terminal platform-copy boundary depend on them.
- [The backend comparison](docs/RENDERER_BACKEND_COMPARISON.md) records the measured workloads and limitations. DX12 is not universally faster, and timestamp elapsed time is not active GPU execution time. Renderer multithreading was explicitly deferred by the user; existing resource preparation workers remain in place. Do not add a threading rewrite or rerun performance suites as routine handoff work.

### Screen-space lighting, fog and presentation

- Scene/Game and thumbnails use four stable directional cascades with a 0.8 logarithmic/uniform split mix, texel snapping, split blending and far fading. Shadow Angular Diameter defaults to 0.53° (0–2°); zero uses weighted 5×5 PCF, positive values use bounded contact-hardening PCSS. Preserve the common world halo, upstream offscreen casters, receiver-plane correction and continuous world normal bias across overlaps. The former single Game world/player-focus policy is removed. Point-shadow admission/update priority uses the visible Game camera eye, otherwise the Scene camera eye; freeze and reuse that origin through preparation and rendering. See [the directional contract](docs/RENDERER_AND_CHARACTER_LIGHTING.md#directional-shadows-for-first-person-cameras).
- `EnvironmentSettings::ssgi` and `::ssao`, shared `EnvironmentSerialization.h`, and the Environment Inspector own the opt-in effects. SSGI is the only GI method: the experimental world-space/dynamic GI method was removed. Missing effects default off; obsolete `gi` data converts in memory and writers emit only current `ssgi`/`ssao`. Loading must not rewrite or dirty scenes, and optional controls do not require a scene-version bump.
- `SsgiGpu` traces at half resolution with 1–4 screen-space diffuse bounces, temporal reprojection, independent raw luminance moments/history age, short-history variance reconstruction, filtering at steps 1/2/4 and atlas publication. Only the first spatial stage feeds next-frame irradiance history; wider stages remain display reconstruction. Medium retains four rays/sixteen steps, Stability .90 and authored denoise radius 4, whose three stages span seven half-resolution pixels. Scene and Game have separate histories and explicit resource owners; disabled/zero-strength effects schedule no effect work. Preserve history resets on view interruptions, identities, cuts, resize, settings and shaders. This is local visible-surface transport: it cannot provide Godot SDFGI-style offscreen room fill. Previews and thumbnails omit SSGI/SSAO.
- GI depth prepasses publish RGBA16F prior-minus-current world displacement/validity for rigid and instanced mesh occurrences. Primary receivers and donor hits use their own motion. New/incompatible geometry/materials, runtime-changing graph inputs and skin/morph deformation publish invalid motion and reject receiver history; unsupported donors retain geometry-validated camera-only lookup. Large normal changes conservatively reject history. Known authored material/light/environment source changes cap history age at four without resetting stationary receivers on moving-donor hits. Do not treat this bounded reconstruction as full A-SVGF/NRD or temporal AA.
- GI donors capture shadowed diffuse environment/direct lighting and eligible Lit emission, with separate World/Character lanes. Specular, existing GI, fog and Glow never enter donors. Opaque/cutout coverage and deformation must agree across shading/depth/capture; transparent draws preserve opaque auxiliary data, and partially faded models neither supply nor receive GI. Publication uses the existing Forward+ atlas, retaining all twelve material texture bindings.
- Scene directional/point lights expose **GI Energy** (`indirectEnergy`, default 1, range 0–16). It scales only that light's diffuse donor contribution, independently of direct brightness/specular/shadows. SSAO darkens environment/ambient and GI, not direct light or emission. Keep tunable quality/ray/step/denoising controls authored rather than replacing them with scene-specific constants. Full controls and limits are in [the lighting guide](docs/RENDERER_AND_CHARACTER_LIGHTING.md).
- Scene/Game top-right debug choices are Lit, Albedo, Roughness, Metal, Normal, Direct Lighting and Indirect Lighting, owned by transient `RenderDebugView` state. Toolbar gestures stay outside viewport input ownership. Lighting diagnostics retain exposure/tone mapping: ACES can clip a weak isolated indirect signal to black. Use Linear presentation when investigating that case before concluding point-light capture is broken.
- Fog covers the empty background/sky as well as finite surfaces. Exponential Density 0 with Height Density 0 must yield exact clear coverage, including the background. Preserve Sky Affect, Aerial Perspective and Sun Scatter through the shared environment serializer and shader paths; Crimson deliberately uses density-aware sky transmittance, rather than Godot's density-independent sky opacity. Material Receive Fog remains independent of lighting and coverage. The editor grid/tools compose later and remain exposure independent.
- `ToneMapping` owns authored per-operator controls shared by Scene/Game presentation and the CPU reference. Preserve linear HDR lighting and one final sRGB encoding. Changing the tone curve, exposure or diagnostic mode must not change GI source energy or direct-light settings. One full-scene HDR Glow effect includes emission, reflected/direct highlights and visible sky/sun. Additive/Mix/Replace compose in HDR; Screen/Soft Light compose in linear presentation space before SMAA. Glow exposes intensity, blend mode, spread, tint, highlight threshold, seven independent linear level gains, saturation, softness, anamorphic stretch and quality. Never normalize current gains by their sum; each level must fade continuously to zero. Old separate Glow/Bloom settings convert once in memory into current `glow` with `source: "Scene"`; writers omit Bloom and Core/Halo Balance. Loading never rewrites or dirties authored data. Spread/stretch select filtered base extent, never sparse tent-tap spacing. Preserve progressive source prefilter reductions of at most 2:1 per axis (up to five prefilters plus seven weighted levels/six up passes); default High starts half resolution and Low quarter, while narrow Spread can use full resolution. Disabled/zero Glow schedules no effect work. Temporal AA and DLSS/FSR remain unimplemented.

### Entity selection and actual hierarchy

- One authored entity has one Outliner row; capabilities appear together as ordered Inspector subsections, without outer empty/component rows or component-selection mode. `SceneOutlinerRows` and `tools/SceneInspectorSections.h` own this presentation. This does **not** flatten real spatial parenting: imported model hierarchies, explicit groups, visual attachments and collider children retain their entity IDs and affine local transforms.
- A Player is a composed actor, not a special entity class. Its direct following camera is edited inline; attached models/particles keep their own selectable rows. `sceneEntityOwner` must not remap arbitrary visual children to their actor. Reparenting a Box/model onto Player must retain visibility, selection, world placement and its real parent. Camera Follow retains its world offset and full translation-free affine world basis; camera edits do not move the controller. Nearest-actor lighting ownership stops at nested actors. Keep actor ownership, controller, Movement, input and navigation independent. Actor light rigs, Darkness Reveal, Environment Ambient Darkness and player-occluder fading have been removed; legacy keys are ignored on load and omitted on Save. Preserve generic instance opacity/material transparency; do not restore the nearest-wall compositor or player-dependent wall fading.
- Scene Save writes schema v23; readers accept v1–v23 and convert older scene data in memory. Collision modes/layers/masks, navigation volumes, shared agent profiles, Enemy behaviour, Tags and Gameplay Effects use the current representation. FPS Movement and Player Input fields, including stair smoothing, are optional v23 fields with defaults and need no new schema version. Save alone writes the current representation. Keep Edit/Play copies isolated, entity IDs stable and all property/reparent operations transactional with undo/redo and cancellation. See [scene/actor architecture](docs/ENGINE_ARCHITECTURE.md#composed-actors-and-scene-migration).

### Quader imports, bundles and material slots

- `src/quader/` owns Crimson's integrated native reader/conversion/publication bridge; `assets/QuaderSceneBundle` and `ContentStorage` own durable storage and recovery. One Quader **project/scene pair** owns one tracked `.crimson-quader` bundle under `Content/<scene_name>/models`, alongside `materials` and `textures` in lowercase snake_case folders, retaining immutable mesh generations and original model/member UUIDs. Only explicit native Quader Instance occurrences share definition/member geometry; ordinary source objects own separate full meshes even when their bytes are identical. Reimport retains historical content-only packages while publishing current owned generations. Individual mesh entities remain in the Outliner, each with its own native Collider child; collision triangles live in scene/history data, not separate imported model assets.
- Expanded glTF/manifest/buffer files belong only in Git-ignored `.crimson/cache/quader-imports/<bundle-id>/<model-id>/`. Startup reconstructs missing/corrupt expansions and member location mappings from the durable bundle, without Quader or its original source. Keep bundles, scenes, shared native materials/textures and authored reference policy durable; never treat the whole `.crimson` directory as disposable. Bundled mesh assets remain available in pickers; Explorer reveals their bundle. Individual meshes support normal Asset Browser deletion through the project reference/history transaction, removing selected bundle records, exact cache members and member locations while preserving siblings and shared native assets. Deleting the final mesh removes the empty bundle and unregisters its ID without tombstoning it; remove only proven empty ancestor folders below Content. Independent subasset rename/move remains protected.
- Existing loose Quader packages migrate through the recoverable file/index transaction after storage recovery/UUID conversion and before stores/watchers. Preserve exact member bytes/IDs, aliases, material assignments, saved-scene bytes and unrelated files. Remove only proven empty former package directories. Warm initialization must not rewrite equal data. `crimson-content-migrate --project-root <root> --report <json>` invokes this same initialization headlessly for requested migration/maintenance; the old executable must not run against new bundle storage.
- Import preparation reads an exact bundle baseline; publication commits bundle, generated members and native material/texture changes with explicit UUID locations before the scene command. `QuaderImportResult::files` carries literal project-relative paths; `locations` carries explicit UUID registrations. Never derive member UUIDs from cache paths. Roll back the location index by its literal `.crimson/asset-locations.json` path and refresh the in-memory snapshot after failure. Retain policy/source/baseline rechecks and coherent prepared-model seeding in `EditorSession`.
- Bundles are resource dependencies: external bundle changes regenerate loader files before model invalidation. Store project-relative paths against the canonical project root on Windows; case-sensitive `lexically_relative` against a differently cased caller root can incorrectly emit `../Engine/...` and break publication. Do not globally recase the coordinator root without also addressing ContentStorage snapshot keys/revisions.
- A Quader mesh with one real material creates one slot. Add a default only for primitives that actually lack a material; do not merely hide an extra importer-created slot. Distinct real slot indices stay distinct even when they share a material ID/name. Legacy `legacyUnusedMaterialSlot` normalization removes only the proven unused trailing fallback and preserves real indices/overrides; model metadata cache v8 retains that marker and the 27-float (108-byte) vertex layout. Keep the former fallback as a virtual identity-hash input so unchanged geometry reuses IDs. Native materials remain shared/editable, with independent Sync materials (default off) and Sync lights (default on) policies.
- Quader's optional UV-interpolation extension v1 is resolved separately from core reader ABI 7. Modes are None=0, Circular=1 and Quad=2 (inverse bilinear). Coordinates, correction and mode travel through `_CRIMSON_UV_INTERPOLATION_COORD`, `_CRIMSON_UV_INTERPOLATION_COEFF` and `_CRIMSON_UV_INTERPOLATION_MODE`; the former circular-only pair is read compatibility. Correct UV0 before material transforms; nonlinear normal frames use the final material UV derivatives after scale/rotation and skip a second normal rotation/sign transform. Normalize derivatives before frame conditioning so camera distance cannot select a different fallback. Preserve the native orthogonal frame convention `B = cross(N, T) * sign`. Ordinary UV, UV1 and triplanar mappings keep their existing behavior. Nonlinear primitives retain original LOD geometry until simplification can preserve their interpolation charts. This adds no geometry, sampler or uniform bindings.
- Reimport preserves same-ID authored assignments; changed layouts remap only unambiguous source identities, dropping removed/ambiguous overrides in the same undoable subtree command. Missing metadata defers publication rather than declaring slots removed. Preserve Crimson-only capabilities, visibility/style, collider overrides and authored light roles on matching generated entities. `tests/quader_bundle_fixture.h` supplies valid shared fixtures; manifest buffer dependencies require `"index": 0`.
- Use short disposable project roots for migration tests: expanded paths plus atomic temporary suffixes can exceed Windows file-path limits in deeply nested diagnostics directories. Test regeneration by removing/renaming only the disposable import-cache subtree, with resolved absolute ownership checks; never delete authored Content to simulate a cache miss. See [the bridge/storage contract](docs/ENGINE_ARCHITECTURE.md#quader-linked-scene-bridge-and-mesh-collision).

## Repository constraints

- Put reusable rendering implementation and shaders in the canonical `third_party/crimson-renderer` submodule. Keep Engine host adapters in `src/crimson-renderer/`, and editor panels and asset import/storage in their own boundaries. Both consumers pin the same published renderer commit; do not restore private copies.
- Keep `App` a composition/lifetime/frame-loop boundary. Scene editing belongs in `src/editor/`, dock views in `src/tools/`, and CPU world/history/storage in `src/scene/`; do not accumulate those implementations in the application loop.
- Public math values use Crimson types. GLM is an implementation detail inside canonical renderer support; do not expose GLM, bx, bgfx, EnTT entity handles or ImGui types in serialized scene data. Keep explicit RAII owners and concrete dependencies rather than introducing a service locator or engine framework.
- Preserve imported assets, material factors/assignments, and `crimson_ui.ini`. Changes to their storage must retain existing project data.
- Application branding lives in `assets/branding`; `src/platform/CrimsonResources.rc.in` embeds the ICO. A user-supplied ICO is authoritative: embed it unchanged, and do not overwrite it by running the PNG converter. Use conversion only when the user requests generation from a PNG. SDL owns the native window-class icon lifetime. Keep branding out of the managed texture library.
