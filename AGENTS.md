# Crimson Engine repository instructions

Native Windows x64 ARPG engine foundation: C++20, MSVC, CMake, SDL3, bgfx with Direct3D 12 by default and optional Direct3D 11, and Dear ImGui docking. The official renderer target/executable is `crimson-renderer` / `crimson-renderer.exe`.

## Current implementation contracts

These checkpoints describe the implementation as of 2026-10-17. Preserve them when changing the relevant system; consult the linked architecture sections for full details instead of reconstructing decisions from old checkpoints or experiments.

### Renderer backends and shader publication

- Direct3D 12 is the application default. **Edit → Preferences → Rendering → Renderer (restart required)** selects DX12 or DX11 for the next launch; `--renderer dx11|dx12` overrides it for one process without saving. `GraphicsBackend.h`, `EditorPreferences`, `app/Options` and `App` own selection before bgfx initialization. Backend choice is application data, never a scene/Environment property. Vulkan is not implemented.
- Both APIs use the same SM5/DXBC shader family and material cache contract. The historical `dx11` shader build token does not mean the running renderer is DX11. Keep embedded programs, shader manifests, generated material interfaces, reload validation and cache generator identity coherent; never edit generated headers manually. See [material shader startup](docs/MATERIAL_SHADER_STARTUP.md).
- Current material generation is v23, with `u_clusterRecordLayoutV6`, six texels per point record, twelve material texture slots and four material MRT outputs. Update every producer/consumer and the cache identity together when changing that ABI. Tone-curve coefficients are presentation-only and stay outside the generated-material ABI.
- Preserve the pinned vcpkg baseline and the [project bgfx overlay](cmake/vcpkg-ports/bgfx/README.md). `d3d12-texture-upload.patch` fixes small-mip upload descriptors and staging written ranges; `d3d12-timer-fence.patch` waits for the command list containing timestamp resolution. Modify the overlay sources and rebuild through the wrapper, not extracted dependencies under `build/`.
- `PlatformSurface` and `ImGuiBgfx` own native secondary-window presentation. DX12 resources require both bgfx-wrapper retirement and confirmed queue completion; the marker after `Present` protects backbuffer reuse/resize/close. A timeout is not proof of completion. Preserve bounded allocator reuse, queued retirement and accounting. Do not reorder numeric view IDs casually: readbacks, compute-before-graphics sorting and the terminal platform-copy boundary depend on them.
- [The backend comparison](docs/RENDERER_BACKEND_COMPARISON.md) records the measured workloads and limitations. DX12 is not universally faster, and timestamp elapsed time is not active GPU execution time. Renderer multithreading was explicitly deferred by the user; existing resource preparation workers remain in place. Do not add a threading rewrite or rerun performance suites as routine handoff work.

### Screen-space lighting, fog and presentation

- `EnvironmentSettings::ssgi` and `::ssao`, shared `EnvironmentSerialization.h`, and the Environment Inspector own the opt-in effects. SSGI is the only GI method: the experimental world-space/dynamic GI method was removed. Missing effects default off; obsolete `gi` data converts in memory and writers emit only current `ssgi`/`ssao`. Loading must not rewrite or dirty scenes, and optional controls do not require a scene-version bump.
- `SsgiGpu` traces at half resolution with 1–4 screen-space diffuse bounces, temporal reprojection, geometry rejection, two bilateral filtering passes and atlas publication. Scene and Game have separate histories and explicit resource owners; disabled/zero-strength effects schedule no effect work. Preserve history resets on view interruptions, identities, cuts, resize, settings and shaders. This is local visible-surface transport: it cannot provide Godot SDFGI-style offscreen room fill. Previews and thumbnails omit SSGI/SSAO.
- GI donors capture shadowed diffuse environment/direct lighting and eligible Lit emission, with separate World/Character lanes. Specular, existing GI, private Character Key/Fill, fog and Glow never enter donors. Opaque/cutout coverage and deformation must agree across shading/depth/capture; transparent draws preserve opaque auxiliary data, and partially faded models neither supply nor receive GI. Publication uses the existing Forward+ atlas, retaining all twelve material texture bindings.
- Scene directional/point lights and the actor's Local World light expose **GI Energy** (`indirectEnergy`, default 1, range 0–16). It scales only that light's diffuse donor contribution, independently of direct brightness/specular/shadows. SSAO darkens environment/ambient and GI, not direct light or emission; artistic Ambient Darkness remains separate. Keep tunable quality/ray/step/denoising controls authored rather than replacing them with scene-specific constants. Full controls and limits are in [the lighting guide](docs/RENDERER_AND_CHARACTER_LIGHTING.md).
- Scene/Game top-right debug choices are Lit, Albedo, Roughness, Metal, Normal, Direct Lighting and Indirect Lighting, owned by transient `RenderDebugView` state. Toolbar gestures stay outside viewport input ownership. Lighting diagnostics retain exposure/tone mapping: ACES can clip a weak isolated indirect signal to black. Use Linear presentation when investigating that case before concluding point-light capture is broken.
- Preserve the editor-angle shadow precision correction: Ambient Darkness publishes a negative sentinel when reconstructed receiver uncertainty exceeds the authored shadow bias, allowing the material to evaluate the exact fragment. Do not mask those bands by changing authored camera clipping or biases. Owners include `AmbientVisibilityGpu`, `ambient_visibility.sh` and the shared material paths.
- Fog covers the empty background/sky as well as finite surfaces. Exponential Density 0 with Height Density 0 must yield exact clear coverage, including the background. Preserve Sky Affect, Aerial Perspective and Sun Scatter through the shared environment serializer and shader paths; Crimson deliberately uses density-aware sky transmittance, rather than Godot's density-independent sky opacity. Material Receive Fog remains independent of lighting and coverage. The editor grid/tools compose later and remain exposure independent.
- `ToneMapping` owns authored per-operator controls shared by Scene/Game presentation and the CPU reference. Preserve linear HDR lighting and one final sRGB encoding. Changing the tone curve, exposure or diagnostic mode must not change GI source energy or direct-light settings. Existing Glow is still the current effect; a replacement bloom system, temporal AA and DLSS/FSR have not been implemented.

### Entity selection and actual hierarchy

- One authored entity has one Outliner row; capabilities appear together as ordered Inspector subsections, without outer empty/component rows or component-selection mode. `SceneOutlinerRows` and `tools/SceneInspectorSections.h` own this presentation. This does **not** flatten real spatial parenting: imported model hierarchies, explicit groups, visual attachments and collider children retain their entity IDs and affine local transforms.
- A Player is a composed actor, not a special entity class. Its direct following camera is edited inline; attached models/particles keep their own selectable rows. `sceneEntityOwner` must not remap arbitrary visual children to their actor. Reparenting a Box/model onto Player must retain visibility, selection, world placement and its real parent. Camera Follow retains its world offset and full translation-free affine world basis; camera edits do not move the controller. Nearest-actor lighting ownership stops at nested actors. Keep actor ownership, controller, input, navigation, Light Rig and Darkness Reveal independent.
- Scene Save writes schema v17; readers accept v1–v17 and convert older composed-actor/camera data in memory. Save alone writes the current representation. Keep Edit/Play copies isolated, entity IDs stable and all property/reparent operations transactional with undo/redo and cancellation. See [scene/actor architecture](docs/ENGINE_ARCHITECTURE.md#composed-actors-and-scene-migration).

### Quader imports, bundles and material slots

- `src/quader/` owns Crimson's integrated native reader/conversion/publication bridge; `assets/QuaderSceneBundle` and `ContentStorage` own durable storage and recovery. One Quader **project/scene pair** owns one tracked `.crimson-quader` bundle in Content, retaining immutable mesh generations and original model/member UUIDs. Individual mesh entities remain in the Outliner, each with its own native Collider child; collision triangles live in scene/history data, not separate imported model assets.
- Expanded glTF/manifest/buffer files belong only in Git-ignored `.crimson/cache/quader-imports/<bundle-id>/<model-id>/`. Startup reconstructs missing/corrupt expansions and member location mappings from the durable bundle, without Quader or its original source. Keep bundles, scenes, shared native materials/textures and authored reference policy durable; never treat the whole `.crimson` directory as disposable. Bundled mesh assets remain available in pickers; Explorer reveals their bundle and independent subasset rename/move/deletion is protected.
- Existing loose Quader packages migrate through the recoverable file/index transaction after storage recovery/UUID conversion and before stores/watchers. Preserve exact member bytes/IDs, aliases, material assignments, saved-scene bytes and unrelated files. Remove only proven empty former package directories. Warm initialization must not rewrite equal data. `crimson-content-migrate --project-root <root> --report <json>` invokes this same initialization headlessly for requested migration/maintenance; the old executable must not run against new bundle storage.
- Import preparation reads an exact bundle baseline; publication commits bundle, generated members and native material/texture changes with explicit UUID locations before the scene command. `QuaderImportResult::files` carries literal project-relative paths; `locations` carries explicit UUID registrations. Never derive member UUIDs from cache paths. Roll back the location index by its literal `.crimson/asset-locations.json` path and refresh the in-memory snapshot after failure. Retain policy/source/baseline rechecks and coherent prepared-model seeding in `EditorSession`.
- Bundles are resource dependencies: external bundle changes regenerate loader files before model invalidation. Store project-relative paths against the canonical project root on Windows; case-sensitive `lexically_relative` against a differently cased caller root can incorrectly emit `../Engine/...` and break publication. Do not globally recase the coordinator root without also addressing ContentStorage snapshot keys/revisions.
- A Quader mesh with one real material creates one slot. Add a default only for primitives that actually lack a material; do not merely hide an extra importer-created slot. Distinct real slot indices stay distinct even when they share a material ID/name. Legacy `legacyUnusedMaterialSlot` normalization removes only the proven unused trailing fallback and preserves real indices/overrides; model metadata cache v4 retains that marker. Keep the former fallback as a virtual identity-hash input so unchanged geometry reuses IDs. Native materials remain shared/editable, with independent Sync materials (default off) and Sync lights (default on) policies.
- Reimport preserves same-ID authored assignments; changed layouts remap only unambiguous source identities, dropping removed/ambiguous overrides in the same undoable subtree command. Missing metadata defers publication rather than declaring slots removed. Preserve Crimson-only capabilities, visibility/style, collider overrides and authored light roles on matching generated entities. `tests/quader_bundle_fixture.h` supplies valid shared fixtures; manifest buffer dependencies require `"index": 0`.
- Use short disposable project roots for migration tests: expanded paths plus atomic temporary suffixes can exceed Windows file-path limits in deeply nested diagnostics directories. Test regeneration by removing/renaming only the disposable import-cache subtree, with resolved absolute ownership checks; never delete authored Content to simulate a cache miss. See [the bridge/storage contract](docs/ENGINE_ARCHITECTURE.md#quader-linked-scene-bridge-and-mesh-collision).

- `test` and `configure` are alternative second arguments, not combinable flags. The executable is `build/Release/bin/crimson-renderer.exe`.
- The launcher builds only if its executable is missing. It does not check source freshness; build changed code before launching it.
- `Dev.cmd` builds/launches Debug. Use Release for ordinary handoffs and Debug when the task needs it. Close the running renderer before rebuilding its executable.
- Ask the user to save and close a running renderer only when implementation is finished and the integration build is ready to start. Never ask at task start or while implementation is still underway; the user may continue using the editor during that work. THIS IS REALLY IMPORTANT, that only the moment before you are need to launch the exe build command this is asked. DO NOT ASK if you are doing work that do not require compilation.

- Computer control, including mouse/keyboard automation and interacting with the user's applications, requires the user's permission. Noninteractive screenshots are allowed. Do not run routine native acceptance/capture suites or maintain `VERIFICATION.md` as part of feature completion.
- Documentation-only changes need consistency/link checks, not an application build. Routine handoffs do not need Debug/Release matrices, UI scaling matrices, or broad image suites.
- The capture script uses the current project and an existing binary. The separate `--editor-smoke` mode imports fixtures and changes saved material assignments; use it only for an import/assignment task that needs it.

## Repository constraints

- Put rendering implementation and shaders in `src/crimson-renderer/`. Keep editor panels and asset import/storage in their own boundaries; follow the architecture's current-versus-target ownership distinction.
- Keep `App` a composition/lifetime/frame-loop boundary. Scene editing belongs in `src/editor/`, dock views in `src/tools/`, and CPU world/history/storage in `src/scene/`; do not accumulate those implementations in the application loop.
- Public math values use Crimson types. GLM is an implementation detail behind `src/math/`; do not expose GLM, bx, bgfx, EnTT entity handles or ImGui types in serialized scene data. Keep explicit RAII owners and concrete dependencies rather than introducing a service locator or engine framework.
- Preserve imported assets, material factors/assignments, and `crimson_ui.ini`. Changes to their storage must retain existing project data.
- Application branding lives in `assets/branding`; `src/platform/CrimsonResources.rc.in` embeds the ICO. A user-supplied ICO is authoritative: embed it unchanged, and do not overwrite it by running the PNG converter. Use conversion only when the user requests generation from a PNG. SDL owns the native window-class icon lifetime. Keep branding out of the managed texture library.
- Treat generated headers and cached dependency sources under `build/` as read-only to manual edits. Change project sources/manifests/build configuration and let tools regenerate outputs.
- Rendering changes must preserve linear HDR lighting, one final sRGB encoding, and the grid/tools' independence from scene exposure. Texture roles determine color decoding and channels; follow the material contract in the architecture.
- Environment preprocessing belongs outside frame submission. Its derived cache is disposable; update preprocessing/BRDF versions when their equations or output conventions change. Preserve the managed source and `assets/environment.json`.
- Preserve explicit GPU/resource owners and release their resources before bgfx shutdown. Keep viewport input ownership explicit so editor widgets, navigation, and future player controls do not consume the same gesture.
- Construct ResourceManager before GPU owners. Worker jobs never call bgfx/ImGui or mutate documents; publish coherent CPU/GPU replacements on the main thread. Persistent AssetRef values are separate from live handles/snapshots and GPU leases. Count pending/retired allocations and drain readbacks before shutdown.
- Keep authored reference/deletion policy separate from runtime residency. Deletion is a staged project transaction; preserve stable IDs, protected role-correct defaults, project-wide saved-scene updates and unrelated unsaved edits. Legacy material/environment/preview files and virtual browser organization remain compatible.
- Use familiar asset fields adjacent to their property: picker, thumbnail/name, clear, and drag-and-drop with immediate assignment.
- Keep one Asset Browser catalog and one **Import** button for supported imports. Models, textures, environments and native scene assets share the browser; typed asset fields filter compatible assets.
- Scene entity IDs are persistent; EnTT handles are temporary. Preserve full affine local matrices and imported model hierarchies. Scene edits use transactional undo/redo, and scene saves atomically replace only the selected managed scene file.
- Keep Dear ImGui's default colors, font and sizing. Preserve docking state; do not introduce custom editor themes unless requested.
