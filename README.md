# Crimson Engine — crimson-renderer

Crimson Engine is a native Windows x64 editor and engine for a first-person action game. It uses C++20, SDL3, bgfx Direct3D 12 with an optional Direct3D 11 backend, EnTT, Jolt, Recast/Detour and Dear ImGui docking. The editor provides native scenes, static and animated glTF/GLB models, particles, lights, camera entities and a Play mode with a first-person WASD controller, mouse look, jumping and strafe camera tilt. A dockable Outliner, transform gizmos, Quader navigation and one shared asset library support scene authoring. Dear ImGui uses its default colors, font and sizing.

Project folder: `C:\Users\Drako\Desktop\_CRIMSON_ENGINE\crimson-engine`. The renderer is named **crimson-renderer**. Its canonical implementation and shaders live in the [`third_party/crimson-renderer`](third_party/crimson-renderer) submodule. Engine host adapters, ImGui/bgfx presentation and diagnostics remain in [`src/crimson-renderer`](src/crimson-renderer).

The current gameplay scope centers on direct first-person movement and an editor-adjustable camera, with DUSK and Quake as references for movement and camera feel. WASD movement, mouse look, jumping, lateral camera tilt and smooth stair traversal are implemented. Actors, enemy navigation, gameplay tags, Attributes and Gameplay Effects remain reusable engine systems; weapons and combat rules need their own agreed scope.

The authoritative [engine architecture guide](docs/ENGINE_ARCHITECTURE.md) separates implemented features from agreed architecture and future work. Scene authoring, resource management and first-person Play are implemented and awaiting broader user acceptance. Native materials have an independent editor with a live 3D preview and can be assigned per slot to Boxes and imported meshes. Imported glTF/GLB materials are editable under their existing shared identities; Save retains their assignments. Quader imports use editable native materials with independent material and light sync policies. glTF skeletons, GPU skinning, morph targets and clip playback are implemented; gameplay animation blending/state machines, retargeting, dynamic rigid bodies and particle collision remain future work.

The [current renderer and character lighting guide](docs/RENDERER_AND_CHARACTER_LIGHTING.md) maps ordinary scene lights, World/Character masks, shadows, environment illumination, GI/AO and shader contracts. Historical checkpoints retain their original scope.

The [large-scene performance implementation guide](docs/LARGE_SCENE_PERFORMANCE_GUIDE.md) records the Godot/Unreal source findings, measured regression baseline, implemented clustered Forward+ lighting and the remaining scalability stages with their before/after verification requirements. The [Forward+ checkpoint](docs/FORWARD_PLUS_CHECKPOINT.md) records correctness checks, measured costs and gains, raw result locations and reproduction commands.

Scene and Game render from one owned immutable frame with validated pass/resource plans and explicit leases. Ordinary scene lights use independent direct receiver and shadow caster scopes. Actor rigs, Darkness Reveal and Ambient Darkness have been removed; [the lighting guide](docs/RENDERER_AND_CHARACTER_LIGHTING.md) describes the current paths.

## Run and develop

Double-click **Launch Renderer.cmd** to open the existing Release executable immediately. The launcher builds only when that executable is missing.

**Dev.cmd** incrementally builds Debug and opens it. Close the renderer before rebuilding code that changes its executable. From a command prompt:

```bat
Build.cmd Release
Build.cmd Release test
"Launch Renderer.cmd" Release
```

The renderer is pinned as the `third_party/crimson-renderer` Git submodule from
[`qvertexworks/crimson-renderer`](https://github.com/qvertexworks/crimson-renderer),
at the same canonical commit consumed by Quader Public. Initialize submodules
explicitly after cloning with `git submodule update --init --recursive`. Configure
checks the recorded commit and matching bgfx package provenance without fetching
replacement source. The canonical submodule owns the bgfx overlay; the Engine's
local overlay continues to own Jolt. Use the pinned native presets and manifest
rather than copying dependencies from a renderer build directory.

The `test` suffix runs the registered checks, including hidden native GPU fixtures. Use `Build.cmd Release configure` after changing dependency or preset settings. Building requires MSVC x64, CMake and vcpkg; the script finds Visual Studio and uses `%VCPKG_ROOT%` or `%USERPROFILE%\vcpkg`. Routine builds reuse the local dependency cache. The executable is `build\Release\bin\crimson-renderer.exe`, with its runtime DLLs beside it.

**Direct3D 12 is the default renderer.** Choose **Edit → Preferences → Rendering → Renderer (restart required)** to select Direct3D 12 or Direct3D 11, then save your documents and restart the application. The preference is application-wide; its tooltip identifies the active backend. Both backends use the same lighting features and SM5/DXBC shader family, so switching alone does not recompile materials or change authored scenes. Vulkan is not exposed in this version.

**Edit → Preferences → Rendering → Antialiasing** selects **Off** or **SMAA**, default SMAA. Changes apply immediately to Scene, Game and material/particle previews. Asset cards use SMAA independently. SMAA 1x filters the tone-mapped scene before grid, collision and editor overlays; picking and raw numerical inspection remain unfiltered. It smooths visible edges without jitter or frame history. Temporal AA and temporal upscaling remain future work.

For recovery or a temporary comparison, launch the executable with an explicit backend. This overrides the preference for that process without saving it:

```powershell
& '.\build\Release\bin\crimson-renderer.exe' --renderer dx11
& '.\build\Release\bin\crimson-renderer.exe' --renderer dx12
```

Backend performance depends on the scene, GPU and driver. Selecting Direct3D 12 does not enable additional bloom, GI, antialiasing or upscaling features by itself.

The application embeds [`assets/branding/crimson-engine.ico`](assets/branding/crimson-engine.ico) unchanged for Explorer, desktop shortcuts, the taskbar, and the title bar. A user-supplied ICO is authoritative; replacing it requires a rebuild. The transparent 512×512 PNG in [`assets/branding/crimson-engine.png`](assets/branding/crimson-engine.png) is also retained. Use `.\scripts\Convert-AppIcon.ps1` only when generating a new ICO from a PNG is explicitly intended. Successful links notify Windows to refresh the application's cached icon. Run `.\scripts\Create-DesktopShortcut.ps1` to create or refresh the **Crimson Engine** desktop shortcut to the Release executable; this also refreshes its cached icon. `.\scripts\Refresh-AppIcon.ps1` repeats just the targeted icon notification when needed.

## Editor panels

- **Viewport:** rendered scene, model/light selection, transform gizmo and navigation, following its dock size.
- **Game:** the active scene Camera's live view, available in Edit mode and during Play. Dock it beside the scene or drag its title bar onto another monitor. It has its own camera and image size, with optional collision and route overlays controlled from Inspector.
- **Outliner:** rootless scene hierarchy, multiple selection, inline renaming and drag-to-reparent. Right-click an entity or empty space for creation, grouping, duplication and deletion.
- **Inspector:** selected entity name and a collapsible **Transform** section. **Position**, **Rotation** and **Scale** each have a horizontal **X**, **Y**, **Z** row with axis-colored strips. Rotation uses degrees; **Lock proportions** links scale changes. Drag a number or Ctrl+click to type; a completed edit is one undo operation. Light controls, mesh material slots and Environment controls live here. Stored affine transforms and imported model hierarchies remain preserved.
- **Asset Browser:** one **Import** button and one collection for models, textures, environment images, editable glTF/GLB materials, native materials, saved scenes, native particle effects and Gameplay Effects. **Create → Particle Effect** creates a saved starter effect in the current Content folder and opens its editor; **Create → Material** creates an editable material.
- **Particle Effect:** a floating, non-dockable effect document with properties on the left and an isolated preview on the right. Its top File, Edit and Environment menus match Material Editor, including Save/Save As and Undo/Redo. Drag its title bar outside the main window to move it onto another monitor; its preview and controls stay active there.
- **Material Editor:** a floating, non-dockable material document with a live preview above selected-node/material properties on the left and a node graph on the right. Its File, Edit and Environment menus own document actions and preview lighting. It can move onto another monitor independently of the docked panels.

A scale axis may be zero. This collapses the model and hides its draw; it remains an editable scene entity. After dragging a scale value to zero, release the mouse and press **Ctrl+Z** to restore the prior transform. The diagnostics panel can appear without taking focus from the Inspector. Confirm a typed value with Enter or leave the field before using scene undo; **Edit → Undo** also restores the prior transform. **Ctrl+Y** reapplies it. The collapsed-transform diagnostic clears when a nonzero scale is restored; it is separate from invalid/nonfinite data diagnostics. Active text fields retain their own text undo.

Use **View** to show/hide Game, Outliner, Inspector and Asset Browser; **Ctrl+Space** toggles the Asset Browser. The scene Viewport remains present. **View → Collisions**, **Grid** and **Transform Gizmo** toggle their overlays; Collisions is the master switch for collision wire and fill in both Scene and Game. These switches and panel visibility survive restart. Single-panel dock panes hide their tab bar automatically; tabbed stacks retain their tabs. Splitters resize panes and docking/layout, including Game, remain saved in `crimson_ui.ini`. The main window restores its size, position, monitor and maximized state. **View → Reset layout** restores the default arrangement. **Edit → Preferences** opens a draggable, resizable window without dimming or blocking the editor. Background and major/minor grid changes appear immediately; preferences are saved application-wide.

## Scenes and entities

Create a scene with **File → New scene** or the Asset Browser's **New scene** action, then drag model cards into the viewport to add independent entities. New scenes start empty with the built-in environment. Repeated placements share the imported model and GPU geometry while keeping separate transforms. Importing an asset only adds it to the browser. An imported model's internal node hierarchy remains unchanged.

Use **File → Save** or **Ctrl+S** to save the current scene; **Save as...** creates a separate scene asset. Scenes are stored beneath `Content` as versioned `.crimson-scene` files and appear beside other assets. Double-click a scene card, or choose **Open scene** from its context menu, to open it. Browser deletion removes the selected scene file while shared models, textures and other scenes remain available. Switching or closing a dirty scene offers Save, Discard and Cancel.

**Save as...** suggests a distinct name such as **Main Copy**. Saving a new scene or a Save As copy rejects an existing saved scene name, including ASCII case and surrounding whitespace variants. Older scenes that already share a name remain separate assets and can still be opened and saved normally.

Viewport clicks select the top-level assembled object through its actual parent hierarchy; use the Outliner to select individual children. Player-owned visuals/cameras select their Player. Ctrl-click toggles objects; Shift-click in the Outliner selects a range. Use F2 or Rename to edit a name inline. Drag Outliner entries onto another entity to parent them, or onto empty background space to unparent. Group/Ungroup preserve world placement, including mirrored and nonuniform transforms. Deleting an entity retains its subtree semantics; undo restores the exact records and stable IDs.

| --- | --- |
| T | Move the current selection |
| R | Rotate the current selection |
| E | Scale the current selection |
| F | Focus the camera on the current selection |
| Delete | Delete selected entities and their descendants |
| Ctrl + D | Duplicate selected subtrees |
| Shift + drag the Move or Rotate gizmo | Duplicate the selection and move or rotate the copies |

Shortcuts respect text entry, widgets and viewport navigation. Position, Rotation and Scale are grouped in the Inspector's collapsible **Transform** section. A single selected entity uses its origin as the gizmo pivot; multiple selections use their combined bounds center. Selected descendants follow a selected ancestor once. Orange selection boxes follow each selected root's orientation and fit its visual contents; auxiliary colliders do not enlarge a model's box. Each completed gizmo/property drag is one undo operation. Undo/redo keeps up to 256 scene commands, and the dirty marker follows the saved state even when undo creates a different editing branch. Selection, camera movement and focusing do not change saved scene content.

Hold **Shift before grabbing** a Move or Rotate handle to duplicate the selected subtrees. The copies appear once the pointer passes the drag threshold and the transform changes; releasing Shift during the drag keeps the same operation. Duplication and the completed transform form one undo step. Escape or losing viewport input cancels the gesture and removes its copies. Shift with Scale keeps ordinary scaling. Duplicate names follow Quader's numbered families across the scene: **Box**, **Box_001**, **Box_002**. Duplicating an already numbered object continues that family, and copied children receive unique numbered names too.

The Outliner shows one row per entity and preserves actual parent-child hierarchy, including Quader imports. Each imported Quader mesh contains its own collider entity. Models and particles attached to Player remain selectable child entities. Select a point light, model, Environment or other entity directly to see its full properties in Inspector subsections; components are never separate Outliner rows. The Player's supplied camera is edited in the Player Inspector. To organize rows by color, Ctrl/Shift-select entities, right-click a selected row and choose **Set Color**. **Apply** commits one undo step; **Cancel** or Escape leaves them unchanged. Colors save with the scene, do not inherit to children, and retain a visible selection cue.

Right-click the Outliner and use **Add** to create Box, Collider, Player, Camera, empty, directional-light, point-light or Environment entities. Add up to four directional lights and 4,096 point lights; edit their color, intensity and enabled state in Inspector. Point lights also have **Radius (m)**, initially 20 m: illumination falls smoothly to zero at that world-space distance, independently of entity scale. Existing scenes without a radius use the same default. A selected point light shows its center gizmo and influence sphere at this radius, without a selection box. Selection, light and other generic debug wires default to orange; collision shapes default to #39AFDDFF and transform axes keep their axis colors. Light position/direction comes from its transform. Directional lighting and its viewport arrow use the same normalized transformed local -Z axis. Scene loading preserves missing model references with diagnostics so saving cannot silently erase them. `.crimson/editor-session.json` stores the last saved scene, panel visibility and editor camera per scene, separate from scene content.

Local lighting uses clustered **Forward+**: GPU compute assigns light influence spheres to screen tiles and 24 logarithmic depth slices for each rendering camera. Tiles start at 32 pixels and grow at very large viewport sizes to keep the grid within its storage capacity while retaining light coverage. Surfaces evaluate their cluster's lights, including transparent meshes and lit particles. Dense overlap has no separate sixteen-light cutoff; its cost still grows with the number of influencing lights. Scene creation, save/load, Quader import share the 4,096-point-light capacity. Directional-light and shadow budgets remain separate.

### Scene lighting

Players and enemies receive ordinary point/directional lights and environment illumination. Light Rigs, Darkness Reveal and Environment Ambient Darkness have been removed. Existing scene files remain readable; their obsolete lighting settings are discarded in memory and omitted on the next Save.

Point and directional lights expose **GI Energy**, default 1 with a 0–16 range. It scales diffuse SSGI donor energy independently of direct brightness, specular highlights and shadows. Zero removes bounce from that source. The control supports Save, undo/redo and temporary Play edits.

All point lights expose **Attenuation**, **Near Falloff Radius (m)**, **Range Falloff**, **Edge Softness**, **Source Radius (m)** and **Specular Scale** after Radius. Godot-style Attenuation sets distance decay: **2** is inverse square (the preserved default), **1** is inverse distance and **0** keeps constant distance energy before the range window. Lower it for a broader light with a less concentrated center, then retune Intensity. Negative values increase energy with distance. Near Falloff Radius reduces the brightness peak close to the source. Lower Range Falloff values fade earlier across the range; Edge Softness sets the fraction of the radius used for that fade (1 uses the full radius). Source Radius controls the simulated emitter size: zero keeps the original point shadows, while a positive radius gives contact-hardening soft shadows and broader reflective highlights. Shadows remain sharper near the caster and soften farther away, including with Specular Scale 0. Specular Scale changes only this light's reflections; set it to 0 to remove its shiny blobs. Source Radius leaves the light's influence Radius and diffuse falloff independent. Existing lights preserve their appearance with source radius 0 and attenuation 2. Controls support scene Save, undo/redo and temporary Play edits.

For a shadow test, enable **Cast Shadows**, put a pillar or Box above a lit floor and compare Source Radius **0**, **0.25** and **0.5 m**. Look at both the contact and the far end of the shadow. Larger values increase the penumbra; a shadow's fully occluded center can remain dark. The positive-radius filter adds a bounded blocker search and filtering cost, so use it where softness matters.

The light Inspector's collapsed **Advanced Lighting** section contains independent direct receiver and shadow caster settings. Models keep their participation controls under **Model → Advanced Lighting**. Character means a model under its nearest Actor/Visual Root; other models belong to World. Changing direct receivers preserves the independent shadow-caster setting.

Quader reimport preserves these Crimson-only model scopes, light roles and GI Energy for matching source identities and light kinds. Geometry, transforms, source light properties and shadow flags continue following the bridge's existing synchronization policy.




For thin walls meeting at a corner, start with **Depth Bias 0 m / Normal Bias 1 texel**. The shadow comparison includes a numerical precision allowance even at zero Depth Bias. Increasing Depth Bias can open a visible gap at the join; point-shadow contact filtering preserves the authored offset.



Ordinary scene-light shadows still block only their own light. To let the player block a torch, enable its Cast Shadows and include **Character** under **Advanced Lighting → Shadow Casters**, alongside World when both should cast. Emission, Unlit materials and fog remain independent.

## Quader bridge

Use **Add → Quader** in the Outliner. In its **Quader** section, browse to a `.qproj`, choose the source **Scene**, and click **Import**. **Import Scale** defaults to 1. Imported geometry, enabled static mesh collision, materials/textures, and directional/point lights appear beneath the generated **Imported** child. Quader group names, object names, nested groups and sibling order are preserved, including empty groups; grouped objects retain their world placement. Spot lights and unsupported collision configurations are reported in the import status.

After the first import, **Auto sync on save** refreshes the link when Quader completes a normal scene/material save. Save the source scene once in Quader to initialize its completed-save records. Recovery autosaves do not trigger synchronization, and Save As does not rebind an existing link. Import and synchronization are inactive during Play and resume in Edit mode.

Import registers its visual model, material and texture files together in one asset-index update. Collision triangles are stored directly on native Collider entities in the scene, with no separate collision model asset. Short Windows file locks receive a bounded atomic retry; a failed import restores both the previous files and the editor's cached locations.

Reimport is one scene Undo operation. It replaces the generated subtree and preserves manually added siblings. Matching instance material assignments survive slot changes when the source material has a unique match. Overrides for removed or ambiguous slots are cleared automatically so import can continue; the new slots inherit their Quader materials. Undo restores both the previous import and its assignments. Imported collision starts as **Trimesh**. Changing that Collider to Cube, Sphere, Cylinder or Capsule preserves its native triangles; reimport retains the chosen primitive, dimensions, local center/transform, color and display settings while updating those retained triangles. Switching back to Trimesh uses the latest imported geometry. Save the Crimson scene normally to persist the link and result; reopening the imported scene does not require Quader or access to the original project.

Each Quader source scene has one tracked **`.crimson-quader` bundle**. Imported files are organized by the source scene name in lowercase snake_case: a scene named **Diablo Room** uses **`Content/diablo_room/models`**, **`materials`** and **`textures`**. Existing generated files in the former flat folders move into this layout on project load, retaining their IDs, material edits and scene references; manually moved assets keep their locations. Renaming the scene or type folders through the Asset Browser retains their asset identities; reimport and auto sync continue using those folders, including for newly added source assets. A texture already shared by several scenes keeps one file and UUID. Empty import folders are removed after asset deletion; unrelated contents are preserved.

Ordinary Quader objects each import their full geometry into a separate model asset, including identical copies. Only explicit Quader **Instance** occurrences share a model asset for the same source definition member. Every placement remains its own named entity with its own collider child. Renaming or moving the same object reuses its asset. Reimport converts former automatic geometry sharing to this rule while retaining older generations needed by existing scenes or history. On reimport, meshes removed from Quader also disappear from the generated hierarchy and model pickers. Geometry, UV or material-slot changes replace the current mesh generation in the pickers. Older geometry remains loadable while a saved scene, the open scene or Undo/Redo still references it; after those references are released, unused generations and their expanded files are removed automatically. This also handles removing every mesh from the source. Native collision data remains in the scene and its Undo history.

Expanded import files and LODs live under the Git-ignored **`.crimson/cache`** directory. Missing expanded files are regenerated from the bundle on project load; the original Quader project is only needed for a fresh source import or synchronization. Keep the bundle, scenes, native materials/textures and authored reference metadata in version control. Existing loose Quader imports migrate automatically to scene bundles through a recoverable storage transaction, retaining their model/member IDs and saved scene bytes. Current generated mesh subassets stay available in model pickers; their storage is owned by the bundle. **Show in Explorer** reveals that bundle. Individual mesh assets can be deleted with the Asset Browser's normal **Delete** action, including after their Quader entity has been removed. Deletion removes the selected mesh from its bundle and generated files, applies the normal reference/history handling and preserves other meshes and shared materials/textures. Deleting the final mesh removes the empty bundle and its empty models folder; importing the linked scene again recreates them. Independent subasset rename and move remain disabled.

After deleting imported assets, use **Import** again to bring the same Quader source back. Visual geometry, materials and textures receive fresh managed identities when their previous identities were deleted; native Collider data is reconstructed from the source. Repeated imports reuse that fresh generation; existing Crimson material edits still follow **Sync materials**. Old deleted references retain their replacement policy.

Quader materials are editable native Crimson materials. Select imported geometry and expand **Model → Materials**, then click **Open** for its material slot, or open the material from the Asset Browser, then edit and save in the Material Editor. Imports create only their source material slots; a mesh with one assigned material has one slot. A default is created only when geometry needs it. Older packages load with their unused extra fallback removed from the material table while preserving real slot indices and existing assignments; reimport reuses compatible packages. These materials are shared: editing one changes every object using that material.

The Quader entity has separate import policies, applied to both manual **Import** and **Auto sync on save**:

- **Sync materials** defaults off. Missing materials are imported the first time; existing materials and their textures are reused, preserving Crimson edits. Enable it to overwrite imported materials and textures from Quader on each reimport. Refresh waits while an affected material document has unsaved edits or an active gesture. A clean open Material Editor reloads the refreshed material. Scene Undo does not restore overwritten shared material files.
- **Sync lights** defaults on. Enabled, it imports and updates Quader directional/point lights. Disabled, it excludes Quader lights; the next reimport also removes previously generated Quader lights. Crimson lights outside the generated Imported subtree are unaffected. Reimport is required to apply a changed policy to the existing imported subtree.

Quader materials use Crimson's existing PBR response and point-light falloff, so lighting/diffuse-model appearance is not an exact cross-engine match.

## Directional shadows and animated materials

New directional lights enable **Cast Shadows**. Existing saved lights keep their previous Cast Shadows setting. Scene and Game use four stabilized cascades with extra detail near the camera, smooth cascade transitions and a fade at the far end of **Shadow Distance (m)**. Shadows follow each rendering camera's perspective as it moves and rotates; player-facing direction does not select a separate shadow map. Shadow Distance defaults to 100 m and is measured in depth from that camera. **Edit → Preferences → Rendering → Shadow resolution** controls point and directional map resolution together.

The directional light Inspector exposes **Shadow Angular Diameter (°)**, default **0.53°**, range **0–2°**. Zero gives filtered hard edges. Positive values keep contact shadows tight and soften them as caster/receiver separation grows; larger angles produce wider penumbrae. **Depth Bias (m)** and **Normal Bias (texels)** retain their authored controls. Offscreen geometry can still cast shadows into the view. Increasing resolution improves finite shadow-map detail and costs memory; increasing Shadow Distance spreads that detail over more space.

Softness has a bounded world-space radius shared by all cascades: it stops growing after one Shadow Distance of light-space caster/receiver separation. Farther casters remain eligible. The [current lighting guide](docs/RENDERER_AND_CHARACTER_LIGHTING.md#directional-shadows-for-first-person-cameras) describes the fitting/filtering contract and limits. The older [ARPG shadow checkpoint](docs/SHADOW_ARCHITECTURE_CHECKPOINT.md) retains historical measurements only.

The Material Editor's Add Node/search menu includes **Add**, **Lerp**, **Panner**, **Time** and **Power**. Lerp blends without automatically clamping Alpha. Panner accepts a UV Mapping and scrolls it using Time and Speed; use its Fractional Part option to wrap the displacement. Time defaults to game seconds, offers Ignore Pause and an optional Period, and animates previews without changing the material's saved values.

## First-person Play, actors and cameras

During Play, the Game view shows a compact metrics overlay in its top-right corner. Press **F1** while Game is focused to hide or show it. The readout updates about four times per second and shows FPS, frame time, main-thread CPU work, GPU frame time, device VRAM, tracked texture/program/model/shadow memory and engine draw calls. CPU/GPU timings and draw calls cover the whole editor frame, including Scene and Game. CPU work excludes the explicit frame/presentation wait; Device VRAM is the driver's device-wide figure and may include other applications. Unsupported GPU counters display **N/A**. The overlay does not intercept gameplay clicks or save anything into the scene.

Use **Add → Box** for a visible unit cube with a shared built-in mesh and the protected default PBR material. Its transform can stretch, rotate and place it as a floor or obstacle. A mesh does not add collision automatically. Right-click the Box and choose **Add → Collider** to create a child Collider entity, or create/reparent a Collider through the Outliner. **Inspector → Collision → Shape** offers **Cube**, **Sphere**, **Cylinder**, **Capsule** and **Trimesh**. Cube exposes local XYZ **Size (m)**; Sphere exposes **Radius (m)**; Cylinder and Capsule expose radius and **Height (m)**. Capsule height includes both rounded caps. Static shapes are centered on the Collider entity; resize and offset this child independently of the visual. Parent scale applies once. The scene grid is a visual guide and never acts as a physics floor.

Select a primitive Collider directly in the Outliner to show its Godot-style dimension handles in the scene Viewport. Drag a Cube face or a Cylinder/Capsule end to resize while keeping the opposite face/end fixed; hold **Alt** to resize around the original center. Radius handles resize around the center. Each drag is one undo step; **Escape** or losing focus restores the original dimensions and transform. **View → Collisions** also gates these handles. Trimesh uses the original geometry selected through **Source**, its model picker or a model drop; switching to Trimesh initially uses a model on the Collider or its closest model ancestor when available. It has no numeric dimensions or resize handles. Switching shapes retains inactive dimensions, the source reference and native triangle data. Quader collision imports store their exact triangles directly on the native Collider entity, shown as **Imported collision**; they create no separate model asset.

Collision overlays respect scene depth, so walls and other opaque geometry hide the wires behind them. Collision fills and wires use a surface depth correction to avoid flickering where they overlap visible floors or walls. Unselected shapes are faint; selecting a Collider makes it clearer. Cube shows twelve edges. Trimesh shows boundaries, sharp creases and curved silhouettes, with flat triangulation lines removed. This changes only the debug display; the collision mesh keeps its original triangles.

Select a Box or imported mesh and open **Inspector → Model → Materials** to change an individual material slot. Drop a material from the Asset Browser onto a slot, or use its picker. **x** restores that slot’s source material; **Open** edits the assigned material. You can also drag a material onto a mesh in the Scene viewport: the surface under the pointer previews the replacement, and releasing assigns it to that mesh’s material slot. Moving away or pressing **Escape** cancels the preview. Hovering does not dirty the scene or add undo history; dropping creates one undo step. Assignments survive save/reopen and duplication, and each instance keeps its own slots while sharing geometry. Scene and Game use the assignments. Meshes and particle sprites share ordinary materials; both shader models and all four blend modes are supported. A new shader or texture may need to finish preparing before its hover preview appears; the existing surface stays visible while it loads.

**Inspector → Model → Shading** is independent for each mesh occurrence, including objects sharing the same asset. **Use Mesh Normals** preserves the authored normals and is the default. **Flat** lights each rendered triangle independently. **Smooth** recomputes normals within the existing hard-normal boundaries and reconstructs the normals of DX12 height displacement, removing its triangle faceting while retaining sharp box edges. Shading changes neither geometry nor collision. Smooth prepares a shared auxiliary normal buffer on demand; animated meshes reconstruct it after deformation. Save, undo/redo, duplication and Play retain the choice. See the [implementation and measured cost](docs/MESH_SHADING_CHECKPOINT.md).

Use **Add → Player** to create one Player entry in the Outliner with a first-person camera. Select it to edit input, controller collision and Movement, Camera and Visuals in Inspector subsections. The camera starts at eye offset `(0, 1.65, 0)` m, looks along local **-Z**, and uses **75° Vertical FOV**, **0.05 m Near** and **2048 m Far**. Existing player and active-camera selections are retained; otherwise the new player and camera become active. WASD movement and jumping need collision geometry and require no Navigation Agent, Navigation Volume or bake. **Add → Enemy** retains controller, Movement, Navigation Agent, rig and reveal capabilities without Player Input or a supplied camera.

Selecting an entity shows its name, visibility, Transform and every applicable property section together. There is no component-selection mode and no extra component row to expand first. **Make Player** in Player Input changes who receives Game controls. Removing a required capability through its Inspector section removes dependents in one undo step. Enemies use the same movement and navigation implementation; runtime commands supply their destinations or velocities.

Use the Player Inspector’s **Visuals** section to assign or attach models and edit their local alignment, materials, animation and rendering properties. Attached models and particles retain their own selectable Outliner rows and independent transforms; dragging a model onto Player preserves its world placement and keeps it selected. The supplied follow camera is edited inline in the Player's Camera section. Explicit groups remain separate user-created groups. Each actor’s Key/Fill affects its owned visuals, and Local World illumination uses the shared scene-light budget.

**Movement** appears directly after Transform. It owns Enabled, Jump Height, Ground Acceleration, Ground Friction, Air Acceleration, Air Control, Strafe Tilt, Tilt Response and Stair Smoothing. ## Attributes and gameplay tags

The bottom **Cmd** bar accepts console commands. Type to show autocomplete above the field; **Tab** or clicking a suggestion fills it, and **Enter** runs it. **Up/Down** recalls recent commands, with Down returning to the unfinished draft after the newest entry. History lasts for the editor session.

During Play, run **`ShowDebug Attributes`** to toggle a top-left Game overlay showing the target's runtime Current values as `Health | 100`, `MaxHealth | 100`, and so on. The target has a yellow wire bounding box. It starts with the designated player, or the first Actor; **Tab** cycles forward and **Shift+Tab** cycles backward while Game has keyboard focus. Command entry returns focus to Game. Targeting does not change the Outliner selection. Stop clears the overlay and its target; each new Play session starts with it off.

The attribute pool is a fixed native C++ catalog available to every entity. Effects supply values; entities have no attribute allowlist or membership configuration. New Players use the catalog through their **Player Defaults** effect gives Vitality and Spirit 50 each and MovementSpeed 5, producing 100 Max Health and 100 Max Mana. New Enemies use **Enemy Defaults**, which gives MaxHealth 100 and MovementSpeed 5. Applying an effect with +25 Spirit to an enemy immediately gives it Spirit 25 and updates the native MaxMana and ManaRegen calculations.

Use **Add Component → Effects** to add the ordered **Starting Effects** array. Select an Effect asset beside each entry, drag it from the browser, use **Open** to edit it, **X** to remove it, or the arrows to reorder it. There is no separate Attributes component or picker to enable a stat: an effect can modify any attribute registered in the native catalog on any entity. Starting effects run once when the entity enters Play. Repeated entries apply according to that asset's stacking rules. Changing the list during Play takes effect on the next spawn/restart.

Choose **Asset Browser → Create → Gameplay Effect** to make a reusable `.crimson-effect` asset. Its editor has Duration, Modifiers, Stacking and Tags sections, plus the shared File/Edit menus, undo/redo, Save and Save As. A property drag is one undo command; Escape cancels it. Modifiers choose a supported Stats attribute, operation and literal or native C++ calculation. For starting values, make an Instant effect with Override Vitality/Spirit or MaxHealth modifiers, then assign it to Starting Effects. Duplicate an effect into Content for different enemy capacities; actors sharing an effect share its future application settings. Engine starter effects are protected and can be duplicated.

Health and Mana spawn full after starting effects establish their capacities. Deliberate starting damage/healing is respected: MaxHealth 100 then Health AddBase -10 starts at 90. Vitality adds 2 Max Health and 0.05 HP/sec per point; Spirit adds 2 Max Mana and 0.10 Mana/sec per point. These formulas stay in C++. Capacity growth during Play retains the current resource amount; shrinkage clamps excess. Health can go negative for overkill, and native Health Regen stops at zero or below. Mana stays at or above zero. MovementSpeed has no upper gameplay limit; zero pauses commanded movement while retaining route intent.

An **Instant** effect changes Base permanently. **Has Duration** or **Infinite** with period zero modifies Current while active; removal restores the evaluated result without that modifier. A positive **Period** applies permanent Base pulses for damage/healing over time. Execute on Application schedules the first pulse after startup; durations and periods round up to simulation ticks. Built-in regeneration continues once per tick, and a periodic heal is additional healing. Effect edits affect future applications; active effects retain their captured definition and magnitudes.

**Stacking** is configured per asset: independent instances, aggregation by source or aggregation by target, limit, duration refresh/extend, period reset, expiration and overflow rules. Limit zero is unlimited. To refresh a buff without increasing strength, use Aggregate by Target, limit 1, allow overflow and Refresh on Successful Application. Additive multiply modifiers combine as percentage bonuses; compound multiply modifiers multiply separately.

During Play, use **`ApplyEffect "My Effect"`** or **`ApplyEffect <UUID>`** to apply an effect to the yellow debug target. Use **`RemoveEffect "My Effect"`** to remove all its active instances on that target. It cannot undo damage or healing already executed by instant/periodic effects. Asset names autocomplete; duplicate names require a UUID. Run ShowDebug Attributes first, and use Tab/Shift+Tab in Game to choose the target. The designated Player supplies source captures, or the target supplies them if there is no Player.

Older scenes convert numeric attributes and the retired membership representation to initializer effects in memory, preserving authored values. Loading does not rewrite the scene. Saving materializes the pending effects and scene together; subsequent saves use only effect references, with no authored attribute membership. Missing or corrupt effect references remain identifiable and report a diagnostic. Runtime reads of untouched known attributes resolve their native defaults. The overlay shows attributes introduced by effects and their native formula results; zero values remain visible after activation. Stop discards runtime values, active effects and the debug target. Abilities, equipment, costs/cooldowns and combat actions remain future work.

Use **Inspector → Add Component → Tags** to assign native gameplay tags through searchable chips; click a chip's **x** to remove it. Only C++ creates tags. Pickers can restrict choices to a hierarchy such as `Stats`. Attributes use their `Stats.*` tags as identifiers without automatically adding those tags to the entity's Tags component. Hierarchical matching lets `Stats.Health` match `Stats`; exact matching requires the full same tag. Explicit parent and child chips remain separate selections. Missing native identifiers remain saved and display a diagnostic so they can be removed or replaced deliberately.

## Collision layers and triggers

Open **Edit → Collision Layers** to name the project's 32 collision layers. Every name is editable, including the initial **World**, **Player**, **Enemy**, **Trigger**, and **Character** names. A slot's number is its identity: renaming it updates Inspector labels without changing saved collision bits, navigation, or actor roles. Blank names display a numbered fallback. Use the settings document's shared File/Edit menus for Save, undo/redo and Close; Escape cancels a name-edit gesture. Names live in `.crimson/collision-layers.json`, separately from scenes and application Preferences. Opening missing settings uses defaults without creating a file; saving handles external changes explicitly.

**Character Controller → Layers** selects what the capsule belongs to, and **Mask** selects the layers its movement detects. New players use Player, enemies use Enemy, and generic controllers use Character; their masks initially accept all layers. Filtering is directional, as in Godot character motion: a player that stops scanning Enemy can move through enemies, while an enemy that still scans Player continues detecting that player. Both objects must stop scanning one another for their movement to ignore each other in both directions. Explicit layer changes remain authored; changing the designated player or Enemy behaviour does not rewrite them. Capsule dimensions and traversal limits still belong to the shared Agent Profile.

Solid level geometry remains common to all characters in this slice. Solid Colliders always include the first layer, initially named World, and every controller's Mask retains that layer. The required checkboxes are checked and locked, with labels following project renames. Solid static Collider masks are All. Other layer memberships remain useful to filtered queries and detectors. Renaming World does not remove its reserved solid-world role. Different navigation through selectively ignored walls is not implemented.

Set **Collider → Mode** to **Trigger** for a Cube, Sphere, Cylinder or Capsule detection volume. Resize it using the existing shape controls and handles. Trigger Layers identify the detector; its Mask selects what it observes. A detector scanning Player detects that capsule even if the player does not scan Trigger. Parent a primitive Trigger Collider beneath an actor to make a following detection sphere or other sensor. A sensor excludes its owning controller and that owner's other sensors. Trimesh remains Solid. Mode/filter edits save with the scene and support the normal undo/redo and cancellation workflow; Quader refresh preserves them.

Trigger volumes never block movement or enter navigation baking. The C++ `PlaySession::triggerEvents()` batch contains Enter/Exit values for all fixed ticks executed by the latest advance, with world/tick identity, trigger/other entity IDs, and Motion, Initial, Configuration or Removed reasons. The batch remains valid until the next advance or Stop; reading it does not consume it. `triggerOverlaps(entity)` returns the current detected entity IDs. Starting inside emits an Initial Enter; edits and teleports update endpoint membership; removal emits a Removed Exit. Stop/world replacement clears observations without gameplay exits. Detection samples overlaps at fixed ticks; crossings entirely between ticks and continuous rotating-trigger detection are outside this slice. No Inspector overlap monitor, scripting or automatic gameplay action is added.

`PlaySession::raycast` accepts a `PhysicsQueryFilter` with a layer mask, ignored entity IDs and world/character/trigger inclusion flags. Generic queries include world and controller capsules by default, while trigger queries are opt-in. World-surface queries can explicitly exclude characters and triggers. Character blocking does not add crowd avoidance: enemies can queue or jam while their requested routes remain active.

## Enemies

Use **Add → Enemy** to create an actor with a capsule Character Controller, Movement, Navigation Agent, and **Enemy** behaviour section. Assign visuals as for the player. The controller uses its shared Agent Profile; include that profile in the level NavigationVolume's **Supported Agent Profiles** so moving behaviours can find routes.

Choose **Inspector → Enemy → Behaviour**:

- **Idle** keeps the enemy still, with gravity and ground contact active.
- **Chase Player** follows the scene's designated player, updates the route as the player moves, and stops at capsule contact, including on ramps. A route that stops making progress or finishes short of the player is retried from the enemy's current position at a bounded interval. No player means the enemy waits.
- **Random Move** chooses reachable navigation points within **Radius (m)** of its position when the behaviour starts. After arriving, it waits for a random duration between **Min Wait (s)** and **Max Wait (s)** before moving again. Defaults are a 5 m radius and a 1–3 second wait. Changing behaviour or deliberately teleporting the enemy starts a new roaming center; ordinary movement does not move that center. A zero radius keeps it still.

Enable **Navigation Agent → Show Route** on each enemy to display its remaining route in Game. Behaviours run during Play, use the existing route/Motor/Jolt pipeline, and wait for navigation preparation without treating it as an arrival. Behaviour, radius, and wait settings save with the scene and support undo/redo; live targets, roaming centers, random sequences, and wait timers are temporary Play state. Motor/Navigation disabling pauses automatic movement. Explicit C++ actor commands take priority until cleared or the Enemy configuration changes. The designated player retains player control even if it also has an Enemy component. Combat, perception, and crowd avoidance remain future work.

## Navigation volumes and agent profiles

Add **NavigationVolume** from the scene's **Add** menu to define navigation coverage. A level supports one active volume. Its full XYZ bounds include eligible surfaces on multiple floors, and rotation changes the inclusion boundary. The volume supplies no collision or floor: walking surfaces still come from static Colliders. Existing levels require adding and resizing a volume manually.

Select the volume and drag its six face handles to resize it. A normal drag holds the opposite face fixed; **Alt** resizes around the center. Each drag is one undo step and **Escape** cancels it. Inspector also exposes **Dimensions**, **Baking**, **Supported Agent Profiles**, **Preview Agent Type** and build status. Baking defaults to 0.10 m horizontal cells, 0.05 m height cells, 128 cells per tile and 0.5 contour simplification error. Background tiles update during editing, with changes coalesced while dragging and the final state requested on release. Green shows current baked surfaces; amber shows pending replacements.

**View → Navigation Mesh** shows or hides those surfaces in **Scene**. The setting changes display only; the selected volume can still be resized while its baked mesh is hidden. **Preview Agent Type** chooses one supported profile to inspect and does not change any actor's behavior. The initial choice is the player's supported profile, otherwise the first supported profile. Game retains the Navigation Agent's independent **Show Route** display.

Create a **Navigation Agent Profile** in the Asset Browser's **Create** menu. Double-click it to edit **Capsule Height**, **Capsule Radius**, **Maximum Slope** and **Maximum Step** in its own File/Edit document. Use **Save As** to copy the protected **Default Agent**, whose values are 1.8 m, 0.30 m, 45 degrees and 0.30 m. Profile files are shared project assets: editing one changes all assigned actors and its prepared navigation. Standard pickers, Open, clear/default and drag-and-drop are available beside assignments. Assign the profile under **Inspector → Navigation Agent**, or **Character Controller** for a controller without navigation. The same profile controls the physical capsule and traversal limits; disabling Navigation Agent leaves physical behavior intact.

Add every required profile to the volume's **Supported Agent Profiles** list. New volumes collect profiles already used by scene controllers, or Default Agent in an actor-free scene. Supported profiles can bake before enemies exist. An actor whose profile is absent from the list cannot request a route and reports the missing setup. Missing or corrupt custom profiles keep their assigned identity instead of silently acquiring a different capsule.

Navigation is prepared in tiles on resource workers and published on the main thread. Actor movement, new destinations and lighting edits reuse existing tiles. Collider changes invalidate nearby tiles; affected routes pause while rebuilding and retain their destination. Preparing tiles are distinct from unreachable ground, so a temporary tile boundary does not become a false stopping point. Generated data is disposable under `.crimson/cache/navigation`; authored volumes and profile assets save normally. Legacy custom controller sizes are retained through profile conversion, with new profile files materialized safely when the converted scene is saved.

The current navigation domain is bounded to 2,048 tiles per profile and 2,048 polygons per tile, with additional cell/height limits reported in diagnostics. Stable source updates, profile preparation/readiness and point projection provide integration points for future streamed or procedural geometry and spawned enemies. Level streaming, procedural generation, combat/perception, crowd avoidance and off-mesh links remain future work.

## Point-light shadows

Select a point light and enable **Cast Shadows** in Inspector. Shadows are initially off on new lights and older scenes. Up to sixteen eligible point lights receive resident maps, prioritized by squared distance from the player focus divided by light radius squared; persistent IDs resolve ties. Without character geometry, the editor camera's target supplies the priority origin. A selected light can have any source index within the 4,096-light scene capacity. Other lights retain their direct illumination. Per-light resolution remains future work. Boxes and imported model entities have their own **Cast Shadows** and **Receive Shadows** switches, both initially on. These switches affect that entity's meshes, not its children. Character visuals cast normally; Collider shapes, capsule outlines, the grid and particles do not cast shadows.

Shadows follow moved lights and geometry in both Scene and Game, including live Play edits. Geometry outside the camera view can still cast into it. Opaque and alpha-cutout materials cast their visible silhouettes. A shadow blocks only its point light: environment illumination and emissive materials remain visible. Use actual mesh geometry for the receiving floor; the editor grid is an overlay.

**Edit → Preferences → Shadow resolution** selects 256, 512 or 1024 pixels per cube face; 1024 is the default. A light needs six faces. Point storage reaches about **387 MiB** at sixteen lights and 1024 pixels; directional maps add to the shared allocation, and saved-scene thumbnails use a separate smaller atlas. Static maps are cached. At most four complete dirty point maps (24 faces) update in one world frame, shared by Scene and Game; deferred age prevents starvation. Pending caster-only changes can retain the previous coherent map briefly, while a new/moved light stays unshadowed until its complete replacement is ready. Scene diagnostics show deferred work, rendered faces, cached lights, world/character projection updates, caster draws and atlas memory. [Reading the Shadows diagnostics](docs/SHADOW_DIAGNOSTICS.md) explains every field, the expected eight-light states, memory accounting and practical checks.

The light's advanced bias controls address surface artifacts: **Depth Bias** defaults to 0.005 m and **Normal Bias** to one shadow texel. Increase bias cautiously for self-shadow speckling; excessive bias separates shadows from their casters. **Source Radius** zero uses the original small fixed filter; a positive radius enables contact-hardening soft point shadows, sharper near the caster and softer farther away. This works with **Specular Scale** zero and does not enlarge the influence Radius. Translucent meshes and particles can receive shadows but do not cast them. Shadow properties participate in scene Save, duplication and undo; Play changes are discarded on Stop.

## Particle effects — Steps 1–4

Choose **Create → Particle Effect** in the Asset Browser. The saved starter needs no import: it emits procedural unlit additive sprites from one point emitter, starting at rest with downward gravity. Double-click an effect card to open it again. Initial velocity launches a particle once at birth; gravity accelerates it continuously. Positive launch direction Y makes it rise before negative Y gravity reverses it. Use **Clear speed** to restore a falling effect, then **Frame** to fit its trajectory. The properties use four top-level sections, with collapsible subsections:

| Section | Controls |
| --- | --- |
| **Emitter Update** | **Timing & emission:** Enabled, Playback, Delay, Rate, Explosiveness, Duration and Capacity. **Simulation:** World/Local space, Pre-process and Seed. |
| **Spawn** | **Shape**, **Initial velocity** and **Lifetime** define where each particle starts, how it launches and how long it lives. |
| **Update** | **Forces:** Gravity, Acceleration and Drag, with enable/remove controls and Add behavior. |
| **Render** | **Material**, **Orientation**, **Color & opacity** (including Brightness), **Size** and **Rotation**. Constant, Random Range and Curve modes stay beside the property they affect. |

- **Spawn → Shape** offers Point, Cone, Sphere and Box. Cone starts on an XZ disk with **Radius (m)** and uses the launch direction/spread below. Sphere fills its radius; Box uses full **Dimensions XYZ (m)**. Selecting Cone or Sphere supplies a useful Direction and Speed setup that you can then edit. **Emitter Update → Timing & emission → Rate (particles/s)** sets the average emission budget. **Explosiveness** concentrates that budget toward the cycle start: 0 emits steadily, 0.5 emits during the first half, and 1 emits the whole cycle together. With Rate 30 and Duration 2 s, all three settings schedule 60 particles per cycle, subject to capacity/work limits.
- **Spawn → Initial velocity** shows **Direction XYZ**, **Speed**, **Spread (degrees)** and **Flatness** together. Spread zero launches straight; larger values spread around the normalized direction. Flatness zero gives three-dimensional spread; one flattens it into a fan in the emitter-local plane through the launch axis and its perpendicular tangent. Flatness changes launch directions, not sprite geometry. **Outward from shape** instead uses each sampled radial direction, with Spread and Flatness still applied around it. Lifetime and speed offer Constant or Random range with minimum/maximum fields. **Emitter Update → Simulation → Seed** controls repeatable variation; Restart reuses it. Opening an older Vector/Fixed effect derives these controls for display without changing its saved launch behavior; conversion occurs only when you deliberately edit a launch control.
- **Emitter Update → Timing & emission → Playback** offers Continuous, One shot and Looping. **Delay (s)** waits once before the first cycle. One shot emits for **Duration (s)**, then drains; Looping repeats that duration without repeating delay. Continuous with Explosiveness above zero repeats the displayed **Cycle Duration (s)**; at zero it keeps the ordinary continuous rate. Burst-list authoring has been replaced by Explosiveness.
- **Emitter Update → Simulation → Pre-process (s)** simulates the effect before its first draw, so a fireplace or smoke plume starts populated immediately. Try a value around the particle lifetime, such as 2 s. Zero keeps ordinary startup; supported values are 0–60 s, rounded up to a 60 Hz tick. Preview, scene placement/opening, Play startup, Restart and Play Effect all finish pre-process before exposing that starting state. It uses the authored seed and initial emitter transform, including ordinary delay, explosiveness, forces and looping; a short one shot may have drained by the requested time. Larger values and particle counts can increase startup work. Pause retains the prepared state; Stop clears to zero, and Play repeats preparation. Ordinary color edits, moving the emitter and saving do not repeat warm-up. Preview camera and playback actions do not dirty the asset.
- **Update → Forces → Add behavior** adds Gravity, Acceleration or Drag. Each has an enable checkbox and Remove action; disabled/removed behavior settings remain available for undo or re-adding. The editor keeps the behavior order valid. **Drag (1/s)** damps velocity; larger values slow particles faster.
- **Emitter Update → Simulation → Simulation space → World** leaves spawned particles detached and interprets gravity/acceleration on world axes. **Local** makes particles follow the emitter and its parents, with forces in emitter coordinates. The full affine transform affects positions and launch velocity; sprite size stays in world meters in both modes.
- **Render** contains collapsible **Material**, **Orientation**, **Color & opacity**, **Size** and **Rotation** sections. Material and Orientation start open; the other appearance sections start collapsed. Size and Rotation offer Constant, Random Range or Curve, using world meters and degrees within the chosen particle plane. The horizontal axis is normalized particle age, from birth at 0 to death at 1. Random Range gives each particle a repeatable value. A zero Size in Curve or Random Range mode hides the sprite without killing it; Constant retains its positive minimum.
- **Curve** uses an interactive plot: MMB pans, the wheel zooms and **Frame** fits the authored curve. Double-click empty plot space to add a key; select/drag keys or edit their numeric Age/Value. Right-click for key actions, or hover the focused plot and press Delete to remove its selected key. Plot navigation changes only the view. The **...** menu provides Add/Remove/Reset; Linear/Constant interpolation remains available.
- **Orientation → Billboard** offers **Disabled**, **Enabled** and **Y-Billboard**. New effects default to Disabled: **Orientation XYZ (degrees)** rotates the sprite plane relative to the emitter, and the existing Rotation track adds in-plane spin. World-space particles retain the emitter frame from their birth; Local-space particles follow its current frame. Emitter scale/shear does not stretch the sprite. Enabled faces the camera; Y-Billboard uses a world-Y-constrained facing plane before in-plane spin. XYZ values remain stored while billboarding is enabled. - **Color & opacity** uses a compact swatch; expand it for linear RGB and independent opacity, or click for the color picker. For smoke, choose **Unlit / Translucent**. Connect **Texture RGB → Emissive Color** and **Texture A → Opacity**. For a hard cutout, choose **Masked** and connect alpha to **Opacity Mask** instead. The effect editor has **Save**, **Save As**, **Undo** and **Redo**. The isolated preview starts automatically. **Pause** freezes it, **Play/Resume** continues it, **Restart** clears and repeats the authored seed, and **Stop** clears particles and returns time to zero. Select its marker or Outliner row, transform it with T/R/E and focus with F. The Inspector's adjacent picker, drag-and-drop and clear controls assign an effect; **Edit Effect** opens its document and **Play Effect** restarts that selected instance. Multiple placements have independent playback. Moving an emitter preserves already spawned world-space particles; later births use its new transform. Duplication, deletion, hierarchy and scene undo/redo use the same entity controls as models. Saving the scene retains authored references and transforms, independently of effect saving.

Valid effect-property drags update the isolated preview; committing publishes the working definition to scene instances. Color, opacity, size, intensity, orientation, billboard mode and rotation modes/values, appearance ranges, curve keys and gradient stops update existing particles immediately, including while paused, without clearing particles or changing their clocks. Switching modes retains inactive authored curves/ranges/gradients. Material assignment and committed texture/color/blend edits replace prepared appearance without restarting simulation. Failed preparation retains an available working material and reports the affected dependency; an initially unresolved appearance omits sprites while simulation continues. Gravity, acceleration, drag and behavior enable/removal apply on the next simulation tick; rate and emitter enabled state apply to subsequent emission. Shape, launch direction/velocity, speed and lifetime ranges apply to new particles, so existing particles keep their birth values. Capacity changes clear live particles while preserving elapsed time, emission phase and Play/Pause/Stop state. **Seed, simulation space, timing and explosiveness edits replay from zero while retaining Pause/Stop state.** Undo, redo and cancellation follow the same rules. Opening a different effect or using Restart/Play Effect starts it again. Saving does not reset playback.

The editor continues playing while either its main window or a detached editor window has focus. When all editor windows lose focus or none can draw, particle time is suspended; restoration skips the suspension interval. Closing a detached particle window closes its document with the usual dirty-file prompt. Mouse/key events belong to their originating window, so navigating the particle preview cannot move the scene camera. Playback state and live arrays never enter scene or effect files. Scenes write version 23 while continuing to read versions 1–23; missing Glow settings start disabled.

The CPU simulation uses 60 Hz ticks, at most eight catch-up ticks per frame, 4,096 scheduled births and 32 scheduling segments per tick. Excess births/segments are counted and do not build a future backlog. Each emitter supports a configured capacity of 1–65,536; scene runtime admits up to 256 instances and 262,144 configured particle slots. A transactional restart or capacity replacement may briefly hold one additional emitter reservation of at most 65,536 slots; reusable presentation buffers are separate. Rendering accepts up to 65,536 packets per view and may omit additional packets when the GPU transient buffer is full. Preview and scene diagnostics explain dropped work and particles cleared by capacity changes. These are work limits, not frame-rate promises. Asset deletion can replace an effect reference or clear it while retaining the emitter entity; close the effect document before deleting its managed asset.

Transparent particles sort back to front across effects, including Alpha/Additive overlap, and batch only consecutive compatible materials. They depth-test against models without writing scene depth. The solid editor background remains independent of exposure; dark smoke can attenuate exact white. Particle RGB is stored and interpolated in linear HDR; opacity remains linear. One tone map applies to combined premultiplied HDR color, so intense translucent emission may saturate at display white. Material thumbnails use a sphere; the protected particle default uses a quad. Particle files write version 9 and read versions 1–9. Files before v9 retain camera-facing billboards; files before v8 default Explosiveness to zero. Old burst schedules remain compatibility data until an explicit Explosiveness edit replaces them with the new schedule; loading and ordinary saves preserve them. Pre-process defaults to zero for v1–v6. Earlier SDR colors decode once on load, preserving their appearance and all existing intensity animation, timing, launch settings and material references. Appearance defaults remain Constant, rotation zero and inactive tracks empty for v1–v4. Files before v4 receive Flatness zero; v3 Outward clears its formerly ignored Spread to retain radial appearance. Material files write version 6 with earlier readers retained. Loading never upgrades files on disk; explicit Save or an authorized asset transaction performs writes.

For fire or glowing sparks, raise particle **Brightness** above 1 or use HDR RGB colors, then enable **Glow** on the active scene Environment. This single effect scatters the complete visible HDR image: the sun, bright reflections, strongly lit surfaces and emission. Its main controls are **Intensity**, **Blend Mode**, **Spread**, **Highlight Threshold** and **Tint**. Glow works with Environment Lighting disabled and needs no HDRI or special particle material. It adds an image-space halo; use a light or GI when the source should illuminate nearby surfaces.

**Glow → Levels** has seven independent 0...1 contribution sliders: Level 1 is tightest and Level 7 widest. Each controls its own amplitude, so halving an isolated level halves its HDR contribution. They are not normalized together. Intensity scales their sum; all zero disables Glow. **Advanced** contains Saturation, Threshold Softness, Anamorphic Stretch and Low/High Quality. Negative Stretch elongates vertically; positive elongates horizontally. High is the default for small moving highlights. A procedural sun or HDRI highlight must actually be visible to produce its disk halo.

**Blend Mode** offers **Additive**, **Screen**, **Soft Light**, **Replace** and **Mix**. Additive is the default. Mix exposes an amount slider retained across mode changes. Additive, Mix and Replace compose in HDR; Screen and Soft Light blend separately tone-mapped Glow with linear display color after editor-matte composition. Changing modes adds no filtering pass. Zero Intensity or Spread disables Glow in every mode.

The Particle and Material Editor **Environment** menus have independent preview Glow controls; those settings remain transient. The active scene Environment saves Glow for Scene and Game. Old separate Glow/Bloom settings convert once in memory into full-scene Glow, preferring active Bloom and otherwise retaining Glow's style. Loading never rewrites or dirties scenes. The next explicit Save writes only current Glow with direct levels. Asset Browser thumbnails omit Glow. Grid, tools and the empty editor matte do not generate highlights. The shared multiscale filter supports wide halos without growing Gaussian sample counts; Spread changes the filtered base footprint while reconstruction keeps fixed sample spacing. At Spread 1 and zero stretch, High starts half resolution and Low quarter. Smaller Spread can use up to full resolution, so tighter halos can increase memory and GPU cost.

Steps 1–4 are implemented. The next [particle roadmap](docs/PARTICLE_SYSTEM_PREWORK.md) milestone is **Step 5: Layered effects and timeline**, for multiple emitters, timing tracks, paused Step and bounded preview seeking. Each current effect still has one emitter. Particle collision remains later work: the engine's existing Jolt Play/character world does not simulate particle gravity or collisions. Flipbooks, stretched sprites, mesh particles and GPU simulation also remain planned.

## Materials

Choose **Create → Material** in the Asset Browser to create a saved native material. New materials start **Lit (PBR) / Opaque**, with **roughness 1**, **metallic 0** and **0.5 gray** in the color picker, represented by starter parameter nodes. The floating Material Editor has a preview above properties in the left column and the material graph on the right. Drag either splitter to resize the panes, or drag the title bar to another monitor.

Select a node to edit its properties. Click empty graph space or the preview image, or select **Output**, to show material properties. Every material supports **Lit (PBR)** and **Unlit**, with **Opaque**, **Masked**, **Translucent** or **Additive** blending, on meshes and particle sprites. Lit exposes Base Color, Roughness, Metallic, Specular (default 0.5), Normal, Ambient Occlusion and Emissive Color. Unlit labels its radiance input Emissive Color. Model switches preserve blend mode and inactive connections. **Opacity Mask** is active only for Masked; **Opacity** is active only for Translucent/Additive. Inactive coverage pins remain dimmed with their connections retained. Cutoff, double-sided rendering and AO strength remain material properties.

For glass, select **Lit (PBR)** and **Translucent**, then enable **Output → Material → Refraction**. Keep **Opacity** at 1 for a fully covered glass surface and use **Transmission** to control how much dielectric diffuse lighting becomes transmitted background. Lower **Roughness** for clear glass or raise it for frosted glass; **Normal** changes the optical surface as well as its lighting. **IOR** controls bending and dielectric reflection together, replacing Specular while Refraction is active. Metallic suppresses dielectric transmission. Every optical input supports ordinary graph connections and a retained disconnected default.

| Glass input | Default | Meaning |
| --- | --- | --- |
| Transmission | 1 | Fraction of dielectric diffuse lighting replaced by transmission, from 0 to 1. |

Lowering Opacity fades the whole surface, including its reflections. Disabling Refraction or choosing another shader/blend retains its values and links; returning to Lit/Translucent restores them. IOR 1 removes interface reflection, distortion and transmission blur while retaining any authored volume absorption.

To use a height map on a mesh, select **Output**, enable **Material → Tessellation**, set a Texture 2D node to **Linear Data**, and connect its **R** output to **Height**. **Displacement Amount** defaults to 0.1 mesh-local units before object scaling; negative values reverse the relief. **Midpoint** defaults to 0.5 and selects the height that stays on the original surface. **Tessellation Factor** defaults to 8 and uniformly subdivides each triangle edge; higher factors increase geometry and GPU cost. **Advanced → Height Texture LOD** selects a smoother mip for displacement, default 0. Height is bounded to 0–1 before displacement; its disconnected fallback is 0.5. Disabling Tessellation retains the Height connection and restores ordinary geometry. This uses DX12 hardware tessellation in Scene, Game and mesh material previews. DX11 and particle sprites retain ordinary rendering with the authored settings preserved. Collision remains the original CPU geometry.

The size slider uses **16, 32, 64, 128, 256 and 512** pixel ticks, defaulting to 128. Dragging several models into the viewport places them as one undoable operation. The browser opens in **Content**, the physical root for game assets. **Project** exposes its sibling **Engine** root for protected engine defaults. Creating a folder creates the same directory on disk; renaming or moving a card moves its file or complete model package. UUID references remain stable. Browser names and directory IDs are recorded in `.crimson/browser.json`.

Right-click an asset or empty browser space for **Import**. It uses the same importer and the active folder captured when the file dialog opens. Newly imported model, image and material cards are placed together in that physical Content folder; reused assets retain their existing folders and aliases. An asset's context menu also offers **Open at Location**, which reveals its physical file in Windows Explorer, **Copy Path**, which copies that file's absolute parent directory, and **Copy Name**, which copies the displayed name or alias without its extension. Models reveal their retained source document inside the managed package, with the normalized model or package manifest as a fallback. Copy Name remains available for named built-in assets; filesystem actions require an available physical file.

## Import and assign textures

1. Click **Import** in the Asset Browser or its right-click menu. PNG, JPEG, TGA, BMP and Radiance HDR are supported alongside glTF/GLB models; multiple files and mixed asset types can be selected. HDR images are environment sources. The destination is the active Content folder when the dialog opens. Each file imports independently, with failures reported in the browser.
2. Files are copied into the active Content folder. Collisions receive a suffix rather than overwriting a different file.
3. Existing sphere material controls retain their texture pickers under **Albedo**, **Roughness**, **Metalness**, and **Normal strength** in the legacy preview/diagnostic mode. Picking or dragging a compatible thumbnail onto a field assigns it immediately. Scene environment fields accept compatible environment images.
4. Adjust tint/factors. Albedo, roughness and metalness maps multiply their factors; first assignment to an empty slot makes the factor neutral (white or 1). Replacing a map preserves the factor; **Clear** removes only the map. Normal assignment preserves its strength.

Albedo samples sRGB color. Roughness and metalness sample red-channel linear data. Normals sample linear RGB tangent-space data with **+Y/OpenGL green**, oriented along the mesh's increasing V direction. **Normal strength** ranges from 0 to 2; zero gives the original smooth surface, and a flat `(128,128,255)` map is neutral. **Reset material** clears maps and restores original values. Imports, material factors, normal strength and assignments survive restart. Asset references are UUIDs; `.crimson/asset-locations.json` records their physical locations. Older material files are converted when read.

Three tiny example textures are included from the earlier smoke check: checker albedo, roughness ramp and metalness stripes. Textures upload on first use and are cached; thumbnails preserve aspect ratio. HDR thumbnails use tone mapping for display without changing the imported source.

## Import and place models

1. Use the same **Import** action and select a `.gltf` or `.glb` file. The Assimp importer copies the model and required buffers/images into a managed model package directory beneath `Content`. Its newly created model, image and material cards appear together in the active Content folder captured when the dialog opened. Reused asset cards keep their existing placement and aliases.
2. Drag the model's card onto the viewport. A temporary model previews placement on the `y=0` grid; releasing queues creation when its resources are prepared. The model keeps its authored scale, orientation and internal node transforms. Failed models report a cause without removing existing scene content.
3. Drop additional models to add more entities. Select a placed model, use T/R/E to transform it and F to focus it. Save the scene to retain placements across restarts.

Managed models reopen even after their original source folder moves or disappears. Failed imports leave the working scene intact. Open imported materials from the browser or **Model → Materials → Open Material**. Save edits the existing shared material, so all users of that material update together. Its imported origin is provenance; it does not prevent editing. Reimporting identical model content reuses its managed package and preserves existing material edits. Changed source content imports as a separate package with separate materials. **Save As** creates an independent material. The source glTF/GLB and packaged geometry remain unchanged. The older preview, sphere material and environment settings remain preserved under `.crimson/` for compatibility; scenes use their own versioned persistence.

Importing an unchanged model again reuses its existing managed asset, textures and materials, including models imported before this behavior was added. Identity checks include the document and every required buffer/image; changed content creates a separate asset without overwriting existing placements. Names alone do not identify models. Existing duplicate packages are retained so their saved references remain valid.

Supported models use triangle geometry, hierarchy transforms, UV0/UV1, vertex colors, metallic-roughness PBR, normal maps, emissive, occlusion, double-sided surfaces and opaque/alpha-cutout/translucent materials. Missing normals are generated flat; missing normal-map tangents use MikkTSpace. Texture wrapping, all six glTF minification modes, magnification filtering and UV selection are retained. Derived mesh LODs and texture mips stream progressively; selecting a model requests original geometry and native texture detail. Rendering and picking share the same prepared snapshot.

Models can contain skeletons/inverse bind matrices, up to eight skin influences per vertex, morph POSITION/NORMAL/TANGENT targets and node/morph animation clips. STEP, LINEAR and CUBICSPLINE interpolation are supported. Select a placed model and open **Model → Animation**: choose a Clip instead of **Bind Pose**, enable Playing, and tune Loop, Speed and Start Time. Start Time is an offset in seconds from the clip's first key. Changing the clip or Start Time restarts that model's transient clock; pausing or changing Speed preserves its position. Animation previews run in Edit mode and Play; Play starts its own clocks and Stop restores the authoring session. Save stores these controls, not the current clock or joint poses. Existing scenes remain in Bind Pose until a clip is selected.

GPU skin/morph deformation runs once per presented pose and is shared by visible geometry, picking, depth and shadows. Deforming geometry uses original LOD0 until deformation-aware simplification is implemented. Animated mesh collision, root-motion extraction, blending/state machines, retargeting, animation events and skeletal editing are separate work. Importing an unrigged model does not generate a skeleton or clips. Points/lines and required unsupported extensions are still rejected; imported cameras/lights and optional unsupported extensions retain diagnostics. Draco/meshopt compression, KTX2 and advanced material extensions remain later glTF coverage.

## Environment lighting

Create an **Environment** in the Outliner and select it to edit its settings in Inspector. The first Environment becomes active; additional nodes and duplicates remain inactive until **Make Active** is used. The Outliner identifies the active node. Deleting it clears activation; other Environment nodes stay inactive and built-in studio defaults with exposure 1 take over. Undo restores the node and its activation together. New scenes remain empty, using those defaults without inserting an Environment entity.

Choose **Source → HDRI / IBL** or **Procedural Sky**. **Lighting** controls distant illumination and reflections; **Intensity** scales the selected environment. Switching sources preserves both sets of settings and the HDRI assignment. **Post-processing** groups Exposure, Tone mapping, Debanding and Glow.

**Ambient Light** controls diffuse environment illumination separately from sky reflections. **Source → Sky** preserves the existing HDRI/procedural diffuse lighting and offers **Color**, **Sky Contribution** and **Energy**. Sky Contribution **0** uses only the chosen color; **1** uses only sky irradiance; intermediate values blend the two. Energy scales the custom color, following Godot's Environment behavior. At contribution 1, change the environment's **Intensity** to adjust sky lighting instead. **Source → Color** uses the color and Energy without sky contribution, even with the environment's Lighting toggle off. **Disabled** removes diffuse ambient illumination while keeping independently enabled sky reflections and direct lights. Ambient Light receives the existing material occlusion; it does not illuminate Unlit materials. These controls save with the Environment and support undo/redo and temporary Play edits. Older scenes retain Sky with contribution 1 and energy 1, preserving their previous appearance.

**Reflections → SSR** enables current-frame screen-space reflections on Lit Opaque, Masked and Translucent meshes and sprites, including glass at full Transmission. Each receiver uses its own material Normal, Roughness and reflectivity. SSR replaces the valid part of the distant environment reflection; misses retain that environment. Unlit and Additive materials do not receive SSR. Visible opaque/cutout geometry supplies reflected radiance; other transparent objects, hidden/offscreen geometry, the editor matte and overlays do not. Planar reflections remain unimplemented.

| Reflection control | Default | Effect |
| --- | --- | --- |
| SSR | Off | Enables local screen-space reflection independently of Environment Lighting |
| Strength | 1 | Blend from environment fallback to valid screen hits; zero bypasses SSR work |
| Quality | Medium | Low/Medium/High use 1/4/12 rough reflection rays, with up to 64/128/256 hierarchy iterations per ray; very smooth surfaces use one ray |
| Max Distance (m) | 50 | Maximum reflected ray distance |
| Max Roughness | 0.6 | Roughness limit, with a smooth fade to the environment |
| Depth Tolerance (m) | 0.05 | Required depth agreement at a hit; excess tolerance can leak through thin geometry |
| Ray Bias (m) | 0.002 | Origin offset that reduces self-intersections |

SSR traces a deterministic min/max depth hierarchy. Rough materials sample different visible-GGX reflection directions and filter each ray's remaining footprint; uncertain hits retain the environment reflection. The result fades toward the environment from half the Max Roughness value to the cutoff. The opaque source stores linear view depth directly alongside radiance, avoiding device-depth quantization and an SSR-only geometry prepass. Combined glass retains an early readable-depth prepass for transmission. It has no temporal history, so it adds no history lag; visible-surface limitations and pixel-scale changes can remain during motion. Reflection donors are captured before SSR, avoiding recursive screen feedback. Glass refraction is captured afterward and can show SSR on opaque objects. Scene, Game, independent previews and saved-scene thumbnails own separate inputs. Settings retain disabled tuning and use ordinary undo/redo, Save and temporary Play edits; older scenes keep SSR off. At 1080p, an active view uses about 79 MiB for SSR radiance/depth pyramids and scratch, plus optional GI/AO/refraction readable-depth storage. Eligible surfaces add one reflection draw; glass uses three adjacent draws when SSR is enabled.

**Global Illumination → Enabled** opts Scene and Game into screen-space diffuse bounce lighting (SSGI), without a lighting bake. Visible ground, walls and props can exchange light. Open levels do not require ceilings, but surfaces behind the camera or hidden by other geometry cannot supply bounce. Keep ordinary sky/ambient illumination for the distant light foundation. Increasing Bounces extends paths through visible surfaces; it cannot recover offscreen geometry.

Point lights contribute through the surfaces they illuminate. **Indirect Lighting** hides their direct light pools: a point-lit flat floor alone has no diffuse self-bounce. GI can brighten a darker or shadowed surface when a nearby illuminated surface faces it; the point's Radius controls direct influence, while GI Max Distance bounds the reflected path. GI does not apply a uniform fill across the point's range. For a clear point-light comparison, illuminate a visible nonmetallic wall or prop side facing another nearby surface. Hidden prop sides and surfaces faded by occluder transparency do not supply this screen-space bounce.

The collapsed **Global Illumination** section provides:

| Control | Default | Effect |
| --- | --- | --- |
| Enabled | Off | Enables SSGI independently of environment Lighting |
| Intensity | 1 | Reflected-light brightness, from 0 to 4; zero bypasses GI |
| Reach (m) | 3 | Distance visible surfaces can exchange light per bounce, from 0.1 to 20 m |
| Quality | Medium | Low/Medium/High ray/step presets or Custom |
| Use Defaults | — | Restores the recommended GI tuning in one undoable edit, keeping Enabled unchanged |
| Advanced → Bounces | 1 | One to four diffuse reflections; additional bounces increase noise and GPU work |
| Advanced → Stability | 0.90 | History reuse, from 0 to 0.98; higher values reduce flicker and respond more slowly |
| Advanced → Samples Per Pixel | 4 at Medium | Rays per half-resolution pixel, from 1 to 16; editing selects Custom |
| Advanced → Ray Steps | 16 at Medium | Marching steps per ray segment, from 8 to 64; editing selects Custom |
| Advanced → Ray Bias (m) | 0.02 | Origin offset from the receiver, from 0.001 to 0.5 m |
| Advanced → Thickness (m) | 0.1 | Depth hit tolerance, from 0.01 to 2 m; excess tolerance can leak through thin surfaces |
| Advanced → Filter Extent | 4 | Filter extent, from 0 to 4; default filtering at steps 1/2/4 spans seven half-resolution pixels |
| Advanced → Smoothing | 1 | Spatial-filter amount, from 0 to 1; zero preserves unfiltered samples |
| Advanced → Radiance Clamp | 10 | HDR sample brightness limit, from 0 to 100; zero disables the clamp |

Use **Use Defaults** to apply the calibrated tuning to an existing Environment; loading preserves its saved values. Medium retains four rays and sixteen steps. High is a more expensive option for difficult small bright sources. The [SSGI quality and cost audit](docs/SSGI_QUALITY_AUDIT.md) records the research, controlled comparisons and GPU measurements behind these choices.

GI reconstructs lighting across frames and filters at several spatial scales while respecting surface boundaries. Rigid mesh movement, including instanced occurrences, reprojects each surface's own prior position. Newly revealed surfaces rebuild their history; skin/morph deformation still uses conservative rejection. Authored lighting-energy changes accelerate history response. Some noise and temporal lag can remain, especially for small bright emitters and surfaces becoming visible. These GI motion vectors do not enable temporal antialiasing or recover offscreen lighting.

The separate collapsed **Screen Space Ambient Occlusion** section adds contact shading from nearby visible geometry. **Enabled** defaults off. **Strength** defaults to 1 with a 0–2 range; **Radius (m)** defaults to 0.5 with a 0.05–5 m range; **Quality** defaults to Medium with Low/Medium/High choices. SSAO attenuates indirect lighting and can be used independently of SSGI . Zero Strength bypasses its work.

For dark interiors, keep ambient fill low and light the room with local sources and their SSGI bounce. SSAO also attenuates SSGI, so ambient Energy can remain zero when bounced light supplies enough fill. To tune a small uniform fill, choose Ambient Light Source **Color** and hold exposure fixed; in Sky mode at Sky Contribution 1, environment Intensity controls sky lighting and the custom-color Energy does not reduce it. SSAO adds local contact shading rather than room-wide darkness.

SSGI and SSAO settings save with the Environment, support undo/redo and temporary Play edits, and retain tuning while disabled. Existing scenes without them keep both off. The removed GI method wrapper converts its common and screen-space tuning in memory; loading does not rewrite the file. Material/Particle Editor previews and Asset Browser thumbnails omit both effects.

Scene and Game each have a **top-right render-view dropdown**: Lit, Albedo, Roughness, Metal, Normal, Direct Lighting and Indirect Lighting. Lit is the normal result. Albedo/material channels and world-space normals ignore exposure, tone mapping and fog; lighting views isolate direct or indirect contributions and retain the Environment's exposure and tone curve. Selections are independent per viewport and temporary. ACES can clip weak isolated indirect light to black even when adding that light produces a visible change in Lit. For this case, compare GI on/off in Lit or temporarily inspect with Linear tone mapping while keeping exposure fixed.




**HDRI** has the existing adjacent image picker, clear button and panorama drag-and-drop, plus Y **Rotation**. Radiance HDR supplies linear radiance; PNG/JPEG/TGA/BMP panoramas decode as sRGB color. Clear returns to the built-in studio. Image preparation runs on workers under `.crimson/cache/ibl`; a working environment stays visible while a replacement is prepared. Intensity and rotation reuse its prepared resources.

HDRI background and sharp reflections retain source detail through a source-sized radiance cubemap: a 2k panorama uses 512-pixel faces, 4k uses 1024 and 8k reaches the 2048-face limit. The base level preserves source radiance with texel-footprint antialiasing; lower levels contain GGX-filtered reflections. The complete FP32 cube costs about 32, 128 or 512 MiB at those sizes. Rough filtering uses a bounded integration grid during preparation, and the derived cache is reused afterward.

**Procedural Sky** provides collapsible **Sky**, **Ground** and **Sun** sections. Top Color/Bottom Color and Horizon Color blend using separate Curve values, initially 0.15 for Sky and 0.02 for Ground. Choose an existing directional light in **Sun → Directional light** to link its direction, color and intensity. None leaves the gradients without a sun; a disabled light keeps its assignment but hides the sun. **Size (deg)** is the angular diameter, initially 0.5°; Halo Extent starts at 30° and Halo Curve at 0.15. The visible sun, ambient illumination and roughness-dependent reflections update when the linked light moves or its settings change. Sky colors remain artistic values: rotating the light does not automatically create a physical sunset. Scene and Game use the same prepared sky for each frame.

**Background → Show Background** displays the selected HDRI or procedural sky independently of Lighting. Turn it off to retain environment lighting behind the editor's background color. With Show Background off, **Custom Color** enables a scene-specific solid color; otherwise the color from Preferences is used. This solid color is independent of exposure and tone mapping. Newly created Environment entities show their background; older scenes keep their previously hidden background.

**Fog** adds independent artistic haze. **Enabled**, **Mode**, **Color** and **Light Energy** are shared controls. It starts disabled in Exponential mode. Light Energy starts at 1 and scales the fog color's radiance without changing opacity.

- **Exponential** uses **Density**, initially 0.01 per meter. Higher density blends surfaces toward the fog color more quickly with camera distance. Distance starts at the camera, including a follow camera's offset from the character: density 0.02 gives about 63% fog at 50 meters, while 0.002 gives about 10%.
- **Depth** uses **Start (m)**, **End (m)**, **Curve** and **Max Opacity**, initially 10, 100, 1 and 1. Fog eases between Start and End; Curve adjusts that transition and Max Opacity caps its distance contribution. An End of 0 follows the rendering camera's far plane. A positive End must exceed Start.
- **Height (m)** and signed **Height Density** work in both modes. Density 0 disables height fog; positive values fill below the chosen world height and negative values fill above it. Distance and height fog combine using the greater opacity, so height fog can exceed Depth's Max Opacity. Switching modes preserves their inactive settings.

**Sky Affect** (0–1, default 1) controls how much fog covers the sky or empty background. **Aerial Perspective** (0–1, default 0) blends fog Color × Light Energy toward the sky's color along the viewing direction. **Sun Scatter** (0–1, default 0) adds a broad bright lobe toward enabled directional lights. These controls follow Godot's color/scattering model. Aerial Perspective also affects fog on surfaces and particles, reusing the existing environment source independently of its illumination Enabled switch.

Alpha particles retain their opacity; additive particles fade with fog without adding a sheet of fog color. Fog affects rendered surfaces, particles and the background before exposure and tone mapping. Background opacity uses the same distance/height response at the rendering camera's far distance, scaled by Sky Affect. Reducing Exponential Density fades it continuously; Density 0 with Height Density 0 restores the original sky or solid background exactly. Sky Affect 0 leaves the background clear while retaining fog on finite surfaces. Independent height fog can remain active at zero Exponential Density. The grid and editor overlays remain independent of fog and exposure.

To exclude a material, open it in the Material Editor, select its **Output** node or click empty graph space, and turn off **Material → Receive Fog**. This disables both distance and height fog for every mesh or particle using that material. It works with Lit and Unlit shading and every blend mode, saves with the material, and supports undo/redo. Existing and new materials receive fog by default. For a black cutaway wall, use an **Unlit**, **Opaque**, pure-black material with **Receive Fog** off on the exterior faces; interior faces can keep a separate fog-receiving material. Depth, opacity and shadow casting remain independent. Glow can still spread over the surface. Keep **Sync materials** off on a Quader link to retain this locally authored setting across reimports.

Environment settings and the explicit Sun reference save with the scene and support undo/redo. Versions 1–23 remain readable; explicit Save writes version 23. Scenes before version 6 use HDRI, no Sun link, a hidden background and disabled Fog. Version-6 fog keeps its existing Exponential appearance, with height fog disabled and Light Energy 1. Missing GI settings default off. Deleting a linked directional light clears its Sun reference, and undo restores it. Material and Particle Editor preview lighting stays independent, while saved-scene thumbnails use the saved Environment with GI disabled.

Environment and direct lights accumulate in linear HDR before exposure and tone mapping. The grid and tools keep their own brightness. IBL supplies distant illumination and reflections; it does not supply local reflections or occlusion. Point lights have optional mesh shadows as described above. Rough metals may darken from the GGX model's missing multiple scattering, and the split-sum approximation loses accuracy at grazing angles.

The Environment Inspector's **Post-processing → Tone mapping** controls Scene, Game and saved-scene thumbnails. **Linear** preserves linear values until display clipping, **ACES** provides filmic contrast, and **AgX** compresses bright saturated colors more gently. ACES and AgX follow the local Godot source's SDR implementation. **Reinhard (legacy)** remains the default to preserve existing scenes. Exposure scales scene lighting before the selected curve; it remains separate from the curve controls. The renderer encodes to sRGB once at presentation.

The selected operator exposes its relevant controls:

| Operator | Control | Default | Range and behavior |
| --- | --- | --- | --- |
| Reinhard | White Point | 0 | 0–64; zero retains the existing unlimited Reinhard response, positive values set the HDR input that reaches display white |
| ACES | White Point | 1 | 1–64; sets the HDR white reference used to normalize the fitted curve |
| AgX | White Point | 16.29 | 2–64; controls highlight compression toward the HDR white reference |
| AgX | Contrast | 1.25 | 1–4; changes the curve's contrast around middle gray |

Linear has no curve parameters. Switching operators retains each operator's tuning. White Point is measured after exposure, so changing exposure still changes where scene values fall on the curve. Settings save with the Environment, support undo/redo and temporary Play edits, and retain the previous appearance when older scenes omit the parameters. Material and Particle Editor Environment menus expose the same operator controls for their independent preview environments; editing a preview does not change the scene's tone curve.

**Debanding** adds a small display-space dither before the final 8-bit image is stored, reducing visible steps in smooth gradients. It defaults off, saves with the Environment and supports undo/redo. It applies to Scene, Game and saved-scene thumbnails; independent material, particle and model previews do not inherit it.

Raw texture thumbnails display source color, while rendered previews include lighting and tone mapping. Material cards use fixed key/fill lighting; the live Material Editor uses its chosen HDRI. Match environment, exposure and tone mapping when comparing appearances across views. Base-color/emissive textures decode sRGB, scalar/normal maps remain linear, and final rendered thumbnail PNGs are displayed without decoding them a second time.

## Asset deletion and shared resources

After dropping a model into the viewport, keyboard focus follows the placement. **Delete** in the viewport, Outliner or Inspector removes selected scene entities as one undoable edit; the model asset stays in the browser. **Ctrl+Z** restores the entities.

To remove asset files, focus the Asset Browser and press **Delete**, or use its context menu. Deleting a Content folder includes its recursive contents. Confirmation shows asset/folder counts without listing the selected names; zero-count categories are omitted. Only surviving usable saved resources trigger a dependency warning. **Dependencies and replacements** starts collapsed and shows only the assets with those external dependencies. Multiple instances in one saved scene count as one owner; unsaved placements, undo history, editor bookmarks and archived sphere/environment settings do not count as saved dependencies. Resources being deleted together are excluded from those warnings. Cancel leaves assets and documents intact. Validation runs in the background before a staged transaction publishes the change.

Without a chosen replacement, ordinary image slots use a solid 50% gray texture, normal slots use a neutral tangent-space normal, environment images use studio, and materials use linear gray albedo `(0.5, 0.5, 0.5, 1)`, roughness 1 and metallic 0 without maps/emission. Imported glTF/GLB material assets are editable and retain stable IDs. Replacement material UV/tangent requirements are validated against every affected primitive. Deletion mappings persist, so deliberately removed package images/materials do not reappear on restart.

Deleting a model without a replacement removes its referencing entities from every saved project scene and from the active document separately. Unrelated descendants survive with their world placement preserved. Independently usable package images and material assets remain available. The confirmation discloses any active undo-history reset; existing unsaved edits are not written into saved scenes. Deletion is a project operation outside entity undo. Files use a recovery journal and same-volume quarantine for rollback/interrupted-operation recovery.

Models, materials and scenes have rendered thumbnails. PBR material cards show the actual material on a shared UV sphere with a fixed camera and key/fill lighting, following Godot's material-preview setup; sprite-compatible materials use a quad. Authored linear factors, packed channels, UV selection, normal maps, emission and alpha cutout use the normal model shader. Model previews use isolated studio lighting; scene saves queue a preview from the saved editor camera. Older scenes receive a bounds-framed fallback. New or changed assets prepare previews in the background. Returning to a folder reuses resident thumbnails immediately; restarting hydrates validated cached PNGs before preparing source models or environments. Preview preparation has a small frame budget, and disposable caches live under `.crimson/cache`.

The CPU ResourceManager uses typed asset references, live-interest handles and immutable version snapshots. Two workers load/decode/process resources while GPU owners publish prepared replacements on the application thread. Texture mips begin with a complete coarse allocation of at most 64 pixels along the longest edge. Mesh caches retain exact LOD0 and safe attribute-aware derived levels. Visible demand refines shared resources; selected models request native detail. The default soft targets are 512 MiB CPU, 512 MiB aggregate managed GPU and a 64 MiB thumbnail sublimit, with five-second idle retention. Live leases remain valid above these targets. Uploads are chunked toward 4 MiB/approximately 2 ms per frame, rather than treating those targets as a hard backend-call limit.

Managed authoritative assets and the selected engine shader family are watched with a 200 ms debounce. Release compiles materials from `shader-tools/shaders` and `shader-tools/include` staged with its executable; source-checkout shader edits take effect after rebuilding Release. Debug can watch a complete live source/include pair, with the staged pair as fallback. Caches, temporary staging and archived import originals are excluded from asset watching. Valid replacements publish coherently; invalid or disappeared files produce diagnostics and retain the last working resource. Clean externally changed scenes can reload between gestures; dirty scenes offer **Reload / Keep editing / Save As**. Saving over externally changed content requires conflict resolution. Shader compilation/interface failures retain embedded or last working programs. Shutdown stops watching/requests, cancels and joins CPU/compiler work, drains readbacks and releases GPU owners before bgfx.

Reports distinguish CPU preparation/submission/frame time, deduplicated GPU queries, renderer-owned bytes and DXGI process residency, including actual GPU query coverage and missing frame IDs. The pinned bgfx statistics API publishes only its latest completed query; when several finish between reads, intermediate timestamps are unavailable. The benchmark requires the requested number of actual samples and never counts duplicates. CPU frame timings include the hidden primary-window Present and normal queue backpressure, with VSync off on both APIs. GPU timestamps cover submitted scene/compute work. The fixtures exclude editor UI, game simulation, asset IO and visible desktop composition latency; synthetic stress results do not predict gameplay FPS.

The benchmark keeps optional per-view GPU profiling off and uses bgfx's ordinary primary presentation cadence without an additional native DX11 flush. GPU timestamp elapsed time can include gaps while the CPU feeds the queue; it is not an active-GPU utilization measurement. The [measured DX11/DX12 comparison](docs/RENDERER_BACKEND_COMPARISON.md) records the local RTX 4090 results, workload, memory, image comparisons and timing limits.

Brightness / Contrast, Sharpen, Height to Normal, RGBA Merge/Split and Alpha
Merge/Split. Search the add-node menu by these names. Use explicit RGBA outputs
for packing; connect alpha to Opacity/Opacity Mask when it should affect coverage.
Packed data textures use Linear Data. See [the node workflow and contracts](docs/MATERIAL_IMAGE_NODES.md).


**Resize** materializes a processed image branch at an explicit Width and Height (1–4096). Choose Nearest, Linear or Area filtering; Area is useful for reducing resolution. For example, connect `Texture → Desaturation → Levels → Resize → Height`. This is cached image resampling, so increasing resolution cannot invent source detail. The initial version accepts static UV0 branches. Empty adaptable image inputs show both grayscale and color capabilities; connected inputs, output connectors and wires show their actual type. R/G/B/A components share the Scalar color. Compatible image-to-scalar inputs connect directly without inserting conversion nodes. See [Resize and its limits](docs/MATERIAL_RESIZE.md).

The material graph also includes **Blur**, **Grow / Shrink**, **Mask Adjust**, **Histogram Scan**, **Directional Warp**, **Image Transform**, **Procedural Texture**, **Height Occlusion**, **Normal Occlusion**, **Direction Select**, **Image Input** and **Normal Map**. Spatial operations generate cached images on resource workers; Image Transform maps the complete processed image using existing UV/triplanar coordinates. Procedural Texture offers twelve pattern families with their own controls and an authored 1K/2K/4K resolution. Normal Map decodes a processed linear RGB normal image for the material's Normal input. See [image nodes and controls](docs/MATERIAL_IMAGE_NODES.md).

Procedural **Variation** changes the arrangement continuously; cyclic families such as Clouds 1 return to the same arrangement at 0 and 1. Use Seed for a different distribution. Switching Pattern applies that family's defaults while retaining Resolution. Generation uses sequential cell-oriented batches with prepared stamps and bounded row scratch; it does not lower the authored resolution or add worker threads.

Static image outputs have 128 px inline previews and 256 px sidebar previews. They evaluate at authored source resolution before area reduction, preserving fine pattern coverage and the effect of nonlinear adjustments. Cached image Value outputs reuse the material's generated image; other supported branches use the same source-resolution CPU evaluation. Inline work is requested only for visible nodes, edits are debounced, and the last complete image stays visible while a replacement prepares. Warm frames reuse completed results.

Flat grayscale/Value previews display numerical data directly, so 0.5 appears as
0.5 gray rather than being brightened by a color display transform. RGB/RGBA
previews retain sRGB color presentation. This improves visibility of procedural
patterns without changing the values used by Height, Roughness or other material
connections.
