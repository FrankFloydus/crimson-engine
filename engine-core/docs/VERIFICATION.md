## HDR reflection filtering — 2026-10-13

Fixed disconnected bright reflection patches produced by sampling an unfiltered HDR panorama during environment convolution.

- **Reproduction:** an isolated copy of the project reproduced the reported patches with `malagas_ferry_road_2k.hdr`, the imported roughness map, metallic 1, roughness factor 0.507, environment intensity 1 and rotation 90°. The same defect appeared with constant roughness 0.2 and no map, and remained when direct lights were disabled. This identified environment preprocessing as the cause. The [before/after comparison](../captures/hdr-alias-20261013-180551/comparison.png) uses identical settings and camera for both captures.
- **Fix:** filtered importance sampling selects source levels by each sample's solid-angle footprint and the destination cubemap texel area. Spherical-area-weighted source reductions preserve radiance through odd sizes, the poles and panorama seam. The existing resolution, sample counts, BRDF and roughness floor are unchanged. Preprocessing version 3 rejects old caches, including the interim version-2 filter tested during this fix.
- **Build and focused checks:** `Build.cmd Release test` succeeded; both CTest targets passed in 0.16 seconds, covering 14 renderer-core and 9 environment-core groups. New checks cover source-pyramid energy and a tiny 40,000-radiance emitter across 1,536 directions at the production 256-sample count. The emitter test compares against independent double-precision source quadrature. An initial fourfold footprint overlap failed the existing reference envelope because it broadened the GGX tail excessively; twofold overlap passed without relaxing the test tolerance.
- **Native HDR checks:** three 24-frame Direct3D 11 captures with the final filter exited 0 and shut down cleanly: [roughness map](../captures/hdr-alias-20261013-180551/after-map.png), [constant roughness](../captures/hdr-alias-20261013-180551/after-constant.png), and [environment only](../captures/hdr-alias-20261013-180551/after-environment-only.png). Visual inspection confirms the disconnected square patches are gone. The first run regenerated the cache; subsequent runs loaded it successfully. Matching baseline images, settings and logs are in the same capture directory.
- **Regression smoke:** `scripts/Verify-Ibl.ps1 -Configuration Release` passed all ten native scenarios and its authored material/environment/layout hash checks. Neutral-normal versus no-map, zero-strength versus no-map, and reopen versus initial assignment comparisons each have zero changed viewport pixels. Detail normals changed 60,481 pixels and rough versus smooth metal changed 60,923. See the [overview](../captures/ibl-20261013-181740/overview.png) and [pixel results](../captures/ibl-20261013-181740/pixel-checks.json).

All reproduction edits and generated assignments were confined to disposable projects under `build/verification`. Later authored material edits were retained rather than restoring an earlier snapshot. Filtering remains a finite-sample approximation, and the existing 128×128 specular face resolution still limits fine mirror detail.

## Application icon and sizing — 2026-10-13

- **User replacement:** the user supplied a new 512×512 RGBA `crimson-engine.png`. It was converted to all nine ICO sizes, embedded by a successful incremental Release rebuild, and the desktop shortcut and Shell icon notifications were refreshed. The PNG remained byte-for-byte unchanged (SHA-256 `BD448B40923334DBBFA04B07D161464E60E5126BA43EC1C8067067CB4D410B00`). The rebuilt executable's icon was extracted to [`user-replacement-icon-extracted.png`](../captures/user-replacement-icon-extracted.png).
- **Window assignment:** the earlier taskbar screenshots contained identical old icon pixels despite the enlarged ICO. Shell extraction and native class handles matched the enlarged resource. Targeted Shell refresh alone did not visibly resolve the user's report. The app now explicitly assigns the SDL-owned class handles through `WM_SETICON`; runtime `WM_GETICON` checks confirmed non-null large/small handles matching their class counterparts. This proves window assignment, not the perceived taskbar size; the user subsequently replaced the artwork.
- **Assets:** the generated logo is a 512×512 RGBA PNG. The embedded ICO has nine 32-bit sizes: 16, 20, 24, 32, 40, 48, 64, 128 and 256 pixels. DIB headers, payload lengths, offsets and transparency masks passed validation; the 256-pixel entry uses PNG compression.
- **Sizing correction:** the exporter now measures visible artwork at alpha ≥8, retains a two-source-pixel antialias allowance, and centers it proportionally within each icon canvas. This ignores nearly invisible outlying pixels and removes the source PNG's excess margins from the ICO. The source PNG's SHA-256 hash was unchanged by export.
- **Small-icon result:** at alpha ≥128, the 24-pixel icon grows from an 18×18 visible footprint to 20×22, with 28.3% more alpha-covered area. The 16- and 32-pixel versions gain 25.8% and 26.7% respectively. The silhouette and internal gaps remain intact. See the [actual-size and enlarged comparison](../captures/icon-scale-candidates/comparison.png).
- **Integration:** `Build.cmd Release` successfully rebuilt the resource and linked the executable. Windows shell icon extraction confirmed the updated embedded emblem in [`app-icon-after-sizing.png`](../captures/app-icon-after-sizing.png). An isolated 30-frame native run exited 0 and saved [`icon-sizing-renderer.png`](../captures/icon-sizing-renderer.png). The desktop shortcut was refreshed and the Release renderer reopened. This resource/export-only change did not require rerunning renderer math suites.

- **Build and focused checks:** `Build.cmd Release test` succeeded. Both CTest targets passed in 0.12 seconds: 14 renderer-core groups and 7 environment-core groups. Initial integration errors in HLSL helper-input scope and a C++ resource-helper overload were corrected before this successful build.

Environment checks cover D3D cube orientation/edges, sRGB decoding, preservation of HDR radiance above 1, constant-environment irradiance/pi normalization, complete specular mips and roughness broadening.
- **BRDF/cache checks:** the LUT agrees with independent double-precision hemisphere quadrature of the correlated Smith direct BRDF. White-furnace, grazing-angle, roughness-floor and invalid-input cases remain finite. Cache tests cover source contents, both versions, settings, lossless round trips, truncated/corrupt rejection and regeneration.
- **Native acceptance:** `scripts/Verify-Ibl.ps1 -Configuration Release` completed ten 24-frame captures with exit 0 and clean shutdown. Scenarios cover normal/detail/reopen, dielectric, smooth/rough metal, neutral/zero-strength normals, near-surface extreme settings, zero exposure and all lighting disabled. Captures and per-run logs are in [`captures/ibl-20261013-175523`](../captures/ibl-20261013-175523).
- **Native imports/persistence:** the isolated smoke imported two PNG normal maps and a Radiance HDR panorama through `AssetLibrary`. - **Pixel comparisons:** the 935×470 viewport comparison region was exactly identical for neutral normal versus no map, zero strength versus no map, and reopened versus initially assigned detail normal (zero changed pixels in all three). Detail normals changed 60,487 viewport pixels; rough versus smooth metal changed 60,922. See [`pixel-checks.json`](../captures/ibl-20261013-175523/pixel-checks.json) and the [capture overview](../captures/ibl-20261013-175523/overview.png).
- **Existing project:** a separate scratch copy of the authored project rendered successfully with its saved factors, imported texture and direct lights plus the default studio. See [`existing-project.png`](../captures/ibl-20261013-175523/existing-project.png). The authored `assets/material.json` and `crimson_ui.ini` SHA-256 hashes were unchanged after all checks. Fixtures, assignments, caches and test layouts remain under `build/verification/ibl-20261013-175523`.

These checks exercise the native managed APIs and rendered results. The picker/drag-and-drop controls follow the existing editor path; native file-chooser clicks and a broad UI/scaling matrix were not automated. Preparation is synchronous at startup or source assignment, with cached reuse thereafter. Environment source changes are recognized on the next preparation/reopen, not by a live file watcher. Specular faces are currently 128×128; split-sum grazing-angle approximation, single-scattering rough-metal darkening, and absence of local reflections/occlusion/shadows remain documented limits.

Verified on 2026-10-13 with the Release MSVC build, SDL3, bgfx Direct3D 11 and ImGui 1.92.8 docking. No Debug build or scaling matrix was required.

- **Release compilation:** successful, including PBR, grid, tone-map, sRGB encode and editor sources.
- **Focused CPU checks:** all 13 groups passed in 0.03 seconds: five preserved mesh groups plus Quader camera math, pan/fly invariants, normalized movement, soft zoom, lazy pivot acceptance, mouse ownership, speed controls, keyboard gating and cancellation.
- **Native smoke:** exit 0. `captures/editor-slice.png` shows three docks, the depth-correct grid and sphere. Three generated PNGs were imported through the managed API and assigned to albedo, roughness and metalness.
- **Persistence:** exit 0 after reopening. `captures/editor-reopened.png` shows the same material and restored layout; `assets/material.json` retains all three relative paths and factors.
- **Grayscale display:** the capture exposed bimg's scalar-to-RGBA conversion displaying grayscale as red. The decoder now expands it into RGB luminance; the final reopened capture confirms correct thumbnails. Data maps still sample R.

Navigation is covered by focused synthetic SDL inputs. Actual OS pointer capture and the native file chooser are available for the interactive session; no broad UI automation pass was added.

Quader was read as the reference and was not modified. The grid retains perspective coverage, palette, hierarchy and fixed bounds, with Filament device-depth remapping adapted for bgfx forward depth.

The final sidebar correction replaces the selection/confirmation buttons with compact object fields immediately below Albedo, Roughness and Metalness. Each field opens a searchable texture picker and supports immediate assignment, clear and drag-and-drop. The incremental Release rebuild passed; `captures/editor-pickers.png` confirms the compact three-field layout. Existing camera checks were retained without another broad test run.
