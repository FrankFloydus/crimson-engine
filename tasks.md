# Tasks

- Re-evaluate whether `imgui.ini` should remain in the repo/worktree once Quader Native has an in-app user settings system. The current workflow intentionally keeps the generated ImGui docking/layout state for now; replace this with a proper user-settings storage path when that system exists.
- Replace the temporary CPU RGBA8 viewport readback path with GPU-native viewport texture presentation. The current transport lives behind `TemporaryRgba8ReadbackFrame`, `IViewportRenderer`, and `ViewportTextureStore` so the UI can already address textures by `ViewportId`, but Filament still renders each requested viewport to CPU memory before uploading it back to Vulkan for ImGui.
- Complete the editor/debug draw primitive system beyond the initial light-gizmo line path. The first pass adds project-owned debug draw value types and a Filament line renderer for directional/point light glyphs, but the reusable draw layer still needs point, triangle, box, sphere, cylinder, cone/arrowhead, billboard/ribbon, and persistent trace primitives before it can serve all planned gizmo/debug uses.
- Replace the temporary CPU-side gizmo picking path with a unified project-owned picking system. The first pass keeps selection tied to ECS owner IDs through debug draw pick payloads and CPU hit proxies, but it still uses app-side ray tests; future renderer/color-ID or acceleration-structure picking should consume the same pick payload contract and return domain/editor-tool IDs, never backend Filament entities.
- Split selected/hovered editor state into a small shared selection model before adding selected/hovered gizmo styling. Selection currently lives in `ScenePropertiesPanelController`, so the viewport can draw basic light gizmos but cannot consistently style selected or hovered gizmos without reaching into a UI controller.
- Refactor `FilamentSceneViewport::Resources` into narrower owners. The current class still owns scene sync, mesh/light caches, PBR materials/textures, render targets, camera state, readback, and now delegates debug draw to a helper. Follow up by extracting render target ownership, scene renderable caches, material/texture ownership, and debug draw resources into focused RAII classes.
- Add separate debug draw material/raster policies for depth-tested versus true overlay rendering. The initial debug draw material is unlit and suitable for editor visualization, but depth-tested and always-on-top overlays should become explicit material variants or render-layer policies instead of sharing one material path.
