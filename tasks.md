# Tasks

- Re-evaluate whether `imgui.ini` should remain in the repo/worktree once Quader Native has an in-app user settings system. The current workflow intentionally keeps the generated ImGui docking/layout state for now; replace this with a proper user-settings storage path when that system exists.
- Replace the temporary CPU RGBA8 viewport readback path with GPU-native viewport texture presentation. The current transport lives behind `TemporaryRgba8ReadbackFrame`, `IViewportRenderer`, and `ViewportTextureStore` so the UI can already address textures by `ViewportId`, but Filament still renders each requested viewport to CPU memory before uploading it back to Vulkan for ImGui.
- Complete the editor/debug draw primitive system beyond the current line/triangle path. The renderer now supports lines, filled transform gizmo cones/cubes/rings, and pick proxies, but the reusable draw layer still needs point, sphere, cylinder, billboard/ribbon, and persistent trace primitives before it can serve all planned debug uses.
- Replace the temporary CPU-side gizmo picking path with a unified project-owned picking system. The current transform and light gizmos keep selection tied to ECS owner IDs through debug draw pick payloads and CPU hit proxies, but future renderer/color-ID or acceleration-structure picking should consume the same pick payload contract and return domain/editor-tool IDs, never backend Filament entities.
- Add undo/command integration for viewport transform gizmo drags. The current gizmo drag path mutates `Scene` transforms directly in `TransformGizmoController`; replace this with a command/undo boundary once the editor command stack exists.
- Add shared hovered editor state for selected/hovered gizmo styling. Selection now lives in `EditorSelectionModel`, but hover state is still transient inside viewport picking and needs a shared model before selected/hovered styling can be consistent across panels and viewports.
- Refactor `FilamentSceneViewport::Resources` into narrower owners. The current class still owns scene sync, mesh/light caches, PBR materials/textures, render targets, camera state, readback, and now delegates debug draw to a helper. Follow up by extracting render target ownership, scene renderable caches, material/texture ownership, and debug draw resources into focused RAII classes.
